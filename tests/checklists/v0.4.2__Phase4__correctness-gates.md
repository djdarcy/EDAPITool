# Human Test Checklist: Phase 4 — Correctness Gates

**Target version:** v0.4.2
**Ships with commit:** TBD (pre-commit)
**Companion automated tests:** 395 total, of which 26 are new — `tests/test_ci_workflow.py` (7), `tests/test_marker_formula.py` (15), `tests/test_service.py` (4 of its 28)

## What this is

Three defects shipped in v0.4.2, and each one is the kind that hides. A CI gate that could not fail; a flag that destroyed spreadsheet formulas when used exactly as documented; a formula printed from a hand-typed copy of constants defined elsewhere. All three were invisible from inside the test suite, which is why the manual steps below matter more than usual.

Run by: the project maintainer. Several steps need a real spreadsheet, a running game session, or push access, and are marked **MANUAL — OWNER ONLY**. An external tester can still run Sections 1 and 3.

## Prerequisites

1. **Python 3.10, 3.11 or 3.12**, and an editable install with the test extras:

   **cmd.exe / PowerShell / POSIX** (same command):
   ```
   pip install -e .[all]
   ```

   The `[all]` extra matters. A bare `pip install -e .` omits `gspread`, and `tests/test_gsheet_guard.py` then skips itself wholesale — 15 tests covering the write allowlist vanish and the suite still reports green. That silent-skip is one of the things this release fixes in CI; do not reintroduce it locally.

2. **For Section 2 only:** the tracking spreadsheet, and Elite Dangerous running and **docked at a station with a commodity market**.

3. **Back up column L before Section 2.** It holds 197 live `VLOOKUP` formulas. A backup exists from the migration (`totals_column_L_*.json` in the project-private backups folder), but take a fresh one — File → Make a copy of the whole workbook is the simplest.

4. **Reset between sections:** nothing to reset for Sections 1 and 3; they are read-only. Section 2 writes to the sheet — see its own reset note.

## High-Value Verification (~5 minutes)

If you only have five minutes, run these five. If any fail, the release is broken.

### HV.1 — The suite passes, and the count is 395

- [ ] **Steps:** `python -m pytest -q`
- [ ] **Expected:** `395 passed`. No skips.
- [ ] **Why this matters:** If you see skips, your install is missing an extra and you are testing less than you think — the exact failure mode this release closes in CI.

### HV.2 — The lint step can now fail the build

- [ ] **Steps:** open `.github/workflows/main.yml` and search for `continue-on-error`.
- [ ] **Expected:** exactly one hit, and it is inside a **comment** explaining that the flag *used to* be there. No `continue-on-error:` appears as an actual YAML key.
- [ ] **Why this matters:** For seven releases the comment above that step said "Stop the build" while the line below it guaranteed the build would not stop.

### HV.3 — CI actually goes red **MANUAL — OWNER ONLY**

- [ ] **Steps:** see Section 1.3. Requires pushing a scratch branch.
- [ ] **Expected:** a red X on the run.
- [ ] **Why this matters:** This is acceptance criterion 5 of #14, and it is the only step that proves the gate works. **A gate that has never failed has not shown that it can.** Everything else in Section 1 is inference.

### HV.4 — `--no-markers` refreshes location without eating the formulas **MANUAL — OWNER ONLY**

- [ ] **Steps:** see Section 2.1.
- [ ] **Expected:** `C2` and `G2` update; column L still contains formulas; output says `Wrote 2 ranges`.
- [ ] **Why this matters:** Before this release the flag wrote *nothing at all* and then printed "DRY RUN" at you. It is the flag a formula-driven sheet is supposed to use.

### HV.5 — Google Sheets accepts the generated formula **MANUAL — OWNER ONLY**

- [ ] **Steps:** see Section 3.2. Paste the output of `--show-formula` into a scratch sheet.
- [ ] **Expected:** Sheets accepts it; no `#ERROR!`, no "Formula parse error".
- [ ] **Why this matters:** The formula is now assembled by a loop. No unit test can prove Google's parser accepts the result — only Google can.

## Section 1: CI now gates (#14)

~10 minutes, most of it waiting on CI.

### 1.1 The workflow declares a test job

- [ ] **Steps** (cross-shell, uses Python only):
  ```
  python -c "import yaml,io; w=yaml.safe_load(io.open('.github/workflows/main.yml',encoding='utf-8')); print(list(w['jobs'])); print(w['jobs']['build']['needs'])"
  ```
- [ ] **Expected:** `['lint', 'test', 'build']` and `['lint', 'test']`.
- [ ] **Check:** `build` depending on `test` means a package can no longer be built and twine-checked from a tree with failing tests.

### 1.2 The test job installs the extra that keeps the guard tests alive

- [ ] **Steps:**

  **cmd.exe**: `findstr /C:"pip install -e" .github\workflows\main.yml`

  **PowerShell**: `Select-String "pip install -e" .github\workflows\main.yml`

  **POSIX**: `grep "pip install -e" .github/workflows/main.yml`
- [ ] **Expected:** the `test` job's line reads `pip install -e .[all]`. (The `lint` job's bare `pip install -e .` is correct — it only needs to import.)
- [ ] **Why:** `.[all]` = `dev` + `gsheets`. Without `gsheets`, `tests/test_gsheet_guard.py` skips its 15 tests — the ones guarding against an irreversible overwrite of hand-entered settlement tabs.

### 1.3 A deliberately broken commit fails CI **MANUAL — OWNER ONLY**

This is the acceptance criterion. It needs push access and it needs a throwaway branch.

- [ ] **Steps:**
  1. `git checkout -b ci-gate-proof`
  2. Break something a test will catch — e.g. in `APITool/markers.py`, change `_PARTIAL_SCALE`'s first threshold from `0.375` to `0.9`.
  3. Confirm it is red locally first: `python -m pytest -q` → expect failures in `tests/test_marker_formula.py`.
  4. Commit and push the branch. **Note:** CI triggers on `main` and `dev` only, so either open a PR against `main` (which fires `pull_request`) or temporarily add your branch to the `on: push: branches:` list in the workflow *on that branch*.
  5. Watch the run: `gh run watch`, or `gh run list --branch ci-gate-proof`.
- [ ] **Expected:** the run **fails**, with the `test` job red.
- [ ] **Then check step-level results**, because a run summary can report success while the step you cared about was skipped:
  ```
  gh run view <run-id> --json jobs --jq ".jobs[] | {name, conclusion, steps: [.steps[] | {name, conclusion}]}"
  ```
- [ ] **Cleanup:** `git checkout main` then `git branch -D ci-gate-proof`, and delete the remote branch (`git push origin --delete ci-gate-proof`). Do not leave it behind — stale branches have already been a recurring cleanup item in this project.

### 1.4 CI's test count matches the local count

- [ ] **Steps:** on the same commit, compare `python -m pytest -q` locally against the CI job's log output.
- [ ] **Expected:** both say the same number (395 at the time of writing).
- [ ] **Why this matters:** A mismatch means something is skipping in one environment and not the other — which is the whole reason criterion 2 exists.
- [ ] **Note:** this is acceptance criterion 3 of #14 and can only be checked once CI has run at least once.

## Section 2: `--no-markers` writes location, not formulas **MANUAL — OWNER ONLY**

~10 minutes. Requires the live spreadsheet and being docked in-game.

> **Back up column L first.** See Prerequisites step 3.

### 2.1 Location refreshes, formulas survive

- [ ] **Steps:**
  1. Dock at a station with a commodity market, and open the Commodity Market screen once so the game writes `Market.json`.
  2. Note what `C2` and `G2` currently say.
  3. Run:
     ```
     edapitool market --sheet-id YOUR_SHEET_ID --update-sheet --no-markers
     ```
- [ ] **Expected output:** a line reading **`Wrote 2 ranges to 'Totals Tab'.`**
- [ ] **Expected — and this is the point:** the output must **NOT** contain the words `DRY RUN`. Before this release it did, on a run you asked to be real.
- [ ] **Check on the sheet:**
  - `C2` shows the current star system; `G2` shows the current station.
  - **Click any populated cell in column L and read the formula bar.** It must still show `=IF(...)` / `=LET(...)`, not a bare glyph.

    > Do **not** judge this by looking at the column. A wholesale value-write produces glyphs that look *identical* to the ones the formulas render. The formula bar is the only reliable check, and this is exactly how the defect stayed invisible.

### 2.2 The default still writes markers

The fix must not have made suppression the default.

- [ ] **Steps:** `edapitool market --sheet-id YOUR_SHEET_ID --update-sheet --dry-run`
- [ ] **Expected:** the dry-run listing includes a marker range (something like `Totals Tab!L5:L201`) alongside `C2` and `G2`.
- [ ] **Why `--dry-run`:** it shows the plan without writing, so you can confirm markers are still planned by default **without** overwriting your formula column. Only drop `--dry-run` here if you actually want the tool to repaint column L.

### 2.3 Reset after this section

- [ ] If column L was overwritten at any point, restore it from the backup taken in Prerequisites step 3.
- [ ] Re-verify by clicking a cell and confirming the formula bar shows a formula.
- [ ] **Note:** Sheets truncates trailing empty rows on read, which has previously caused a restore to land two rows short. After restoring, check the **last** populated row as well as the first.

## Section 3: The marker formula is generated

~5 minutes. No spreadsheet needed for 3.1.

### 3.1 `--show-formula` renders from the constants

- [ ] **Steps** (the encoding prefix matters — see the note below):

  **cmd.exe**:
  ```cmd
  set PYTHONIOENCODING=utf-8
  edapitool market --show-formula
  ```

  **PowerShell**:
  ```powershell
  $env:PYTHONIOENCODING = "utf-8"
  edapitool market --show-formula
  ```

  **POSIX**:
  ```bash
  PYTHONIOENCODING=utf-8 edapitool market --show-formula
  ```
- [ ] **Expected:** a formula containing `stock/need<0.375` and `stock/need<0.625`, the glyphs `● ◕ ◑ ◔ ○`, a legend, and a suggested-fills block listing `#38761d`, `#6aa84f`, `#93c47d`, `#b6d7a8`, `#e8f2e4`.
- [ ] **Expected:** step 3 of the printed text now says `--no-markers` **still refreshes the location cells**. Before v0.4.2 it implied the flag wrote nothing.
- [ ] **KNOWN ISSUE, NOT A REGRESSION:** without `PYTHONIOENCODING=utf-8`, the glyphs mangle on a Windows console (cp1252/437). This predates v0.4.2, affects local terminal output only, and does not affect what reaches Google Sheets. Note it; do not fail the checklist for it.

### 3.2 Google Sheets accepts the generated formula **MANUAL — OWNER ONLY**

- [ ] **Steps:**
  1. Create a scratch tab (or a throwaway spreadsheet).
  2. Copy the formula block from 3.1's output — the whole thing, from `=IF(` to the final `)`.
  3. Paste it into a cell and press Enter.
- [ ] **Expected:** Sheets accepts it. It will show a blank or an error about the missing `MarketData` tab **reference**, which is fine — what must **not** appear is `Formula parse error`, which would mean unbalanced parentheses or bad `LET` syntax.
- [ ] **Why this matters:** the formula is assembled by a loop over `_PARTIAL_SCALE`. The suite checks the parentheses balance, but only Google can confirm Google parses it.

### 3.3 The duplicate is really gone

- [ ] **Steps:**

  **cmd.exe**: `findstr /C:"0.375" APITool\cli.py`

  **PowerShell**: `Select-String "0.375" APITool\cli.py`

  **POSIX**: `grep -n "0.375" APITool/cli.py`
- [ ] **Expected:** no matches. The thresholds now live only in `APITool/markers.py`.
- [ ] **Why this matters:** the 197 formulas currently in the spreadsheet were pasted from the copy that used to live in `cli.py`. While both existed, changing the real constant would have left the sheet grading on old thresholds with every test still green.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| CI workflow shape: no failure-swallowing, test job runs pytest, extra installed, matrix, build gating, mutation decision recorded | `tests/test_ci_workflow.py` | 7 |
| Marker formula derives from `_PARTIAL_SCALE`; thresholds/glyphs/colours track the constants; paren balance at any scale length; empty scale refused; help text embeds the formula | `tests/test_marker_formula.py` | 15 |
| `--no-markers` plan shape, no marker-column value or format writes, no notes, CLI reports a real write not a dry run, markers on by default | `tests/test_service.py` (new) | 4 |
| Everything else (catalog, matcher, journal, market, sheets, ship, cargo contract, write guard) | rest of `tests/` | 369 |

Mutation audit: 22 of 22 mutants killed across `markers`, `cli` and `sheets`.

## What the automated tests DON'T cover

- **Whether CI can actually fail.** The suite reads the workflow file and asserts its shape. It cannot run GitHub Actions. Section 1.3 is the only proof.
- **Whether Google Sheets parses the generated formula.** Paren balance is checkable; Google's parser is not. Section 3.2.
- **Whether the live sheet's formulas survive a real `--no-markers` run.** Every automated test uses a fake worksheet. Section 2.1.
- **Console rendering of the marker glyphs** on cp1252/437 Windows terminals.
- **`service.py` mutation strength.** `service.py` is absent from `tests/one-offs/mutate.py`'s catalogue, so its tests have never been audited for detection power — and the runner accepts an unknown module name *silently*, so asking for it appears to work. Tracked in the standing plan (item 2.1).
- **Real CAPI behaviour, real journal timing, credential expiry.** Unchanged in this release, but still untested by automation.
