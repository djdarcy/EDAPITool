# Human Test Checklist: the settlement plugin -- a tab from a template

**Target version:** 0.10.0
**Ships with commit:** TBD, over `99a60d3` (the plugin's code)
**Companion automated tests:** 15 in `tests/test_settlement_plugin.py` (the matrix parser, the seed's shape, the template made once and hidden, the copy shown, the run-time write bound, dry run, the two refusals), against a fake workbook. Suite: 1,110.

## What this is

`edapitool plugins settlement new` makes a settlement tab for a site that does not exist yet: a copy of a hidden template, titled, with its block seeded from the `Base` matrix. The automated tests prove the mechanics against an in-memory workbook. This checklist covers the one thing they cannot: a real Google Sheet, with your formulas, your conditional formatting, and the Sheets API's own behaviour for duplicating and showing a tab. About 10 minutes. **Every write step runs on a copy of your workbook, never the original.**

## Prerequisites

1. EDAPITool installed from this tree; `edapitool --version` begins `0.10.0`.
2. **A copy of your workbook.** In Google Drive, right-click the workbook, **Make a copy**, and note the copy's id from its URL. Every step below names that copy. The original is never opened for writing.
3. A scratch config directory, so your real configuration is untouched. `ED_CONFIG_DIR` moves the config and the credential lookup together, so copy the two credential files in; copy them only, never open or print them.

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\edsettle
   copy "%USERPROFILE%\edapitool\gsheet_credentials.json" %TEMP%\edsettle\
   copy "%USERPROFILE%\edapitool\gsheet_token.json" %TEMP%\edsettle\
   set ED_CONFIG_DIR=%TEMP%\edsettle
   ```

   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\edsettle" | Out-Null
   Copy-Item "$env:USERPROFILE\edapitool\gsheet_credentials.json", "$env:USERPROFILE\edapitool\gsheet_token.json" "$env:TEMP\edsettle\"
   $env:ED_CONFIG_DIR = "$env:TEMP\edsettle"
   ```

   **POSIX**:
   ```bash
   mkdir -p /tmp/edsettle
   cp ~/edapitool/gsheet_credentials.json ~/edapitool/gsheet_token.json /tmp/edsettle/
   export ED_CONFIG_DIR=/tmp/edsettle
   ```

4. Write `config.json` there, with the copy's id:

   ```json
   {"targets": {"settlements": {"kind": "gsheet", "plugin": "settlement", "id": "YOUR_COPY_ID", "config": {}}}}
   ```

5. The game need not be running. No step opens the original workbook.

## High-Value Verification (~5 minutes)

### HV.1 -- The plugin is there and out of the pipeline

- [ ] **Steps:** `edapitool plugins`, then `edapitool plugins describe settlement`, then `edapitool plugins settlement`.
- [ ] **Expected:** `settlement` under `Loaded`, serving `settlements`; no `Pipeline market` section (nothing in this config offers a step); `describe` shows the five config keys and `process    (none)`; the plugin lists `new`.
- [ ] **Why this matters:** a command-only plugin must load and stay out of the refresh.

### HV.2 -- A dry run reads the matrix and creates nothing

- [ ] **Steps:** `edapitool plugins settlement new --type "industrial large" --name "Ind. Lrg. 3" --dry-run`
- [ ] **Expected:** `industrial large: N commodities from 'Base'`, the tab, the title cell `C3 = 'Settlement industrial large'`, the block `R1:AC60: N commodities, seeded as a planned site`, then `Dry run: nothing created.` Open the copy: no new tab, no `_settlement template`.
- [ ] **Why this matters:** a dry run that writes is the worst outcome, and the template creation is the step most likely to slip into one.

### HV.3 -- The real run: a template, a shown tab, a seeded block

- [ ] **Steps:** the same command without `--dry-run`.
- [ ] **Expected:** the command reports the template made from `Agri Lrg. (ex)`, `Created 'Ind. Lrg. 3'.`, the binding line `{"region": "Ind. Lrg. 3!R1:AC60", "site": "Ind. Lrg. 3"}`, and the Totals Tab reminder. In the copy: a hidden `_settlement template` (View > Hidden sheets), a visible `Ind. Lrg. 3` whose `C3` reads `Settlement industrial large`, whose `R1:Z…` block lists the industrial-large commodities with `Required` filled and `Provided` 0 and `State` `planned`, and -- the point -- **whose column B lists those commodities and column C their counts, computed by the tab's own formulas**. Compare B and C against your `Next` tab's hand copy of the same type: the same commodities, the same counts.
- [ ] **Why this matters:** this is the hand-copy the plugin replaces.

### HV.4 -- The refusals create nothing

- [ ] **Steps:** run `new` again with the same `--name`; then with `--type nope --name X`.
- [ ] **Expected:** `Error: a tab named 'Ind. Lrg. 3' already exists; nothing created.` and `Error: unknown settlement type 'nope'; the matrix offers: agricultural small, …` -- 18 types. The copy has no new tab either time.

### HV.5 -- The second tab reuses the template

- [ ] **Steps:** `new --type "agricultural medium" --name "Agri Med. 1"`.
- [ ] **Expected:** no "made the hidden template" line; one `_settlement template` still; a visible `Agri Med. 1` with the agricultural-medium commodities.

## Section 1: the template and the formulas

### 1.1 Conditional formatting and the trip counters travelled

- [ ] **Steps:** open `Ind. Lrg. 3` beside `Agri Lrg. (ex)`.
- [ ] **Expected:** the same column shading rules; row 1's trip counters show numbers computed from the seed (total round trips from the required total); row 2's system and site show what you passed with `--site`/`--system`, or blanks and the tab name.

### 1.2 `--refresh-template`

- [ ] **Steps:** in the copy, type a note into `Agri Lrg. (ex)!N1`; run `new --type "extraction small" --name "Extr. Sm. 1" --refresh-template`.
- [ ] **Expected:** `removed the old template`, `made the hidden template`, and the new tab carries the note in `N1` (the template was remade from the source). Delete the note afterwards.

## Section 2: the live site overwrites the seed (needs the game; optional)

### 2.1 The binding takes over

- [ ] **Steps:** add the printed binding under your regions target in the scratch config (naming the copy's id for that target too); dock at a construction site of the matching type; `edapitool serve --once`.
- [ ] **Expected:** the block now carries the live site's name, market id, timestamp and `active` state; column B and C unchanged where the required counts match; the `Provided` column now real. No cell outside `R1:AC60` and `C3` changed.

## What the automated tests DO cover

| Area | Count |
|---|---|
| The matrix: header row found by `PLANETARY`, 18 types, the leading space, the zero-width space, commas, blanks, an unknown type's refusal | 7 |
| The seed equals `construction_region_rows` of the synthetic site, state `planned` | 1 |
| The plugin loads, offers `new`, is absent from the pipeline; `describe` output; `check_config` | 2 |
| Dry run creates nothing; the real run makes the template once (hidden, cleared) and a shown copy; the guard allows the block and title and refuses the rest; the second run reuses the template; a taken name and an unknown type refuse before anything is made | 5 |

## What the automated tests DON'T cover

- The Sheets API's `duplicateSheet` carrying formulas, formats and protected ranges.
- The `updateSheetProperties` request actually showing the copy.
- Your formulas reading the seed: that column B fills, that the counters compute, that the glyph marker column reads `MarketData` for the new rows.
- OAuth: the first run may print Google's consent URL if the token needs refreshing.
- The wording of the printed binding line as a person copies it into a config file.

## Known limits, by design

- The binding is printed, not written: the plugin never edits your configuration.
- The Totals Tab's source list is yours to extend; the command reminds you.
- One template per workbook; `--refresh-template` remakes it from `source_tab`.

## Reporting issues found

Note the step, the exact command and output, and the state of the copy's tab list; file an issue referencing this checklist and #35.

## Cleanup

1. Delete the copy of the workbook, or keep it as a sandbox.
2. Unset `ED_CONFIG_DIR` and remove the scratch directory:

   **cmd.exe**: `set ED_CONFIG_DIR=` then `rmdir /s /q %TEMP%\edsettle`
   **PowerShell**: `Remove-Item Env:\ED_CONFIG_DIR; Remove-Item -Recurse "$env:TEMP\edsettle"`
   **POSIX**: `unset ED_CONFIG_DIR; rm -rf /tmp/edsettle`
