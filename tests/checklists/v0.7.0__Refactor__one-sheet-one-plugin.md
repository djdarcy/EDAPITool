# Human Test Checklist: one sheet, one plugin

**Target version:** v0.7.0
**Ships with commit:** "Make one spreadsheet's code a plugin, and the rest of the tool ignorant of it"
**Companion automated tests:** 590 passing, plus two probes under `tests/one-offs/thinking/plugin-isolation/`

## What this is

Everything describing one particular Google Sheet now lives in a plugin directory of its own — `APITool/plugins/settlement/` — and no layer above it names anything a person typed into their spreadsheet.

**Nothing the tool does has changed.** Same tabs, same columns, same output. What changed is where the knowledge lives, and one consequence escapes: **two import paths are gone.** That is the entire reason this is a minor bump rather than a patch, and it is what step 1 checks.

**The live read and the live write were already verified** against the real spreadsheet before this shipped — 20 requirements read from the real Totals Tab, and `market --update-sheet` reporting `Wrote 3 ranges`. Do not redo those; this checklist covers only what was left.

**~6 minutes. The game does not need to be running for any step.** `market` reads `Market.json` from disk and that file persists from your last session, so the comparison works with Elite Dangerous closed. That is worth saying because the opposite is the natural assumption.

**Release state:** 0.6.4 through 0.7.0 are all committed and deliberately unreleased — no tags, no GitHub releases. In this project a tag accompanies a release; a version number is a build identifier.

---

## ⚠ Read before running anything

**Do not run `edapitool market --update-sheet` against a workbook whose marker column holds formulas.** It clears that column unconditionally.

Measured on 2026-09-16: the command wiped all 20 formulas from `Totals Tab!L5:L24`, which had to be restored from a snapshot. The clearing is correct behaviour *from when the tool painted glyphs there*; it is wrong now that the column computes itself.

This is **pre-existing and not a regression** from this version, and it is filed separately. Until it is fixed, use `--dry-run`, which step 4 does.

The asymmetry that makes it a defect rather than a preference: `serve --write-location` is **off by default**, and its own help text says those cells are better as formulas. The marker range never got the same gate.

---

## Prerequisites

1. `edapitool` installed from this working tree, with the `gsheets` extra.
2. Google credentials already configured — the same ones `serve` uses.
3. No setup, no env vars, no throwaway config. Every step below is read-only or prints to your terminal; nothing writes to your spreadsheet or your dotfiles.

**All commands are identical in cmd.exe, PowerShell and bash** — they are `edapitool` and `python` invocations with no shell-specific syntax, no redirection and no environment variables, except step 3 where the per-shell forms are given explicitly.

## High-Value Verification

### HV.1 — The import paths that moved ← **the reason for the bump**

Validates: the one user-visible consequence of this release.

- [ ] **Steps** (cross-shell safe):

  ```
  python -c "from APITool.sheets import SheetLayout"
  python -c "import APITool.workbook"
  python -c "from APITool.plugins.settlement.layout import SheetLayout; print(SheetLayout().totals_tab)"
  ```

- [ ] **Expected:**
  - The first two **fail** — `ImportError` and `ModuleNotFoundError`. That is correct, not a bug.
  - The third **succeeds** and prints `Totals Tab`.
- [ ] **Why this matters:** if you have any script of your own importing either old path, it breaks on upgrade and this is the line to change. Nothing else about the tool moved.

### HV.2 — The tool still runs with the plugin removed

Validates: the property this whole release exists to create.

- [ ] **Steps:**
  ```
  python tests/one-offs/thinking/plugin-isolation/poc_pull_the_plug.py
  ```
- [ ] **Expected:** a table where every row reads `as designed`, ending with `RESULT: the plug pulls cleanly. Requirement 3 of #18 is MET.`
  No row says `*** COLLATERAL ***`.
- [ ] **Why this matters:** it blocks the plugin from importing and then checks what breaks. Journal reading, market, ship, CSV/JSON export, the daemon and the CLI must all survive; only the plugin's own features may die.

### HV.2b — The tool still *runs* with the plugin removed ← added in v0.7.1

Validates: the half of HV.2 that HV.2 could not see.

- [ ] **Steps:**
  ```
  python -m pytest tests/test_destination_seam.py -q -k still_RUN
  ```
- [ ] **Expected:** 2 passed. With the plugin blocked, `edapitool --version` and `edapitool market --help` both run.
- [ ] **Why this matters:** HV.2 asks whether modules *load*. v0.7.0 shipped with every one of those checks green and `edapitool --version` unable to run without the plugin present, because the plugin was imported at the top of `main()` to build the argument parser's defaults. Importable is not runnable, and only the second is what you experience. v0.7.1 fixes it and this step is the guard.

### HV.3 — No layer above the plugin knows your spreadsheet

Validates: the measurable goal of the release.

- [ ] **Steps:**
  ```
  python tests/one-offs/thinking/plugin-isolation/probe_no_sheet_knowledge.py
  ```
- [ ] **Expected:** `0 leaks   (0 literal, 0 layout default)`. It reported **32** before this work.
- [ ] **Why this matters:** it counts every mention of a tab, column or header *a person maintains* anywhere outside `APITool/plugins/` — in code, in argparse help text, in comments, and in dataclass defaults. The exit code is the count, so it can gate a script.

### HV.4 — The market comparison still reads your sheet

Validates: the read path and the write plan, without writing.

- [ ] **Steps:**
  ```
  edapitool market --update-sheet --dry-run
  ```
- [ ] **Expected:** your last station and system, the comparison, and a `DRY RUN - would write:` block naming `Totals Tab!C2`, `Totals Tab!G2` and the marker range. **Nothing is written.**
- [ ] **Check:** the outstanding quantities shown match what the Totals Tab's outstanding-quantity column actually says. Open the sheet and spot-check a row or two.
- [ ] **Why this matters:** every automated test of this path uses a mock worksheet. This is a real read, through the layout that moved.

### HV.5 — `serve` starts

Validates: `build_daemon` now **requires** a layout rather than defaulting to one, and `serve` is the only surface that change could break.

- [ ] **First: check whether a daemon is already running.** If one is, leave it alone and skip this step — do not start a second against the same spreadsheet.
- [ ] **Steps:**
  ```
  edapitool serve
  ```
  Let it reach its first poll, then stop it with Ctrl-C.
- [ ] **Expected:** it starts, prints which targets it is keeping current, and polls. No traceback, and specifically no `ValueError` about a missing layout.
- [ ] **Why this matters:** `serve` has not been exercised since the refactor. A required argument with no caller supplying it fails at startup, which no unit test in the suite would catch.

## Section 1: Known rough edge

### 1.1 `--show-formula` on a stock Windows console

- [ ] **Steps** (pick your shell):

  **cmd.exe**
  ```cmd
  edapitool market --show-formula
  set PYTHONIOENCODING=utf-8
  edapitool market --show-formula
  ```

  **PowerShell**
  ```powershell
  edapitool market --show-formula
  $env:PYTHONIOENCODING = "utf-8"
  edapitool market --show-formula
  ```

  **POSIX**
  ```bash
  edapitool market --show-formula
  PYTHONIOENCODING=utf-8 edapitool market --show-formula
  ```

- [ ] **Expected:** the first invocation **fails** on a default Windows console with `UnicodeEncodeError: 'charmap' codec can't encode character '○'`. The second prints the full formula, including the thresholds `0.375` and `0.625` and the glyphs `◔ ◑ ◕`.
- [ ] **This is pre-existing, not a regression.** It reproduces identically on the previous commit. The marker glyphs are not representable in codepage 1252, which is what a stock `cmd.exe` and PowerShell 5.1 use. Recorded here so it is on the books rather than rediscovered.

## What the automated tests DO cover

| Area | Where | Count |
|---|---|---|
| Removing the plugin breaks only plugin features | `tests/test_destination_seam.py` | 24 |
| Modules above a plugin reach it only at function scope | `tests/test_market_data.py` | 3 |
| Everything else | the rest of `tests/` | 563 |

Both layering checks were verified to fail when they should: injecting a module-scope plugin import into the service, and a plugin import into the generic toolkit, turned each red with a message naming the offender.

## What the automated tests DON'T cover

- **Whether your spreadsheet looks right.** Column alignment, row offsets, glyph rendering — a marker one row off passes every assertion.
- **A real Google Sheets worksheet.** Every automated test of the reader and writer uses a mock, so quota behaviour, API errors and partial writes are invisible to them.
- **`serve` running for real** — HV.5 is the only coverage of daemon startup.
- **Console encoding**, which is section 1.1 and cannot be reproduced under pytest's captured output.

## Reset and cleanup

Nothing to reset. No step writes to your spreadsheet, creates a file, or changes configuration. If you set `PYTHONIOENCODING` in section 1.1, it lasts only for that shell session — close the window, or unset it:

| cmd.exe | PowerShell | POSIX |
|---|---|---|
| `set PYTHONIOENCODING=` | `Remove-Item Env:\PYTHONIOENCODING` | `unset PYTHONIOENCODING` |
