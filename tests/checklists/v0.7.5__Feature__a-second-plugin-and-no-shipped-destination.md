# Human Test Checklist: a second plugin, and no shipped destination

**Target version:** v0.7.5
**Ships with commit:** `v0.7.5 feat(plugins)!: the core ships no destination (#18, #26, #27)`
**Companion automated tests:** 775 passing (756 at v0.7.4), notably `tests/test_jsonl_plugin.py` (23, new), `tests/test_plugins_verb.py` (8, new), `tests/test_plugin_loader.py` (86), `tests/test_config_regions.py` (21), `tests/test_plugin_docs.py` (7, new)

## What this is

This release contains **one breaking change and one new plugin**, and the automated tests cannot tell you whether either of them *feels* right to use. They can tell you a refusal fires; they cannot tell you the refusal explains what to do next. They can tell you a listing prints; they cannot tell you it reads well in a terminal at 80 columns.

Run this before trusting v0.7.5 against a workbook you care about. The highest-value part is Section 1 — the migration break — because it affects an existing install on first run and the only person who can judge whether the message is good enough is someone reading it cold.

Everything here runs against a throwaway configuration directory. Nothing in this checklist touches your real settings, your real tokens, or your real spreadsheet.

## Prerequisites

1. **Python 3.12+**, this repo checked out, dependencies installed.
2. **A journal to read.** Most `market` steps read Elite Dangerous journal files. If you have none, pass `--journal-dir` at an empty temporary directory — the command still runs and reports "Not docked", which is enough for every step here except where a station is explicitly expected.
3. **The entry point.** Either the installed `edapitool` command or `python -m APITool.cli`. This checklist writes `edapitool`; substitute freely.

### State isolation — do this first, it is the whole safety story

`ED_CONFIG_DIR` redirects **everything** the tool owns — settings, tokens, your own plugins, Google credentials — to a directory you name. Set it once at the start of your session and your real `~/edapitool/` is untouched for the whole run.

**cmd.exe**:
```cmd
set ED_CONFIG_DIR=%TEMP%\edapitool-checklist
mkdir "%ED_CONFIG_DIR%"
set ED_PLUGIN_DIR=%ED_CONFIG_DIR%\plugins
echo %ED_CONFIG_DIR%
```

**PowerShell**:
```powershell
$env:ED_CONFIG_DIR = "$env:TEMP\edapitool-checklist"
New-Item -ItemType Directory -Force $env:ED_CONFIG_DIR | Out-Null
$env:ED_PLUGIN_DIR = "$env:ED_CONFIG_DIR\plugins"
Write-Host $env:ED_CONFIG_DIR
```

**POSIX**:
```bash
export ED_CONFIG_DIR=/tmp/edapitool-checklist
mkdir -p "$ED_CONFIG_DIR"
export ED_PLUGIN_DIR="$ED_CONFIG_DIR/plugins"
echo "$ED_CONFIG_DIR"
```

- [ ] **Confirm the redirect took** before going further — run `edapitool plugins` and check it does **not** report a target you recognise from your own settings. If it names your real workbook, the variable is not set in this shell and you must stop and fix that.

### Resetting between sections

Delete the settings file and write the next one. The directory can stay.

**cmd.exe**: `del "%ED_CONFIG_DIR%\config.json"`
**PowerShell**: `Remove-Item "$env:ED_CONFIG_DIR\config.json" -ErrorAction SilentlyContinue`
**POSIX**: `rm -f "$ED_CONFIG_DIR/config.json"`

### Safety rules for this run

- **Never run `market --update-sheet` against your real workbook.** Issue #25 is still open: a real write clears the marker column, which now holds formulas. Use `--dry-run`. Every `--update-sheet` step in this checklist points at a *file* destination in the temp directory, never a spreadsheet.
- Every path written here is under `ED_CONFIG_DIR` or the system temp directory.
- This checklist builds no git fixture, so no scratch-git rules apply. If you add a step that does, give every git command `-C <scratch path>` and every commit `-c user.email=... -c user.name=... -c commit.gpgsign=false -c tag.gpgsign=false`, so it cannot land in a real repository and cannot trigger an interactive signing prompt.

## High-Value Verification (~6 minutes)

If you only have a few minutes, run these six. They are the "did the work actually ship" tests, and each is covered again in detail below.

### HV.1 — An un-migrated settings file gets a working tool and no destination

Validates: the breaking change, from the perspective of someone upgrading.

- [ ] **Steps:**
  1. Write a settings file in the shape every install before v0.7.5 had:

     **cmd.exe / PowerShell / POSIX** (cross-shell, uses Python):
     ```
     python -c "import json,os,pathlib; p=pathlib.Path(os.environ['ED_CONFIG_DIR'])/'config.json'; p.write_text(json.dumps({'client_id':'not-a-real-id','sheet_id':'NOT-A-REAL-SHEET'}, indent=2))"
     ```
  2. `edapitool plugins`
- [ ] **Expected:** no plugin loaded. A section headed `Available but not loaded`, listing `settlement` and `jsonl`, each with `never configured -- add a "targets" entry naming it` and a pointer to `edapitool plugins describe <name>`.
- [ ] **Why this matters:** this is what an existing user sees on first run after upgrading. If the message does not tell them what to do, the release is a support burden regardless of whether the code is correct.

### HV.2 — `market` still works with no destination configured

Validates: the core publishes open formats with nothing configured (#18 criterion 6).

- [ ] **Steps:** with HV.1's settings file still in place, run `edapitool market --no-sheet`
- [ ] **Expected:** exit code 0 (or 2 if you are not docked). Commander, System and Station print. A line beginning `No comparison:`. **No traceback, and not exit 1.**
- [ ] **Why this matters:** before v0.7.5 this exited 1 with "no destination plugin is loaded" — so an unconfigured install could not read its own journal. That made "with none configured it publishes open formats only" a sentence the code contradicted.

### HV.3 — The refusals name the flag that needed a plugin

Validates: the two things a destination is actually for still refuse, usefully.

- [ ] **Steps:** `edapitool market --update-sheet --dry-run`
- [ ] **Expected:** exit code 1, and output shaped like:
  ```
  Error: --update-sheet needs a destination plugin, and none is configured.
    available settlement (shipped) -- not enabled
    available jsonl (shipped) -- not enabled
  ```
- [ ] **Why this matters:** "no destination plugin is loaded" alone does not tell a person *which thing they asked for* needed one. Read this as a stranger and judge whether you would know your next move.

### HV.4 — A file destination publishes, end to end

Validates: the second kind — a plugin whose destination is not a spreadsheet at all.

- [ ] **Steps:**
  1. Point a target at the `jsonl` plugin:
     ```
     python -c "import json,os,pathlib; d=pathlib.Path(os.environ['ED_CONFIG_DIR']); (d/'config.json').write_text(json.dumps({'targets':{'observations':{'kind':'jsonl','plugin':'jsonl','path':str(d/'obs.jsonl'),'config':{'only':['checked_at','system','station']}}}}, indent=2))"
     ```
  2. `edapitool plugins`
  3. `edapitool market --no-sheet --update-sheet`
  4. View the file — **cmd.exe**: `type "%ED_CONFIG_DIR%\obs.jsonl"` / **PowerShell**: `Get-Content "$env:ED_CONFIG_DIR\obs.jsonl"` / **POSIX**: `cat "$ED_CONFIG_DIR/obs.jsonl"`
- [ ] **Expected:** `plugins` reports `jsonl ... serves 'observations'` and `settlement` as available. The market command runs. The file holds **exactly one line**, a JSON object with only the three fields named in `only`.
- [ ] **Why this matters:** this is the proof the plugin contract is not secretly shaped like a spreadsheet. If a file destination had needed the contract widened, the whole migration would have been cosmetic.

### HV.5 — The settlement workbook's behaviour is unchanged

Validates: the thing that must not have regressed.

- [ ] **Steps:**
  1. Configure a settlement target (a fake sheet id is fine — nothing here opens it):
     ```
     python -c "import json,os,pathlib; d=pathlib.Path(os.environ['ED_CONFIG_DIR']); (d/'config.json').write_text(json.dumps({'targets':{'book':{'kind':'gsheet','plugin':'settlement','id':'NOT-A-REAL-SHEET','config':{'construction_regions':[{'region':'Tab Name!R1:AC60','site':'Site Name'}]}}}}, indent=2))"
     ```
  2. `edapitool plugins`
  3. `edapitool market --no-sheet`
- [ ] **Expected:** `settlement ... serves 'book'`, no `CONFIG` complaint line, and the market command behaves exactly as it did in v0.7.4.
- [ ] **Why this matters:** every other test here is about new behaviour. This is the one asking whether the old behaviour survived.

### HV.6 — `market --help` still shows real defaults

Validates: the flag-default change did not make the help text useless.

- [ ] **Steps:** `edapitool market --help`
- [ ] **Expected:** `--totals-tab`, `--need-header` and `--empty-marker` still describe meaningful defaults in their help text, even though the flags themselves now default to "not given".
- [ ] **Why this matters:** the defaults moved from the parser into the plugin. If the help text moved with them, `--help` silently became less useful and no automated test would notice.

## Section 1: the migration break (~5 min)

This is the section that matters most. v0.7.4's CHANGELOG promised *"Nothing changes for an existing install… the tool reads it as one target named `default`."* v0.7.5 reverses that promise deliberately. Judge whether the reversal is survivable for someone who did not read the CHANGELOG.

### 1.1 A bare `sheet_id` enables nothing

- [ ] **Steps:** reset, then write `{"client_id": "x", "sheet_id": "NOT-A-REAL-SHEET"}` (HV.1 step 1), then `edapitool plugins`
- [ ] **Expected:**
  - Both shipped plugins listed under `Available but not loaded`
  - Each carries `never configured -- add a "targets" entry naming it`
  - **The output does not begin with a blank line** (it did before this release)
- [ ] **Check:** read the whole listing as a stranger. Does it tell you what a `targets` entry looks like, or only that you need one? (`plugins describe <name>` is the intended next step — judge whether the pointer to it is findable.)

### 1.2 `sheet_id` still names a spreadsheet for the plugin-free commands

The key was **not** removed. It no longer selects a *plugin*, but it still says *where*.

- [ ] **Steps:** with the bare-`sheet_id` file in place, run `edapitool ship --export ship-tab --dry-run` (or `carrier --export google` if you have CAPI credentials in this throwaway directory, which you probably do not — in that case read the error and confirm it is about credentials, not about a missing sheet id).
- [ ] **Expected:** the command does **not** complain that there is no spreadsheet id. It finds `NOT-A-REAL-SHEET`.
- [ ] **Why:** a person who has never installed a plugin still needs a way to name a workbook. If this step reports "no spreadsheet id", the key was over-removed.

### 1.3 A target's `id` beats a bare `sheet_id`

- [ ] **Steps:** write a file carrying **both** a top-level `sheet_id` and a `gsheet` target with a different `id`:
  ```
  python -c "import json,os,pathlib; d=pathlib.Path(os.environ['ED_CONFIG_DIR']); (d/'config.json').write_text(json.dumps({'sheet_id':'THE-OLD-ONE','targets':{'book':{'kind':'gsheet','plugin':'settlement','id':'THE-NEW-ONE'}}}, indent=2))"
  ```
  then `edapitool market --no-sheet --json` and look at the output.
- [ ] **Expected:** the run uses `THE-NEW-ONE`. The target's `id` is the more specific statement of the same fact and wins.
- [ ] **Check:** nothing anywhere reports `THE-OLD-ONE`.

### 1.4 A malformed `targets` map is refused by name, not by traceback

- [ ] **Steps:** write `{"targets": "not-an-object"}`, then `edapitool plugins`, then `edapitool market --no-sheet`
- [ ] **Expected:** both report an error naming `targets` and what was wrong with it. **No traceback in either.**

### 1.5 A target naming a plugin that does not exist

- [ ] **Steps:** write a target with `"plugin": "no-such-plugin"`, then `edapitool plugins`
- [ ] **Expected:** a `NOT loaded` section naming it, with `not found by the scan` as the reason and a line saying the tool is unaffected.
- [ ] **Check:** the other sections still print. One bad target must not take down the listing.

## Section 2: `market` with no destination (~4 min)

### 2.1 The missing comparison is reported as missing

- [ ] **Steps:** reset to no settings file at all, then `edapitool market --no-sheet --json`
- [ ] **Expected:** valid JSON on stdout with `"comparison_skipped": "no destination plugin is configured"`.
- [ ] **Why:** an empty comparison table rendered as an answer reads as "you need nothing here", when the truth is that nobody was asked. Confirm the JSON distinguishes the two.

### 2.2 CSV and JSON export with nothing configured

- [ ] **Steps:** `edapitool market --no-sheet --export csv,json --output "%TEMP%\edapitool-export"` (PowerShell: `$env:TEMP\edapitool-export`; POSIX: `/tmp/edapitool-export`)
- [ ] **Expected:** if you are docked with a current market, files are written and named in the output. If you are not docked, it says it is skipping csv/json because there is no current market — **not** that there is no plugin.
- [ ] **Check:** exit code is 0 or 2, never 1.

### 2.3 `--show-formula` refuses by name

- [ ] **Steps:** `edapitool market --show-formula`
- [ ] **Expected:** exit 1, and the message names `--show-formula` as the flag that needed a destination plugin.

### 2.4 A plugin that has no formula to show

- [ ] **Steps:** configure the `jsonl` target (HV.4 step 1), then `edapitool market --show-formula`
- [ ] **Expected:** `The 'jsonl' plugin has no formula help.` — a plugin without one says so rather than showing another plugin's.

## Section 3: the `jsonl` plugin (~6 min)

### 3.1 A dry run writes nothing

- [ ] **Steps:** with the `jsonl` target configured and `obs.jsonl` deleted, run `edapitool market --no-sheet --update-sheet --dry-run`
- [ ] **Expected:** the output says it *would* append a record. The file **does not exist** afterwards.
- [ ] **Check:** `if exist` / `Test-Path` / `ls` the path and confirm absence. A dry run that creates the file is not dry.

### 3.2 One record per refresh, appended

- [ ] **Steps:** run `edapitool market --no-sheet --update-sheet` three times, then count the lines.

  **PowerShell**: `(Get-Content "$env:ED_CONFIG_DIR\obs.jsonl" | Measure-Object -Line).Lines`
  **POSIX**: `wc -l < "$ED_CONFIG_DIR/obs.jsonl"`
  **cmd.exe**: `python -c "import os,pathlib;print(sum(1 for _ in open(pathlib.Path(os.environ['ED_CONFIG_DIR'])/'obs.jsonl')))"`
- [ ] **Expected:** exactly three lines. Each parses as JSON on its own.

### 3.3 `only` narrows the record, and a bad `only` is the plugin's complaint

- [ ] **Steps:**
  1. Set the target's `config` to `{"only": ["system", "cargo_capacity"]}` — the second field is one this plugin does not publish.
  2. `edapitool plugins`
- [ ] **Expected:** the plugin loads and the listing carries a `CONFIG observations: ...` line, in the plugin's own words, naming `cargo_capacity` and saying which fields it does know.
- [ ] **Check:** the complaint names **the target**, not just the plugin. With two targets configured, you must be able to tell which one is wrong.

### 3.4 A record is refused when the path is not the declared one

This is enforcement, and it is the reason kinds exist at all. There is no supported way to trigger it from the command line — core builds the guard from the plugin's own declaration, so the two always agree — which is itself the thing to confirm.

- [ ] **Steps:** run `edapitool plugins describe jsonl` **twice** — once with no settings file, once with the `jsonl` target from HV.4 configured.
- [ ] **Expected:**
  - with no target: `writes     nothing as shipped`
  - with the target: a `writes` section naming `__file__: <the path you configured>`
- [ ] **Why:** a plugin's declared write bound comes from its target, not from inside the plugin — so `describe` has to answer about the plugin *as configured*. If it shows a path you did not configure, something is hardcoded that should not be; if it says "nothing" while a target is set, it is describing a plugin that is about to write as though it were inert.
- [ ] **Check:** do the same for `settlement` with a `gsheet` target and confirm its four declared ranges are unchanged (`Totals Tab: C2`, `G2`, `L3:L`, `FreighterData: A1:Z1000`). A sheet plugin's bounds are its own and must not shift.

> Written before the code did this. The first draft of this checklist asserted the configured behaviour, `describe` did not have it, and the step failed on first run — a file destination reported "writes nothing as shipped" while configured to append to a file. Fixed before release.

### 3.5 Known defect — the empty timestamp

- [ ] **Steps:** read a record written while **not docked** (no current market).
- [ ] **Expected — and this is a known defect, not a new bug:** `"checked_at": ""`. The field is honest (there was no market reading) but it makes records unorderable.
- [ ] **Check:** confirm it is empty rather than wrong or missing, and note it if you see anything else. Tracked as a follow-up; do not file a duplicate.

## Section 4: the `plugins` verb (~4 min)

### 4.1 Listing imports nothing

- [ ] **Steps:** configure one plugin, then `edapitool plugins`
- [ ] **Expected:** the listing names every plugin found, but only the configured one is under `Loaded`. Unconfigured plugins are listed without being imported.
- [ ] **Why:** showing an unloaded plugin's capabilities would mean running code you declined. The split between `list` and `describe` exists for consent, not for tidiness.

### 4.2 `describe` imports the one you name

- [ ] **Steps:** `edapitool plugins describe settlement` and `edapitool plugins describe jsonl`
- [ ] **Expected:** for each — location, origin, kind, what it writes, what it supplies, what it subscribes to, and a starter `config` block.
- [ ] **Check:** the two describe pages share **no vocabulary**. `settlement` supplies `requirements` and subscribes `markers`; `jsonl` supplies `previous` and subscribes `record`. Overlap would mean the contract had quietly acquired a spreadsheet's nouns.

### 4.3 A plugin that does not import

- [ ] **Steps:**
  1. Create a broken plugin in your throwaway user plugin directory:
     ```
     python -c "import os,pathlib; d=pathlib.Path(os.environ['ED_PLUGIN_DIR'])/'plug_broken'; d.mkdir(parents=True,exist_ok=True); (d/'__init__.py').write_text('raise RuntimeError(\"planted: this plugin does not import\")\n')"
     ```
  2. Configure a target naming `plug_broken`, then `edapitool plugins`
- [ ] **Expected:** a `NOT loaded` section with the plugin's name, the reason (`RuntimeError: planted: ...`), and `the tool is unaffected; other plugins loaded normally`.
- [ ] **Check:** any other configured plugin still appears under `Loaded`.

### 4.4 A user plugin shadowing a shipped one

- [ ] **Steps:** create a directory named `jsonl` in your user plugin directory with a minimal `__init__.py`, configure a target naming `jsonl`, then `edapitool plugins`
- [ ] **Expected:** the user plugin is used, origin `user`, and a line saying it **shadows the shipped plugin at `<path>`**.
- [ ] **Why:** the surprising state is the one that must be named. Silent shadowing is how someone debugs the wrong file for an hour.

### 4.5 Readability, at 80 columns

- [ ] **Steps:** narrow your terminal to 80 columns and re-run `edapitool plugins` with two plugins loaded and one broken.
- [ ] **Expected:** columns stay aligned, long paths wrap tolerably, nothing is truncated into nonsense.
- [ ] **Check:** this is pure judgement and no test covers it. Is it pleasant to read, or merely correct?

### 5.1 `ED_CONFIG_DIR` redirects everything

- [ ] **Steps:** with `ED_CONFIG_DIR` set, run any command that reads settings and confirm your real `~/edapitool/` is not consulted.
- [ ] **Check:** compare modification times on your real `~/edapitool/config.json` before and after the whole checklist run. **It must not have changed.** This is the single most important check in this section.

### 5.2 A home-relative path expands

- [ ] **Steps:** set `ED_CONFIG_DIR` to `~/edapitool-checklist-test` (literally, with the tilde), create that directory, put a settings file in it, and run `edapitool plugins`.
- [ ] **Expected:** the tilde expands; the file is found.

### 5.3 A missing settings file is not an error

- [ ] **Steps:** point `ED_CONFIG_DIR` at an empty directory and run `edapitool plugins`, `edapitool --version`, and `edapitool market --no-sheet`.
- [ ] **Expected:** all three run. No plugin loaded, no traceback, no complaint about a missing file. An absent configuration is absent, not broken.

## Section 6: flags and defaults (~3 min)

### 6.1 A flag the loaded plugin cannot take

- [ ] **Steps:** with the `jsonl` target configured, `edapitool market --no-sheet --need-sign negative`
- [ ] **Expected:** exit 1, and a message naming `--need-sign` and listing what the `jsonl` plugin's layout *does* take (`--fields`, `--only`, `--path`).
- [ ] **Why:** silently dropping the flag would be worse — a setting that cannot take effect should say so. Judge whether the message is actionable.

### 6.2 A flag nobody typed is not passed

- [ ] **Steps:** with the `jsonl` target configured, `edapitool market --no-sheet` with **no** layout flags at all.
- [ ] **Expected:** it runs. It must **not** complain about `--need-sign` or any other flag you did not type.
- [ ] **Why:** this was a real defect — the tool handed every plugin the settlement workbook's vocabulary whether it spoke it or not, so a file destination was refused for a flag nobody had asked for.

### 6.3 Known defect — `--show-formula` on a Windows pipe

- [ ] **Steps:** with a settlement target configured, run `edapitool market --show-formula` and pipe the output somewhere (e.g. `| findstr x`).
- [ ] **Expected — known defect, PRE-EXISTING at v0.7.4, not introduced here:** on a Windows console using codepage 1252, this raises `UnicodeEncodeError` and prints a traceback, because the formula text contains `○` (U+25CB).
- [ ] **Workaround to confirm:** set `PYTHONIOENCODING=utf-8` and re-run — it succeeds and emits 2013 bytes.
- [ ] **Check:** confirm it behaves this way rather than filing it as new. Unpiped, to a UTF-8-capable terminal, it should be fine.

## What the automated tests DON'T cover

- **Whether the migration message is good enough.** A test asserts the string is present. Only a person can say whether someone reading it cold knows what to do next. That is Section 1, and it is why this document exists.
- **Terminal rendering** — column alignment, 80-column wrapping, codepage handling. Section 6.3 is a live example of a defect that only appears through a real Windows pipe.
- **Real Google Sheets behaviour.** Nothing here opens a spreadsheet. The live dry-run comparison against the real workbook is a separate exercise and is deliberately out of scope.
- **Real CAPI calls**, including the fleet-carrier endpoint's 15-minute cooldown.
- **File locking and concurrency** — two `serve` daemons appending to one jsonl file, antivirus interference mid-write.
- **Whether the `plugins` output is pleasant**, as opposed to correct.
- **Performance feel** — does discovery feel instant with several plugins installed?

## Reporting issues found

1. Note the section and step number (e.g. `1.2`, `HV.4`).
2. Capture the exact command and its full output.
3. Say which shell you used and what `ED_CONFIG_DIR` was set to.
4. Save the settings file that produced it.
5. File an issue referencing this checklist by filename and the version it ships with.

**Before filing, check Sections 3.5 and 6.3** — two defects are known and documented there, and a duplicate report costs more than it looks.
