# Human Test Checklist: the renderer seam and presenter separability

- **Target version:** v0.3.2
- **Ships with commit:** TBD — "Split the sheet writer from this workbook's presentation"
- **Companion automated tests:** 312 tests — `tests/test_sheets.py` (106), `tests/test_journal.py` (46), `tests/test_matcher.py` (46), `tests/test_catalog.py` (45), `tests/test_market_data.py` (31), `tests/test_service.py` (24), `tests/test_gsheet_guard.py` (14)

## What this is

v0.3.2 is a refactor with **no intended user-visible change**. The code that decides which cells may be written, finds columns by header text and parses quantities was separated from the code that chooses glyphs and colours. The whole point of running this checklist is to confirm that "no intended change" is actually true — and the one thing automated tests provably cannot check is what the marker column *looks like* in a real browser against a real spreadsheet.

That gap is not hypothetical here. In v0.3.0 a conditional-formatting regression shipped green: every test passed, and the missing dark-green background was caught by a person looking at the sheet. Sections 2 and 4 exist because of that.

Run this before trusting v0.3.2 against your live workbook.

## Prerequisites

1. **Elite Dangerous installed**, with a journal directory. Sections 3 and 4 need the game running and the commander **docked at a station with a commodity market**.
2. **Python 3.10+** and the project installed in development mode (`pip install -e .`).
3. **A spreadsheet you are willing to write to.** Sections 4.2 and 4.3 write real cells. Every step that writes says so explicitly; every step before it uses `--dry-run`.
4. **Back up column L before Section 4.** This is the marker column and the tool rewrites it wholesale.

**Backing up the marker column** (do this once, before Section 4):

```
edapitool market --dry-run --no-colour > marker-column-before.txt
```

Then, in the browser, select column L rows 5–225, copy, and paste into a scratch tab or a local file. The tool's own backup is not a substitute — Google Sheets truncates trailing empty rows on read, so a programmatic snapshot can come back shorter than the column really is. This bit a restore during v0.3.0 development; the browser copy is the reliable one.

**Resetting between sections:** nothing in Sections 1–3 writes to the spreadsheet or to any config. Section 4 writes; restore from your column-L backup if you need to start over.

## High-Value Verification (~5 minutes)

**If you only have 5 minutes**, run these five. They are the whole claim of v0.3.2: nothing looks different, and the presentation is now genuinely optional.

### HV.1 — The suite and the mutation audit still agree

Validates: the refactor did not create an untested seam.

- [ ] **Steps** (same across all shells):

  ```
  python -m pytest -q
  python tests/one-offs/mutate.py
  ```

- [ ] **Expected:** `312 passed`, and `All 44 applied mutants killed.` No line saying any mutant *survived* or was *skipped*.
- [ ] **Why this matters:** A skipped mutant means the audit silently stopped measuring something. That happened during this very refactor — an anchor went stale when code moved and the runner quietly skipped it.

### HV.2 — The presenter is actually removable

Validates: issue #7's acceptance criterion 4, the one the layering test cannot reach.

- [ ] **Steps** (same across all shells):

  ```
  python tests/one-offs/thinking/presenter-removable/probe.py
  ```

- [ ] **Expected:** every line `OK`, ending `VERDICT: SEPARABLE`. In particular `CONTROL: markers is blocked` must say `OK`.
- [ ] **Why this matters:** If the CONTROL line says anything else, the probe is not actually removing the presenter and the verdict is meaningless — which is exactly how its first version passed while measuring nothing.

### HV.3 — Data-only paths need no spreadsheet and no credentials

Validates: the generic half of the tool stands alone.

- [ ] **Steps** (same across all shells):

  ```
  edapitool market --no-sheet --export csv
  edapitool market --no-sheet --json
  ```

- [ ] **Expected:** a CSV file written and machine-readable JSON on stdout. No browser window opens, no Google sign-in is requested.
- [ ] **Why this matters:** These paths went through the module that used to load the glyph definitions on import. If credentials are demanded here, the separation is cosmetic.

### HV.4 — The marker column looks identical (MANUAL, needs the game)

Validates: the refactor's core promise.

- [ ] **Steps:** Dock at a station with a commodity market, open the Commodity Market screen once, then:

  ```
  edapitool market --dry-run
  ```

- [ ] **Expected:** the same glyph set as before this version — `●` for "buy the whole outstanding quantity", `◕ ◑ ◔` for partial coverage, `○` for "sells it, currently out", blank for "not sold here". Nothing written.
- [ ] **Why this matters:** This is the visual contract. A test can assert the *string* `●`; only you can confirm the column still reads as a scale.

### HV.5 — The dark fill still carries light text (MANUAL, needs the browser)

Validates: the specific regression that shipped green once already.

- [ ] **Steps:** After running Section 4.2's write, look at the sheet in a browser. Find a row marked `●`.
- [ ] **Expected:** dark green background with **white** text. Lighter fills (`◕ ◑ ◔ ○`) carry black text. Rows you already have enough of show grey text on no fill.
- [ ] **Why this matters:** This exact pairing broke once and no test noticed. There is now a test for it (`test_only_the_darkest_fill_uses_light_text`), but the test asserts the API payload — only the browser shows what Sheets actually rendered.

## Section 1: The seam (~3 min, no game or spreadsheet needed)

### 1.1 The mechanics module knows nothing about presentation

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  python -c "import ast;t=ast.parse(open('APITool/sheets.py',encoding='utf-8').read());print(sorted({n.module for n in ast.walk(t) if isinstance(n,ast.ImportFrom) and n.module}))"
  findstr /R /C:"^MARKER_" /C:"^COLOUR_" APITool\sheets.py
  ```

  **PowerShell**:
  ```powershell
  python -c "import ast;t=ast.parse(open('APITool/sheets.py',encoding='utf-8').read());print(sorted({n.module for n in ast.walk(t) if isinstance(n,ast.ImportFrom) and n.module}))"
  Select-String -Path APITool\sheets.py -Pattern '^(MARKER_|COLOUR_)'
  ```

  **POSIX**:
  ```bash
  python -c "import ast;t=ast.parse(open('APITool/sheets.py',encoding='utf-8').read());print(sorted({n.module for n in ast.walk(t) if isinstance(n,ast.ImportFrom) and n.module}))"
  grep -E '^(MARKER_|COLOUR_)' APITool/sheets.py
  ```

- [ ] **Expected:** the import list contains `catalog` and `matcher` but **not** `markers`. The glyph/colour search returns nothing.
- [ ] **Check:** if `markers` appears in that list, the layering has inverted and `python -m pytest -k mechanics_module_does_not_import` should already be failing.

### 1.2 The write guard did not multiply

- [ ] **Steps** (pick your shell):

  - **cmd.exe**: `findstr /S /M "guard.check(" APITool\*.py`
  - **PowerShell**: `Select-String -Path APITool\*.py -Pattern 'guard\.check\(' | Select-Object -Unique Path`
  - **POSIX**: `grep -rl 'guard\.check(' APITool/`

- [ ] **Expected:** exactly one file — `APITool/sheets.py`.
- [ ] **Why this matters:** the guard is the thing standing between a typo and your hand-entered settlement data. If a second presenter ever has to call it itself, the guards can drift apart and one of them will be the lenient one.

### 1.3 A second renderer really is small

- [ ] **Steps** (same across all shells):

  ```
  python -m pytest tests/test_sheets.py -q -k "second_renderer" -v
  ```

- [ ] **Expected:** `test_ac5_a_second_renderer_is_fifteen_lines_and_borrows_every_mechanic` passes.
- [ ] **Check:** open `tests/test_sheets.py` and read `BuyListRenderer`. It should be readable end to end in a few seconds and mention nothing about guards, ranges or column letters. If it has grown, the seam is leaking.

### 3.2 The generated tab path still works

- [ ] **Steps** (writes to the spreadsheet — `MarketData` tab only):


- [ ] **Expected:** the `MarketData` tab is rewritten; the marker column in `Totals Tab` is **not** touched (that is what `--no-markers` means).
- [ ] **Check:** in the browser, confirm `Totals Tab` column L is unchanged from your backup.

### 3.3 No credentials anywhere on the generic path

- [ ] **Steps** (pick your shell — runs with an empty HOME so no saved token can be found):

  **PowerShell**:
  ```powershell
  $old = $env:USERPROFILE; $env:USERPROFILE = "$env:TEMP\edapitool-nocreds"
  New-Item -ItemType Directory -Force $env:USERPROFILE | Out-Null
  edapitool market --no-sheet --json
  $env:USERPROFILE = $old
  ```

  **POSIX**:
  ```bash
  HOME="$(mktemp -d)" edapitool market --no-sheet --json
  ```

- [ ] **Expected:** JSON on stdout. No browser opens, no prompt for a client ID.
- [ ] **Reset:** the PowerShell form restores `USERPROFILE` on its last line — confirm with `Write-Host $env:USERPROFILE` that it points back at your real profile before continuing.

## Section 4: The live write (MANUAL — writes real cells) (~5 min)

> **Skip this section** if you are not willing to write to a real spreadsheet. Sections 1–3 and HV.1–HV.4 already cover everything except the browser rendering.

### 4.1 Dry run first, always

- [ ] **Steps:** `edapitool market --dry-run`
- [ ] **Expected:** a list of exactly which cells would change. Read it. The only ranges named should be `C2`, `G2`, and the marker column from row 5 down.
- [ ] **Check:** if any other cell appears — especially anything in column B or column O — **stop and report it**. Column B holds formulas and column O holds hand-entered priority; neither is ours to write.

### 4.2 Write, then look

- [ ] **Steps:** `edapitool market`
- [ ] **Expected:** markers written; the station and system cells updated.
- [ ] **Check in the browser:**
  - `●` rows: dark green fill, white bold text
  - `◕ ◑ ◔` rows: progressively lighter green fill, black text
  - `○` rows: near-white fill, black text
  - rows you already have enough of: grey text, **no** fill
  - rows not sold here: completely blank, no fill, no leftover colour from a previous station

### 4.3 Stale formatting is actively cleared

- [ ] **Steps:** After 4.2, undock, fly to a **different** station with a market, open its Commodity Market screen, and run `edapitool market` again.
- [ ] **Expected:** every cell that no longer qualifies is blank **and uncoloured**. No green left behind from the previous station.
- [ ] **Why this matters:** a leftover fill under a blank glyph is the visual equivalent of a stale marker — it says "buy this here" about a station you have left. Only a two-station run shows it.

### 4.4 Hover notes still carry the numbers

- [ ] **Steps:** In the browser, hover over any marked cell.
- [ ] **Expected:** a note with the commodity name, quantity needed, stock, how many to buy now, unit price, estimated cost, and when the market was read.

## What the automated tests DON'T cover

- **What Google Sheets actually renders.** Every colour test asserts the *payload sent to the API*. Whether Sheets applied it, and whether the result is legible, is visible only in a browser. This is the single largest gap and the reason HV.5 and Section 4.2 exist.
- **Glyph rendering in a terminal.** Windows codepage 437/1252 will not show `● ◕ ◑ ◔ ○` correctly without a UTF-8-capable terminal.
- **Real Google API behaviour** — rate limits, partial batch failures, permission errors, and the fact that gspread mutates the dictionaries you hand it.
- **Real journal timing.** `Market.json` is written only when the Commodity Market screen is opened. No fixture reproduces the race between docking, opening the screen, and running the tool.
- **A live two-station sequence.** Section 4.3's stale-formatting check needs actual travel.
- **Whether the marker column is *useful*.** Tests confirm the glyphs are correct; only using the sheet while buying tells you whether the scale helps.

## Reporting issues found

1. Note the section and step number (e.g. "HV.5" or "4.3").
2. Capture the exact command and its full output.
3. For rendering issues, a screenshot of the sheet is worth more than any description.
4. Note your OS, terminal, and — on Windows — the output of `chcp`.
5. File against issue #7 if it concerns the generic/specialized separation; otherwise open a new issue referencing this checklist and the v0.3.2 commit.
