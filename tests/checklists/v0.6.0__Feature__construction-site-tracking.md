# Human Test Checklist: Colony construction site tracking

**Target version:** v0.6.0
**Ships with commit:** `Report what a colony construction site still needs`
**Companion automated tests:** 24 in `tests/test_construction.py`; 431 passing overall

## What this is

`edapitool construction` reads the game's own journal and reports what a colony build still needs. This checklist covers what the automated tests structurally cannot: whether the numbers agree with the in-game construction panel, whether the default scan depth finds *your* sites, and whether the names you can see in-game are the names the tool accepts.

**This release is read-only.** Nothing is written to any spreadsheet. See "What this release does NOT do" before reporting a bug.

Run it in about 15 minutes. If you only have five, do the High-Value section.

## Prerequisites

1. **Elite Dangerous, played at least once since colonisation launched**, with at least one construction site you have docked at or flown to. Without that there is nothing to read and every section below will correctly report nothing.
2. `edapitool` installed and on PATH.
3. **No setup required, and that is the point.** Do not configure a spreadsheet id or authenticate. If you already have, Section 1 asks you to prove the verb ignores them.

**State isolation:** this release writes nothing except the files you explicitly ask for with `--export`. Send those to a scratch directory:

**cmd.exe**
```cmd
set SCRATCH=%TEMP%\edapitool-check
mkdir %SCRATCH%
```

**PowerShell**
```powershell
$env:SCRATCH = "$env:TEMP\edapitool-check"
New-Item -ItemType Directory -Force $env:SCRATCH
```

**POSIX**
```bash
export SCRATCH=/tmp/edapitool-check
mkdir -p "$SCRATCH"
```

## High-Value Verification (~5 minutes)

### HV.1 — It works with nothing configured

Validates the rule this verb exists to follow: an output format must not require credentials.

- [ ] **Steps:** in a shell with **no** `ED_SHEET_ID` set and no Frontier login performed:
  ```
  edapitool construction --json
  ```
- [ ] **Expected:** valid JSON on stdout, exit code 0. No prompt, no error about a spreadsheet, no authentication attempt.
- [ ] **Why this matters:** if this fails, the verb has acquired a dependency it does not need — the exact defect issue #10 was filed for.

### HV.2 — The numbers agree with the game

Validates the parser against the only authority that matters.

- [ ] **Steps:** dock at a construction site, open its construction panel in-game, and note two or three commodities with their required and delivered amounts. Then:
  ```
  edapitool construction
  ```
- [ ] **Expected:** the "still need" column equals what the panel shows as outstanding, and "delivered" equals what it shows as contributed.
- [ ] **Why this matters:** no mock can tell you the parser agrees with Elite Dangerous. This is the one check nothing else can make.

### HV.3 — It finds all of your sites

- [ ] **Steps:**
  ```
  edapitool construction --list --all
  ```
- [ ] **Expected:** every construction site you can remember visiting appears. Note how many.
- [ ] **Then:** `edapitool construction --list --all --scan-files` (no number — reads every journal file).
- [ ] **Expected:** the same count. **If the second command finds MORE, the default scan depth is too shallow for your journal — please report it with both counts and the number of files in your journal directory.**
- [ ] **Why this matters:** a default that silently hides half your builds looks like missing data rather than a missing setting.

### HV.4 — You can select a site by the name you can see

- [ ] **Steps:** take a station name exactly as the game shows it, *without* any "Planetary Construction Site:" prefix, and:
  ```
  edapitool construction --site "Your Site Name"
  ```
- [ ] **Expected:** that site's report. The prefixed form and the bare `MarketID` should work too.
- [ ] **Why this matters:** the game prefixes these names and a person does not. If only the prefixed form matched, nobody would ever type it.

### HV.5 — Nothing was written anywhere

- [ ] **Steps:** after running everything above, open your tracking spreadsheet if you have one.
- [ ] **Expected:** completely unchanged. No new tab, no edited cell.
- [ ] **Why this matters:** this release is read-only by design; any write is a bug.

## Section 1: Works with nothing configured (~3 min)

### 1.1 No spreadsheet id anywhere

- [ ] **Steps** (clear the variable for this shell only):

  **cmd.exe**
  ```cmd
  set ED_SHEET_ID=
  edapitool construction
  edapitool construction --json
  edapitool construction --list
  ```

  **PowerShell**
  ```powershell
  Remove-Item Env:\ED_SHEET_ID -ErrorAction SilentlyContinue
  edapitool construction
  edapitool construction --json
  edapitool construction --list
  ```

  **POSIX**
  ```bash
  unset ED_SHEET_ID
  edapitool construction
  edapitool construction --json
  edapitool construction --list
  ```
- [ ] **Expected:** all three succeed. No mention of spreadsheets, sheet ids, or Google.

### 1.2 The help does not advertise credentials

- [ ] **Steps:** `edapitool construction -h`
- [ ] **Expected:** **no** `--client-id`, `--redirect-uri` or `--manual-auth`. This verb never authenticates and its help should not offer options implying otherwise.
- [ ] **Note:** `edapitool ship -h` and `edapitool serve -h` *do* still list those, and neither authenticates either. That is a known pre-existing wart, not a fault of this release.

### 1.3 No journal at all

- [ ] **Steps:** `edapitool construction --journal-dir "%TEMP%\definitely-not-a-journal"` (cmd) / `$env:TEMP\...` (PowerShell) / `/tmp/definitely-not-a-journal` (POSIX)
- [ ] **Expected:** a clear message that no journal directory was found, mentioning `ED_JOURNAL_DIR`. Exit non-zero. **Not** a traceback.

## Section 2: Reading real journal data (~4 min)

### 2.1 The default report

- [ ] **Steps:** `edapitool construction`
- [ ] **Expected:** site name, system, an "Updated" timestamp, a progress percentage with tonnes, then a table of outstanding commodities sorted by **most needed first**, with what each pays per tonne. A trailing count of outstanding commodities and total tonnes.
- [ ] **Check:** the percentage is consistent with the tonnes — `provided / required` should equal the percentage shown.

### 2.2 Progress agrees with the game's own figure

- [ ] **Steps:** `edapitool construction --json`, then compare `progress` against `total_provided / total_required`.
- [ ] **Expected:** they match to at least four decimal places.
- [ ] **Why:** the game reports progress directly and it was measured to be a plain tonnage ratio. If these ever diverge, the game changed its definition and that is worth knowing.

### 2.3 A completed site

- [ ] **Steps:** if you have finished a build: `edapitool construction --site "That Site" --all`
- [ ] **Expected:** status `complete`, 100%, and "Nothing outstanding — every commodity is delivered."

### 2.4 Scan depth and timing

- [ ] **Steps:**
  ```
  edapitool construction --list --all --scan-files 6
  edapitool construction --list --all
  edapitool construction --list --all --scan-files
  ```
- [ ] **Expected:** the counts should be equal or increasing. Note roughly how long the last one takes.
- [ ] **Reference:** on one journal of 621 files, 6 files found 3 of 6 sites in 0.09s, the default 120 found all 6 in about 1s, and all 621 took 4.4s and found no more. **If your timings are wildly different — particularly if the default feels slow — please report your file count.**

## Section 3: Selecting among several sites (~3 min)

Skip if you only have one construction site.

### 3.1 Listing

- [ ] **Steps:** `edapitool construction --list`
- [ ] **Expected:** only **active** sites, with a footnote saying how many were hidden and why.
- [ ] **Then:** `edapitool construction --list --all` — completed, failed and stale sites appear with their status in place of a percentage.

### 3.2 Two sites sharing a name

- [ ] **Steps:** if two of your builds share a station name: `edapitool construction --site "Shared Name"`
- [ ] **Expected:** an error that names the ambiguity and shows the `--system` value for each candidate. **Not** a silent pick of the first.
- [ ] **Then:** re-run with `--system "..."` and confirm it resolves.

### 3.3 A name that does not exist

- [ ] **Steps:** `edapitool construction --site "No Such Place"`
- [ ] **Expected:** an error that then **lists the sites that do exist**, with their ids. Exit non-zero.

### 3.4 A site you have never approached

- [ ] **Steps:** look for any row in `--list --all` showing `(name unknown)`.
- [ ] **Expected:** if present, a **single** footnote explains it — not one hint repeated under every such row. Selecting it by `MarketID` still works.
- [ ] **Why:** the journal can hold what a site needs without ever having recorded what it is called.

## Section 4: Renamed sites (~2 min)

Skip unless you have renamed a build.

### 4.1 Former names are shown

- [ ] **Steps:** `edapitool construction --list --all`
- [ ] **Expected:** a renamed site shows its **current** name, followed by `(was Old Name)`.

### 4.2 Old names still select it

- [ ] **Steps:** `edapitool construction --site "The Name It Used To Have"`
- [ ] **Expected:** resolves, and reports under the **current** name.
- [ ] **Why this matters:** notes written months ago keep working, and you get back the name to fly to.

---

## Section 5: Stale and abandoned builds (~2 min)

### 5.1 The wording never claims more than it knows

- [ ] **Steps:** `edapitool construction --list --all`, looking at any site marked `stale`.
- [ ] **Expected:** the output says how long since the game last mentioned it. It should **never** say "expired", "abandoned" or "failed" for a merely-old site.
- [ ] **Why this matters:** Elite Dangerous does not mark a lapsed build failed — measured on a site left at 15.2% and untouched for 303 days, the flag is still false. Staleness here is our inference from elapsed time, and the wording has to admit that.

### 5.2 The threshold is adjustable

- [ ] **Steps:** `edapitool construction --list --all --stale-after 5` then `--stale-after 3650`
- [ ] **Expected:** sites move between `stale` and `active`. A **complete** site stays complete at any threshold — completion is a fact and outranks a time-based guess.

---

## Section 6: Exports (~2 min)

### 6.1 CSV and JSON

- [ ] **Steps:**
  ```
  edapitool construction --export csv,json --output <SCRATCH>
  ```
- [ ] **Expected:** two files named for the site and a timestamp. Paths printed.
- [ ] **Check the CSV:** one row per commodity, with the site's identity and progress repeated on every row so snapshots concatenate.
- [ ] **Check the JSON:** it should be **identical in structure** to `--json` on stdout. If they differ, that is a bug — they are built by the same function precisely so a script reading a file and a script reading stdout see the same shape.

### 6.2 Export needs no spreadsheet either

- [ ] **Expected:** 6.1 worked with no sheet id configured. If it asked for one, that is the issue-#10 defect returning.

---

## Section 7: Windows console and encoding (~2 min)

### 7.1 A plain cmd.exe window

- [ ] **Steps:** open **cmd.exe** (not Windows Terminal, not PowerShell) and run:
  ```cmd
  edapitool construction
  edapitool construction --list --all
  ```
- [ ] **Expected:** no `UnicodeEncodeError`, no garbled characters, columns line up.
- [ ] **Why this matters:** this project has a live history here — a sibling command once crashed on a console that could not encode a glyph. Station names carry apostrophes, and a colonisation ship's raw name contains `$` and `;`.

### 7.2 Long names do not break the table

- [ ] **Expected:** a long station or commodity name may widen the table but must not corrupt the alignment of other rows.

## What this release does NOT do

Read this before filing a bug.

- **Nothing is written to any spreadsheet.** No new tab, no cells, no formatting.
- **`edapitool serve` does not publish construction data.** The daemon still publishes only `MarketData` and `ShipCargo`.
- **No settlement-tab integration exists.** You cannot yet declare in a tab which site it tracks, and nothing populates a "Delivered" column.

All of that is the next unit of work, tracked in issue #21.

## What the automated tests DON'T cover

- **Whether the parser agrees with the game.** Fixtures are shaped from real events, but only a human with the construction panel open can confirm the tool and Elite Dangerous say the same thing.
- **Whether the default scan depth suits *your* journal.** The default was chosen from one commander's 621 files.
- **Console rendering** on Windows codepages, terminal width, column alignment.
- **Real journal files** — malformed lines, partial writes, rollover mid-session, unusual directory locations.
- **Whether the output is actually useful.** A shopping list sorted the wrong way passes every assertion.
- **A renamed site end to end**, which needs a rename to have really happened.

## Reporting issues found

1. Note the section and step number.
2. Capture the exact command and its full output.
3. Include your journal file count and roughly how long the command took, for anything scan-related.
4. **Do not paste your `MarketID`s if you would rather not** — the site name and progress are enough for almost every report.
5. File against issue #21, referencing this checklist and the version.
