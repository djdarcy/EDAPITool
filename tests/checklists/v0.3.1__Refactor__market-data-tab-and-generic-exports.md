- **Test strength:** all 38 injected mutants killed (`python tests/one-offs/mutate.py`)

## What this is

Before v0.3.1, the only way the station market reached a spreadsheet was as symbols and cell colours written directly into specific cells. That is a *rendering*: nobody else could consume it, and it could not be restyled without a code change.

v0.3.1 makes the tool emit the market as **data** — as CSV, as JSON, and as a generated `MarketData` tab that any spreadsheet can read with its own `VLOOKUP` formulas. Writing markers directly still works and is still the default, so nothing changes until you opt in.

This checklist verifies two things automated tests structurally cannot: that the data contract behaves as documented **inside a real Google Sheet**, and that the generic paths genuinely work for someone with no Google credentials at all.

**Steps marked `MANUAL` need a real spreadsheet and/or a running copy of Elite Dangerous.** Steps marked `SAFE` write only to scratch locations or nowhere.

## Prerequisites

1. **Python 3.10+**, package installed: `pip install -e .[gsheets]`
2. **A Google Sheet** copy for testing (File → Make a copy). Note its id from the URL.
3. **Elite Dangerous** with a journal directory, or `ED_JOURNAL_DIR` pointing at one.

### State isolation

Sections 1 and 4 need **no** spreadsheet and **no** credentials — that is what they exist to prove. Sections 2 and 3 write to whichever spreadsheet id you supply, so **use a copy**, not your working sheet.

**cmd.exe**
```cmd
set ED_SHEET_ID=YOUR_COPY_ID
set OUT=%TEMP%\edtest-market
mkdir %OUT%
```

**PowerShell**
```powershell
$env:ED_SHEET_ID = "YOUR_COPY_ID"
$env:OUT = "$env:TEMP\edtest-market"
New-Item -ItemType Directory -Force $env:OUT
```

**POSIX**
```bash
export ED_SHEET_ID=YOUR_COPY_ID
export OUT=/tmp/edtest-market
mkdir -p "$OUT"
```

### A note on console output

The marker glyphs (`● ◕ ◑ ◔ ○`) are non-ASCII. Windows consoles default to cp1252 and will mangle them in **terminal output only** — they reach Google Sheets correctly regardless. Set `PYTHONIOENCODING=utf-8` if the terminal display bothers you.

### Reset between sections

**cmd.exe**: `set ED_SHEET_ID=` &nbsp; **PowerShell**: `Remove-Item Env:\ED_SHEET_ID` &nbsp; **POSIX**: `unset ED_SHEET_ID`

  **POSIX**

  ```bash
  export HOME=/tmp/edtest-nocreds && mkdir -p "$HOME"
  export ED_JOURNAL_DIR="/path/to/Saved Games/Frontier Developments/Elite Dangerous"
  edapitool market --no-sheet --export csv,json --output "$OUT"
  ```

- [ ] **Expected:** Two files written, named after the station. No credential prompt, no browser, no error.
- [ ] **Why this matters:** If this needs credentials, the tool is not generic and the release has not delivered what it claims.

### HV.3 — The MarketData tab is written and shaped correctly `MANUAL`

- [ ] **Steps:** Dock somewhere, open the station's Commodity Market screen once, then:
  ```
  edapitool market --sheet-id YOUR_COPY_ID --export market-tab --no-markers
  ```
- [ ] **Expected:** A `MarketData` tab appears. Row 1 names the station and system, row 2 the timestamp and source, row 3 the headers, row 4 onward one commodity per row. Column A is empty.
- [ ] **Why this matters:** This is the published contract other spreadsheets will build against.

### HV.4 — The documented VLOOKUP actually returns the right values `MANUAL`

- [ ] **Steps:** In any empty cell of your **copy**, enter:
  ```
  =VLOOKUP("Biowaste", MarketData!$B:$G, 2, FALSE)
  =VLOOKUP("Biowaste", MarketData!$B:$G, 3, FALSE)
  ```
  (substitute a commodity the station actually stocks)
- [ ] **Expected:** The first returns stock, the second returns buy price — matching what `edapitool market --no-sheet` printed.
- [ ] **Check:** Delete the scratch cells afterwards.
- [ ] **Why this matters:** The README publishes these exact index numbers. If they are off by one, every consumer's formula is silently wrong.

### HV.5 — `--no-markers` leaves the marker column untouched `MANUAL`

- [ ] **Steps:** Note the marker column contents. Run HV.3's command again. Re-check.
- [ ] **Expected:** The marker column is **byte-identical** — same glyphs, same colours, same header cell.
- [ ] **Why this matters:** The refactor is meant to be additive. Silently clearing markers would be a regression.

### HV.6 — Default behaviour is unchanged `MANUAL`

- [ ] **Steps:** `edapitool market --sheet-id YOUR_COPY_ID --update-sheet`
- [ ] **Expected:** Markers written exactly as in v0.3.0 — same glyphs, same green scale, same grey for covered rows. No `MarketData` tab is written (you did not ask for one).
- [ ] **Why this matters:** Existing users must see no change until they opt in.

## Section 2: The MarketData tab (~10 min) `MANUAL`

### 2.1 The tab is created if absent

- [ ] **Steps:** Delete `MarketData` from your copy, then run `--export market-tab`.
- [ ] **Expected:** It is recreated with the right shape. No error.

### 2.2 Wholesale rewrite, no stale rows

- [ ] **Steps:** Export at a station with many commodities, then at one with fewer.
- [ ] **Expected:** The tab holds only the second station's commodities. **No leftovers from the first.**

### 2.3 Metadata never collides with a lookup

- [ ] **Steps:** Inspect column B of the tab.
- [ ] **Expected:** Only `Station`, `Updated (UTC)`, `Commodity`, and real commodity names. The station name itself is in column C, **not** column B.
- [ ] **Why:** A whole-column `VLOOKUP` would otherwise be able to match a metadata row.

### 2.4 Not docked clears the tab rather than leaving it stale

- [ ] **Steps:** Undock, then `edapitool market --sheet-id YOUR_COPY_ID --export market-tab`
- [ ] **Expected:** The tab is rewritten with the headers and **no commodity rows**; row 1 carries the reason (e.g. `Not docked`).
- [ ] **Why this matters:** A tab still holding the last station's prices, under a fresh-looking header, is the same failure the market freshness gate exists to prevent — just on a different surface.

### 2.5 Stale market data also clears it

- [ ] **Steps:** Dock somewhere new **without** opening the commodity screen, then export.
- [ ] **Expected:** Headers only, with "Commodity Market screen" in the reason.

### 2.6 The write guard still holds

## Section 3: The sheet-side marker formula (~10 min) `MANUAL`

### 3.1 The formula is printed and copy-pasteable

- [ ] **Steps:** `edapitool market --show-formula`
- [ ] **Expected:** A formula, the glyph legend, and the suggested conditional-formatting colours. Exits without touching anything.

### 3.2 The formula reproduces the tool's own markers

This is the check that proves the specialized formatting is genuinely reproducible in the sheet.

- [ ] **Steps:**
  1. Run `--update-sheet` so the tool writes markers. Screenshot or note the column.
  2. Run `--export market-tab` so `MarketData` is current.
  3. Paste the `--show-formula` formula into the first commodity row of the marker column and fill down.
- [ ] **Expected:** **Every cell shows the same glyph the tool wrote.**
- [ ] **Reset:** Undo (Ctrl+Z) to restore the tool-written values.
- [ ] **Gotcha, learned the hard way:** if you script this restore rather than using Ctrl+Z, note that reading a range returns **fewer rows than you asked for** when the trailing cells are empty. Pad your restore to the full range or the last rows keep the formula.

### 3.3 Conditional formatting survives a tab rewrite

- [ ] **Steps:** Set up the colour rules on the marker column, then run `--export market-tab` again.
- [ ] **Expected:** Colours unaffected. The rules live on the marker column; the rewrite touches only `MarketData`.

### 3.4 The formula degrades sensibly for unknown commodities

- [ ] **Steps:** Add a commodity to a settlement tab that the current station does not trade.
- [ ] **Expected:** The formula's `IFERROR` yields 0, producing a blank cell — not `#N/A`.
- [ ] **Note:** This is a deliberate lossiness. The CLI still reports unrecognized commodity names; the formula cannot.

## What the automated tests DON'T cover

- **Whether Google Sheets evaluates the published `VLOOKUP` indices as documented.** Tests assert the grid's *positions*; only a real sheet proves the formula. HV.4 and 3.2 are the only evidence.
- **Whether the `--show-formula` output pastes cleanly** into the Sheets formula bar — quoting, `LET()` availability, locale-dependent argument separators (some locales use `;` not `,`).
- **Conditional formatting behaviour** across a tab rewrite.
- **Real API latency** for a ~370-row write on every docking.
- **Whether the tab is legible to a human** — column widths, number formatting, whether the metadata rows read as metadata.
- **Locale and codepage effects** on the glyphs in terminal output.
- **Whether a stranger can actually use the CSV** without reading our source.
