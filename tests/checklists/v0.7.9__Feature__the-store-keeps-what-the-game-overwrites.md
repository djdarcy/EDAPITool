# Human Test Checklist: the store keeps what the game overwrites

**Target version:** 0.7.9
**Ships with commit:** TBD (pre-commit)
**Companion automated tests:** 63 new: `tests/test_store.py` (34: open, versions, verify, backup, rebuild, archive, the market projection, the CLI verbs, the docs), `tests/test_store_archive.py` (15: the side files, the off switch, output unchanged with the store on and off, a store failure never reaching the command, the CAPI answers and where they are located), 12 fingerprint tests added to `tests/test_daemon.py` and 2 watcher tests added to `tests/test_journal.py`. Full suite: 929.

## What this is

From 0.7.9 the tool keeps everything it reads from the game and from Frontier in one SQLite file, `store.db`, beside `config.json` -- the bytes as read, so the game rewriting `Market.json` no longer destroys the only copy -- and gains three verbs to look after that file: `store verify`, `store backup`, `store rebuild`. Two `serve` bugs are fixed in the same release. This checklist walks all of it in a **scratch configuration directory** and a **scratch journal directory**, so your real `~/edapitool/` and your real journal are never touched. About 15 minutes; nothing needs the game, a spreadsheet, a Frontier login or the network except the two optional sections at the end.

## Prerequisites

1. 0.7.9 installed editable (`pip install -e .` from the repo root); `edapitool --version` prints `0.7.9`. Python 3.10 or newer on the path (the queries below use its `sqlite3` module; the `sqlite3` command-line shell is not needed).
2. **Every section sets `ED_CONFIG_DIR` to a scratch directory.** With it set, nothing under `~/edapitool/` is read or written. The first `market` command in a fresh scratch directory also writes a starting `config.json` there and says so on its first line; that is 0.7.8's behaviour and expected. Start from a fresh scratch directory:

   **cmd.exe**
   ```cmd
   set ED_CONFIG_DIR=%TEMP%\edapitool-scratch
   if exist "%ED_CONFIG_DIR%" rmdir /s /q "%ED_CONFIG_DIR%"
   set ED_NO_STORE=
   ```
   **PowerShell**
   ```powershell
   $env:ED_CONFIG_DIR = "$env:TEMP\edapitool-scratch"
   if (Test-Path $env:ED_CONFIG_DIR) { Remove-Item -Recurse -Force $env:ED_CONFIG_DIR }
   Remove-Item Env:\ED_NO_STORE -ErrorAction SilentlyContinue
   ```
   **POSIX**
   ```bash
   export ED_CONFIG_DIR=/tmp/edapitool-scratch
   rm -rf "$ED_CONFIG_DIR"
   unset ED_NO_STORE
   ```
3. **A scratch journal directory** holding one journal file and the captured Ryman market. From the repo root:

   **cmd.exe**
   ```cmd
   set ED_JOURNAL=%TEMP%\edapitool-journal
   if exist "%ED_JOURNAL%" rmdir /s /q "%ED_JOURNAL%"
   mkdir "%ED_JOURNAL%"
   copy tests\fixtures\market_ryman_journal.json "%ED_JOURNAL%\Market.json"
   ```
   **PowerShell**
   ```powershell
   $env:ED_JOURNAL = "$env:TEMP\edapitool-journal"
   if (Test-Path $env:ED_JOURNAL) { Remove-Item -Recurse -Force $env:ED_JOURNAL }
   New-Item -ItemType Directory $env:ED_JOURNAL | Out-Null
   Copy-Item tests\fixtures\market_ryman_journal.json "$env:ED_JOURNAL\Market.json"
   ```
   **POSIX**
   ```bash
   export ED_JOURNAL=/tmp/edapitool-journal
   rm -rf "$ED_JOURNAL"; mkdir -p "$ED_JOURNAL"
   cp tests/fixtures/market_ryman_journal.json "$ED_JOURNAL/Market.json"
   ```
   Then create the journal file (cross-shell, needs Python):
   ```
   python -c "import os,json; d=os.environ['ED_JOURNAL']; open(os.path.join(d,'Journal.2026-09-08T021410.01.log'),'w',encoding='utf-8').write(json.dumps({'timestamp':'2026-09-08T02:14:10Z','event':'LoadGame','Commander':'Tester','FID':'F0000001'})+'\n'+json.dumps({'timestamp':'2026-09-08T02:14:12Z','event':'Docked','StationName':'Ryman Enterprise','StarSystem':'Lhou Mans','MarketID':3226578176,'StationType':'Coriolis','StationServices':['dock','commodities']})+'\n')"
   ```
4. The query used throughout. Save this as `q.py` in the scratch journal directory with your editor (a one-liner that writes it was tried and PowerShell's quoting rejects it):
   ```python
   import os, sqlite3, sys
   p = os.path.join(os.environ["ED_CONFIG_DIR"], "store.db")
   print("store:", p, "exists" if os.path.exists(p) else "MISSING")
   if os.path.exists(p):
       c = sqlite3.connect(p)
       for sql in sys.argv[1:]:
           print(sql)
           for row in c.execute(sql):
               print("  ", row)
       c.commit()
   ```
   Check it: `python %ED_JOURNAL%\q.py` / `python $env:ED_JOURNAL\q.py` / `python "$ED_JOURNAL/q.py"` prints `store: ... MISSING`.

Below, `<Q>` stands for that command with the path spelled for your shell, and `<J>` for the scratch journal directory (`%ED_JOURNAL%`, `$env:ED_JOURNAL`, `"$ED_JOURNAL"`).

## High-Value Verification (~5 minutes)

### HV.1: `store verify` on a fresh install creates nothing

- [ ] **Steps:** with a fresh scratch directory (prerequisite 2), `edapitool store verify`
- [ ] **Expected:** `No store at <scratch>\store.db -- nothing has been archived yet.`, exit 0. The scratch directory **does not exist** afterwards, and no `config.json` was written either: `dir %ED_CONFIG_DIR%` / `Test-Path $env:ED_CONFIG_DIR` / `ls "$ED_CONFIG_DIR"` reports it missing.
- [ ] **Why this matters:** a verb that checks a file must not make one to have something to check; and the store verbs are the one command family exempt from the first-run configuration write.

### HV.2: one read, one row

- [ ] **Steps:**
  ```
  edapitool market --journal-dir <J> --no-sheet --json
  edapitool market --journal-dir <J> --no-sheet --json
  edapitool store verify
  <Q> "select obs_id,kind,subject,observed_at from observations" "select obs_id,market_id,station,items_count from market_snapshot" "select commander,commander_fid,liveness from sources"
  ```
- [ ] **Expected:** the first `market` run begins with the `Wrote a starting configuration` line (0.7.8) and both print the market as JSON (`"ok": true`, the Ryman items). `store verify` prints `Store OK: <scratch>\store.db`. The query shows **one** observations row, `(1, 'market_json', '3226578176', '2026-09-08T05:48:18Z')`; **one** snapshot, `(1, 3226578176, 'Ryman Enterprise', N)` with N the number of items in the fixture; and a sources row `('Tester', 'F0000001', 'absent')` -- the commander and Frontier id came from the journal's `LoadGame`, and the file is `absent` because the game can overwrite it.
- [ ] **Why this matters:** the same bytes read twice are one round, so polling in `serve` costs nothing; and the row names who was playing.

### HV.3: the game overwriting the file loses nothing

- [ ] **Steps:** rewrite `Market.json` as a different station's market (cross-shell, needs Python):
  ```
  python -c "import os,json; p=os.path.join(os.environ['ED_JOURNAL'],'Market.json'); d=json.load(open(p,encoding='utf-8')); d['MarketID']=4323280387; d['StationName']='Dieterle Beacon'; d['timestamp']='2026-09-08T06:00:00Z'; open(p,'w',encoding='utf-8').write(json.dumps(d))"
  edapitool market --journal-dir <J> --no-sheet --json
  <Q> "select obs_id,subject,length(payload) from observations" "select obs_id,market_id,station from market_snapshot"
  ```
- [ ] **Expected:** the `market` output now says the market is stale (`"ok": false`, the reason names the station mismatch: the journal still says you are docked at Ryman) -- **and the read was archived anyway**: two observations rows, subjects `3226578176` then `4323280387`, two snapshots, `Ryman Enterprise` then `Dieterle Beacon`. The first row's payload length is unchanged from HV.2 (compare with `length(payload)` there if you noted it; or trust that the bytes are content-addressed and a rewrite cannot alter a stored row).
- [ ] **Why this matters:** this is the whole reason the store exists. Before 0.7.9 the Ryman bytes were gone the moment the file was rewritten.

### HV.4: `backup` after `verify`, and `rebuild` never touches the raw rows

- [ ] **Steps:**
  ```
  edapitool store backup
  <Q> "delete from market_item" "select count(*) from market_item"
  edapitool store rebuild
  <Q> "select count(*) from market_item" "select count(*) from observations" "select count(*) from sources"
  ```
- [ ] **Expected:** `Backed up to <scratch>\store.db.bak-<stamp>` and that file exists beside `store.db`. After the delete the item count is 0; after `Rebuilt market_snapshot, market_item from the primary tables.` the item count is back to the two markets' items, and the observations and sources counts are exactly what they were (2 and 2).
- [ ] **Why this matters:** a projection that looks wrong is one `rebuild` away, and a rebuild can never cost a raw row.

### HV.5: the off switch, and the command's output does not change

- [ ] **Steps:** with a fresh scratch directory (prerequisite 2) **and the Ryman `Market.json` copied back** (prerequisite 3's copy -- HV.3 left the Dieterle version in place, and a stale market prints no `age_seconds` to compare), then `ED_NO_STORE` set (`set ED_NO_STORE=1` / `$env:ED_NO_STORE = "1"` / `export ED_NO_STORE=1`):
  ```
  edapitool market --journal-dir <J> --no-sheet --json
  <Q>
  ```
  then unset it (`set ED_NO_STORE=` / `Remove-Item Env:\ED_NO_STORE` / `unset ED_NO_STORE`) and run the same `market` command again.
- [ ] **Expected:** `<Q>` reports the store `MISSING` after the first run. The two JSON outputs are identical apart from `"age_seconds"` under `"market"` (the market's age against the wall clock, which moves between runs) and the first run's `Wrote a starting configuration` line, which the fresh directory earns. Judge it by eye or save both to files and diff them.
- [ ] **Why this matters:** the store is additive. Nothing you asked for changes because of it, and a person who wants no bookkeeping has a switch.

## Section 1: refusals (~3 min)

Start from the state HV.4 left (a store with two markets), or rebuild it with HV.2 and HV.3.

### 1.1 a table the tool did not make fails `verify`, and `backup` refuses

- [ ] **Steps:**
  ```
  <Q> "create table stray (x integer)"
  edapitool store verify
  edapitool store backup
  ```
- [ ] **Expected:** `verify` prints `Store <path>: 1 problem(s)` and `  - table stray is not registered (this tool did not make it)`, exit 1. `backup` prints `Refused: backup refused; verify found: table stray is not registered ...` on stderr, exit 1, and **no new** `store.db.bak-*` file appears (`dir %ED_CONFIG_DIR%` / `Get-ChildItem $env:ED_CONFIG_DIR` / `ls "$ED_CONFIG_DIR"`).
- [ ] **Check:** `<Q> "drop table stray"` then `edapitool store verify` is `Store OK` again.

### 1.2 a store from a newer tool is refused by name, by every verb

- [ ] **Steps:**
  ```
  <Q> "pragma user_version=7"
  edapitool store verify
  edapitool store backup
  edapitool store rebuild
  ```
- [ ] **Expected:** each prints `Refused: <path> is schema version 7, newer than this tool's 1; upgrade edapitool rather than let it guess` on stderr, exit 1, and nothing in the file changes. Read the path as rendered on your console: it should be your scratch path, not garbled.
- [ ] **Check:** `<Q> "pragma user_version=1"` restores it; `store verify` is OK.

### 1.3 `backup` and `rebuild` with no store

- [ ] **Steps:** with a fresh scratch directory (prerequisite 2): `edapitool store backup` then `edapitool store rebuild`.
- [ ] **Expected:** both print `No store at <scratch>\store.db -- nothing has been archived yet.` and exit **2** (`echo %ERRORLEVEL%` / `$LASTEXITCODE` / `echo $?`); `verify` in the same state exits 0 (HV.1). Nothing is created.

## Section 2: the other side files (~2 min)

### 2.1 `ship` archives `Cargo.json`

- [ ] **Steps:** copy the cargo fixture beside the journal (`copy tests\fixtures\cargo_ship.json "%ED_JOURNAL%\Cargo.json"` / `Copy-Item tests\fixtures\cargo_ship.json "$env:ED_JOURNAL\Cargo.json"` / `cp tests/fixtures/cargo_ship.json "$ED_JOURNAL/Cargo.json"`), then:
  ```
  edapitool ship --journal-dir <J> --json
  <Q> "select kind,subject,observed_at from observations where kind='cargo_json'"
  ```
- [ ] **Expected:** the hold prints as JSON as it did in 0.7.8; the query shows one row `('cargo_json', 'Ship', '2026-09-08T06:46:29Z')`. No new `market_snapshot` row (cargo is kept raw; it has no projection yet).

### 2.2 a file the game is mid-way through writing is not a row

- [ ] **Steps:** truncate `Market.json` to half (cross-shell, needs Python):
  ```
  python -c "import os; p=os.path.join(os.environ['ED_JOURNAL'],'Market.json'); b=open(p,'rb').read(); open(p,'wb').write(b[:len(b)//2])"
  edapitool market --journal-dir <J> --no-sheet --json
  <Q> "select count(*) from observations"
  ```
- [ ] **Expected:** `market` reports no market data (as 0.7.8 did for an unreadable file) and the observations count is unchanged. Restore the file afterwards with prerequisite 3's copy. Note the advice it prints says `No Market.json found` although the file is present and half-written: that wording predates 0.7.9 and conflates absent with unreadable; it is a known wording gap, not a store defect.

## Section 3 (optional): with the game and a Frontier login (~5 min)

Skip unless you have `edapitool auth` set up. **Use your real `~/edapitool/` for this section** (unset `ED_CONFIG_DIR`), because that is where your tokens are; the store there is yours to keep.

### 3.1 `profile` archives Frontier's answer

- [ ] **Steps:** `edapitool profile`, then with `ED_CONFIG_DIR` unset run the query against `~/edapitool/store.db`:
  ```
  python -c "import os,sqlite3; c=sqlite3.connect(os.path.expanduser('~/edapitool/store.db')); print(c.execute('select kind,subject,recorded_at from observations where kind like \"capi_%\" order by obs_id desc limit 3').fetchall())"
  ```
- [ ] **Expected:** a `capi_profile` row whose subject is your commander name, recorded just now. Run `profile` again within a minute: no second row (Frontier's answer has not changed).

### 3.2 `serve` at a station with no commodity market

- [ ] **Steps:** in the game, dock somewhere with a commodity market, then somewhere without one (an outpost or settlement with no market), with `edapitool serve` running against your usual configuration.
- [ ] **Expected:** on the second docking the log line for `MarketData` says it was **written** (the advice row for "no commodity market" at the new station), not `MarketData unchanged`. Before 0.7.9 it said unchanged and the tab kept showing the previous station.

## What the automated tests DON'T cover

- **The game writing CRLF journals** needs no hand check: the game does, the watcher test writes CRLF bytes, and the mutation sweep showed that every other watcher test was CRLF on Windows too. Nothing to walk.
- **Real file locking while the game rewrites `Market.json`**: the reader treats an unreadable or half-written file as "no data right now" (2.2 simulates it with a truncated file); the live race is only observable with the game running.
- **`store.db-wal` and `store.db-shm` beside the file**: the store uses write-ahead logging, so two small companion files appear while a connection is open, and on a network or synced drive they are worth a look. `serve` keeps no connection open between reads.
- **The `sqlite3` library version** that Python ships: `Connection.backup` needs 3.6.11 or newer, which every supported Python has; a distribution's own Python may differ.
- **Windows path rendering in the refusal messages** (1.2): they are plain ASCII with the path as Python prints it; confirm on cmd.exe.
- **The feel of the three verbs' output**: whether `Store OK: <path>` and the `Refused:` lines say enough, and whether exit 2 for "no store" is the right shape. Judge as you go.
- **Frontier's real answers** (section 3): every test uses a fake response.

## Reporting issues found

1. Note the section and step
2. Copy the exact command and its full output, stdout and stderr
3. Keep the scratch `store.db` (and any `.bak-*`) -- it is small and it is the evidence
4. File an issue referencing this checklist and #22

## Cleanup

Delete the scratch directories and unset the variables:
**cmd.exe** `rmdir /s /q "%ED_CONFIG_DIR%" & rmdir /s /q "%ED_JOURNAL%" & set ED_CONFIG_DIR= & set ED_JOURNAL= & set ED_NO_STORE=`
**PowerShell** `Remove-Item -Recurse -Force $env:ED_CONFIG_DIR, $env:ED_JOURNAL; Remove-Item Env:\ED_CONFIG_DIR, Env:\ED_JOURNAL; Remove-Item Env:\ED_NO_STORE -ErrorAction SilentlyContinue`
**POSIX** `rm -rf "$ED_CONFIG_DIR" "$ED_JOURNAL"; unset ED_CONFIG_DIR ED_JOURNAL ED_NO_STORE`

Your real `~/edapitool/` was never touched, except by section 3 if you ran it -- and that store is yours to keep.
