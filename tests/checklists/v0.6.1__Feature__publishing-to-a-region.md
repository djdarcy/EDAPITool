# Human Test Checklist: Publishing to a Region

**Target version:** v0.6.1
**Ships with commit:** TBD
**Companion automated tests:** 47 new tests across `tests/test_destination.py` (17), `tests/test_region_publishing.py` (24), `tests/test_baseline_freshness.py` (6). Suite went 431 → 478. Mutation: 11/11 killed on `google.exporter`.

## What this is

Until now the tool could only publish a grid that **owned an entire tab** — `MarketData`, `ShipCargo`, `FreighterData`. This release lets it publish into a **declared rectangle** of a tab that also holds hand-maintained content, so a settlement tracker can keep its own columns and have generated data appear beside them.

That makes clearing the dangerous part. A block that owns a whole tab is cleared by wiping the tab; a block that owns a rectangle must be cleared to that rectangle's own bounds, or the tail of a larger earlier write survives — and **a stale row renders identically to a fresh one**, so nobody can tell by looking. This checklist exists mostly to put a human's eyes on that.

Run it against a spreadsheet you own, on a **duplicated** tab.

## Prerequisites

1. **Python 3.10+**, this repo installed with the sheets extra: `pip install -e .[gsheets]`
2. **Google Sheets credentials** — either `~/.ed_gsheet_credentials.json` (OAuth client secrets) or a valid `~/.ed_gsheet_token.json`
3. **A spreadsheet you own.** Examples below use the public template `1WACbf6u81fLIWsJVXsxUqYyIGZ0OCckN-Qb1FBgHAy0`; substitute your own id — you cannot write to that one.
4. **A journal with at least one `ColonisationConstructionDepot` event.** Confirm with `edapitool construction --list`. If it reports no sites, you cannot run sections 1–4; sections 5 and 6 still apply.

### Make a scratch tab first — do not skip this

Every destructive step below points a region at a tab. **Duplicate any tab holding real work and aim at the copy.** In Google Sheets: right-click the tab → *Duplicate*. That is exactly what made this feature safe to validate during development.

```
Set SHEET to your spreadsheet id and TAB to your duplicated tab.
```

**cmd.exe**
```cmd
set SHEET=your-sheet-id-here
set TAB=Copy of Agri Lrg. (ex)
```

**PowerShell**
```powershell
$env:SHEET = "your-sheet-id-here"
$env:TAB   = "Copy of Agri Lrg. (ex)"
```

**POSIX**
```bash
export SHEET=your-sheet-id-here
export TAB="Copy of Agri Lrg. (ex)"
```

### Knowing your tab's real size — you will need it

A region cannot extend past the tab's grid (see HV.3). Find the tab's column count from the Sheets UI, or:

```
python -c "from APITool.google import GoogleSheetsExporter; b=GoogleSheetsExporter().open_spreadsheet('YOUR_SHEET_ID'); [print(w.title, w.row_count, 'x', w.col_count) for w in b.worksheets()]"
```

A 29-column tab ends at **AC**, not AD.

### Reset between sections

Nothing here writes outside the region you name, so resetting means clearing that region by hand in the Sheets UI (select the range → Delete → Values), or simply re-running a known-good publish.

## High-Value Verification (~5 minutes)

If you only have five minutes, run these six. If any fail, the work is broken.

### HV.1 — A shrinking block leaves nothing behind

Validates the single reason bounds are declared rather than derived.

- [ ] **Steps:**
  1. `edapitool construction --list` and note two sites with **different commodity counts**
  2. Publish the larger one:
     `edapitool construction --site "<BIGGER SITE>" --publish-to "%TAB%" --region R1:AC60 --sheet-id %SHEET%`
  3. Note the last row number the block reaches in the Sheets UI
  4. Publish the smaller one to the **same region**:
     `edapitool construction --site "<SMALLER SITE>" --publish-to "%TAB%" --region R1:AC60 --sheet-id %SHEET%`
- [ ] **Expected:** not one row of the first block survives. Scroll the whole reserve, R1 down to R60.
- [ ] **Why this matters:** if a row of the old block survives, it looks exactly like current data and no formula or person will ever flag it. This project already lost three releases to that shape in a different column.

### HV.2 — Nothing outside the reserve is touched

- [ ] **Steps:**
  1. Type `LEFT-SENTINEL` into **Q5** (one column left of the reserve) and `RIGHT-SENTINEL` into **AC5** if your reserve ends before it — otherwise pick any cell outside your declared range
  2. Note the value in the tab's **TOTAL row** (B4/C4/E4 on a settlement tab)
  3. Publish to `R1:AB60`
- [ ] **Expected:** both sentinels survive verbatim; the TOTAL row and every column B–L are byte-for-byte unchanged.
- [ ] **Why this matters:** the whole point of a region is that it shares a tab with someone's hand-entered work.

### HV.3 — A reserve bigger than the tab is refused, not clipped

**This defect was found on the live sheet and no offline test could see it.**

- [ ] **Steps:**
  1. Find your tab's column count (see Prerequisites). For a 29-column tab the last column is **AC**.
  2. Deliberately declare one column too far:
     `edapitool construction --publish-to "%TAB%" --region R1:AD60 --sheet-id %SHEET%`
- [ ] **Expected:** a refusal naming the offending column, the tab's column count, and the real last column — e.g. *"the reserve ends at column AD but the tab has 29 columns (through AC)"*. Exit code 1. **Nothing is written or cleared.**
- [ ] **Why this matters:** before this check, that command **succeeded**. Google Sheets silently clipped the clear to AC and reported success, so the reserve did not clear what it claimed to — the exact failure declared bounds exist to prevent.

### HV.4 — A grid bigger than its reserve is refused by name

- [ ] **Steps:** publish a site with more than 5 commodities into a reserve too small to hold it:
  `edapitool construction --publish-to "%TAB%" --region R1:Z8 --sheet-id %SHEET%`
- [ ] **Expected:** a refusal stating the grid's shape *and* the reserve's, e.g. *"the grid is 22 rows x 9 columns but the reserve is 8 x 9"*. Never a truncated block, never a silently widened one.
- [ ] **Why this matters:** silent truncation would drop commodities off the bottom of the list, and a shopping list missing an item is worse than no list.

### HV.5 — The three generated tabs are unchanged

- [ ] **Steps:** `edapitool ship --export ship-tab --sheet-id %SHEET%`
- [ ] **Expected:** `ShipCargo` is rewritten exactly as it was before this release — whole-tab clear, grid from A1. Any formula elsewhere in the workbook that reads `ShipCargo` still resolves to the same value.
- [ ] **Why this matters:** regions are new; the existing publishing path must not have moved underneath the workbook.

### HV.6 — A region needs an allowlist

- [ ] **Steps:** in a Python shell:
  ```python
  from APITool.google import GoogleSheetsExporter
  from APITool.sheets import Destination
  GoogleSheetsExporter().export_grid([["x"]], "any-sheet-id",
                                     Destination.region("SomeTab", "A1:B2"))
  ```
- [ ] **Expected:** `WriteRefused`, saying no region allowlist is configured. No network call is made.
- [ ] **Why this matters:** the default for a tab holding someone's work must be "not writable", and opting in must be deliberate.

## Section 1: Clearing (~10 min)

### 1.1 Publishing an empty region clears it entirely

- [ ] **Steps:** publish a site, then publish to the same region with a site that has no outstanding resources (a completed one, via `--all`), or clear the range by hand and re-publish
- [ ] **Expected:** where the tool publishes nothing, the reserve is empty — not left holding the last report.

### 1.2 Growing inside the reserve is free

- [ ] **Steps:** publish a small site, then a larger one, into the same generous reserve (`R1:AC60`)
- [ ] **Expected:** the larger block appears in full; nothing outside the reserve is disturbed. Growth within a declared reserve needs no re-declaration — which is what makes future extra columns safe.

### 1.3 Restart behaviour — the one the alternative design fails

- [ ] **Steps:**
  1. Publish a **large** site. Let the process exit completely.
  2. Start a **fresh** process and publish a **small** site to the same region.
- [ ] **Expected:** nothing from the first publish survives.
- [ ] **Why separately:** the rejected alternative (remember the last extent, clear only that) passes every other scenario in this document and fails only this one — measured at 471 orphaned cells. Since `serve` dies with its shell, a restart between publishes is ordinary.

### 1.4 The reserve is cleared before the write, not after

- [ ] **Check:** watch the Sheets UI during a publish, or publish a smaller grid over a larger one and confirm no interleaving of old and new rows at any point.

## Section 2: The published block (~5 min)

### 2.1 The metadata row identifies the site without context

- [ ] **Check row 1 of the block** carries: station name, star system, MarketID, a UTC timestamp, state (`active` / `complete` / `failed`), progress as a fraction, and the three totals.
- [ ] **Expected:** someone finding this block six months later can tell which site it describes without trusting the tab it sits on.
- [ ] **Judgement call:** is the row legible? Is the timestamp obviously UTC? Flag it if not.

### 2.2 Headers and data

- [ ] **Check row 2** reads `Symbol | Commodity | Required | Provided | Remaining | Payment`
- [ ] **Check row 3 onward**: one row per commodity, numbers as numbers (right-aligned, not text)
- [ ] **Cross-check one commodity against the game**: open the construction panel in Elite Dangerous and confirm Required/Provided match exactly for at least one item.

### 2.3 Progress reconciles

- [ ] **Check:** summed Provided ÷ summed Required equals the progress figure in row 1, to 4 decimal places.
- [ ] **Note:** this will *not* necessarily match a settlement tab's own percentage — the sheet may compute it differently (by trips, by cargo value). A discrepancy here is a sheet-formula question, not a tool bug.

## Section 3: Refusals and their wording (~5 min)

These are judgement tests. The code either refuses or it doesn't; what you are assessing is whether a person reading the message knows what to do next.

### 3.1 `--publish-to` without `--region`

- [ ] **Steps:** `edapitool construction --publish-to "%TAB%" --sheet-id %SHEET%`
- [ ] **Expected:** refused, explaining that the region is declared rather than inferred *because publishing clears it*.
- [ ] **Judgement:** does the explanation land, or does it read as bureaucracy?

### 3.2 `--publish-to` without a spreadsheet

- [ ] **Steps:** run with no `--sheet-id`, no `ED_SHEET_ID`, and no `sheet_id` in `~/.ed_capi_config.json`
- [ ] **Expected:** all three ways of supplying it are named.

### 3.3 A malformed region

- [ ] **Steps:** try `--region R1:AD` (open-ended) and `--region R:AD` (columns only)
- [ ] **Expected:** refused, saying a reserve must be a closed rectangle because an open-ended one cannot be cleared to its own extent.

### 3.4 A nonexistent tab

- [ ] **Steps:** `--publish-to "NoSuchTab"`
- [ ] **Expected:** note what happens. A region publish to a missing tab should fail clearly rather than silently creating one — creating a tab is a whole-tab act, and a region is by definition a guest on a tab that already exists. **If it creates the tab, file that.**

## Section 4: Windows rendering (~3 min)

### 4.1 Output is readable on a default console

- [ ] **Steps:** run a publish and a refusal in **cmd.exe**, then **PowerShell**, at default width
- [ ] **Expected:** no mojibake, no box-drawing artefacts, no lines wrapping mid-word into nonsense. Codepage 437/1252 is the default and the tool must not assume UTF-8.

### 4.2 A tab name with spaces and punctuation

- [ ] **Steps:** use a tab named like `Copy of Agri Lrg. (ex)` — spaces, a period, parentheses
- [ ] **Expected:** quoting works in all three shells; the name appears intact in both success and refusal messages.

## Section 5: The contract baseline (~5 min, no construction site needed)

`tests/one-offs/thinking/cargo-contract/baseline.py` snapshots what every cross-tab formula resolves to, so a reshape can be proved not to have changed meaning. It now refuses to compare against a capture from a different commit.

### 5.1 The staleness guard fires

- [ ] **Steps:**
  1. `python tests/one-offs/thinking/cargo-contract/baseline.py %SHEET% compare` — should report *"Baseline is current"* and pass
  2. Edit `baseline.json` and change one character of `meta.sha`
  3. Run `compare` again
- [ ] **Expected:** refused, naming both the captured commit and HEAD, exit code 2. **No network call is made** — the check runs before the spreadsheet is opened.
- [ ] **Reset:** `git checkout tests/one-offs/thinking/cargo-contract/baseline.json`

### 5.2 Capture records provenance

- [ ] **Steps:** `python tests/one-offs/thinking/cargo-contract/baseline.py %SHEET% capture`, then inspect the file

  **cmd.exe** `type tests\one-offs\thinking\cargo-contract\baseline.json | findstr meta`
  **PowerShell** `Get-Content tests/one-offs/thinking/cargo-contract/baseline.json | Select-String meta`
  **POSIX** `grep -A5 '"meta"' tests/one-offs/thinking/cargo-contract/baseline.json`
- [ ] **Expected:** a `meta` block with `format`, `sha`, `captured_at` and `cells`.

## Section 6: Layering (~2 min, no credentials needed)

### 6.1 The generic layer stays vendor-neutral

- [ ] **Steps:**

  **cmd.exe** `findstr /s /i "gspread google.oauth2" APITool\sheets\*.py`
  **PowerShell** `Select-String -Path APITool/sheets/*.py -Pattern "gspread|google\.oauth2"`
  **POSIX** `grep -rn "gspread\|google\.oauth2" APITool/sheets/`
- [ ] **Expected:** no matches. `APITool/sheets/` is the vendor-neutral toolkit; a second backend would reuse it unchanged.

### 6.2 `Destination` is a value

- [ ] **Steps:**
  ```python
  import json
  from APITool.sheets import Destination
  d = Destination.region("Any Tab", "R1:AC60")
  print(json.dumps(d.to_dict()))
  print(Destination.from_dict(json.loads(json.dumps(d.to_dict()))) == d)
  print(d.anchor, d.reserved_rows, d.reserved_cols, d.describe())
  ```
- [ ] **Expected:** round-trips to `True`; anchor `R1`; no network access anywhere in the above.

## What the automated tests DON'T cover

- **Real Google Sheets clipping.** HV.3 is the proof: a reserve running off the grid *succeeded* against the real API and was silently clipped. Every offline test passed. Mocks model what you expect the API to do, and that is precisely the blind spot.
- **API quota and rate limits.** Publishing in a tight loop, or alongside `serve`, may hit them. Nothing here simulates that.
- **Partial failure.** If the clear succeeds and the write then fails — dropped connection, revoked token — the region is left empty. No test constructs that.
- **Rendering and legibility.** Whether the metadata row reads well, whether numbers are right-aligned, whether the block is obviously machine-generated to a human scrolling past.
- **Message quality.** Every refusal is asserted to *fire*; none is asserted to be *helpful*. Section 3 is where that is judged.
- **Concurrent human edits.** Someone typing into the tab while a publish is in flight.
- **Cross-platform.** The suite runs on Windows here; POSIX console behaviour is unverified.

## Known gap

**`edapitool serve` does not publish construction regions.** The daemon keeps the three generated tabs current; a construction block is refreshed only when a person runs the command. So a region will go stale while the game is running and nothing will say so. That integration is the next unit — do not report it as a defect.

## Reporting issues found

1. Note the section and step number (e.g. HV.3, or 3.4)
2. Capture the exact command and its full output
3. Screenshot the region if the problem is visual
4. Open an issue referencing this checklist and v0.6.1
5. For anything where stale data survived a publish, say so in the title — that class is the most serious this feature has
