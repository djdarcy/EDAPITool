## Defects and observations

**D1 (defect, user-facing): a malformed `pipelines` value crashes `edapitool plugins` with a Python traceback.** `cli.py` line 1328 calls `settings.get_pipelines()` with no handler, and `get_pipelines` raises `ValueError` for a non-object entry (settings.py:351) and for non-list or non-string steps (settings.py:357). `plugins` is the command the refusal messages tell the user to run to diagnose, so it is the worst place to crash. `serve` handles the same error cleanly. Suggested fix: catch the `ValueError` in `cmd_plugins` and print it as a `REFUSED` line in the pipeline section, as the other refusals are.

**D2 (defect): `market` misreports the same malformed shape as "no destination plugin is configured".** The shape error is swallowed on the `market` path, so the user sees `comparison_skipped: no destination plugin is configured` (or the `--update-sheet needs a destination plugin` error) while two targets are configured. It should print the shape error the way `serve` does. Suggested fix: surface the `ValueError` in the market path's pipeline resolution as a "pipeline cannot run" refusal, same as the named-target refusals.

**O1 (observation): an empty `steps` list silently drops the Pipeline section from `plugins`**, with nothing printed to say the pipeline is empty. A one-line "Pipeline market: no steps" or a refusal would make it legible.

**O2 (observation): a `pipelines` entry for any name other than `market` is silently ignored.** Fine for 0.9.0 by design ("only the market pipeline runs") but a user who types `"cargo"` as the key sees nothing; 5.4's refusal only covers `reads`.

**O3 (observation, not a failure, per the dispatch note): a target named `market` shadowing a built-in was not probed for refusal;** the dispatch says 0.9.0 does not refuse it. Recorded for later.

**O4 (observation): the first `plugins` run in an empty config dir creates `store.db` alongside `config.json`** (seen in the scratch `cfg/` after `market`). Harmless; mentioned because Section 7 only says `config.json` is written.

**O5 (checklist wording): the checklist's Section 5 assumes the real totals target is named `totals-workbook`;** the scratch config used `test-workbook` and the sections behaved identically. No change needed.

No step reached Google. No step wrote the jsonl file (the only write steps were `--dry-run` or refused).
