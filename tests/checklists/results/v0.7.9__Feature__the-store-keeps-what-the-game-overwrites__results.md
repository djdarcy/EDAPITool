## Mismatches between checklist wording and observed behavior

### Mismatch #1 — HV.5 as sequenced never exercises the `age_seconds` comparison it describes

**Checklist text (HV.5):** *"The two JSON outputs are identical apart from `"age_seconds"` under `"market"` (the market's age against the wall clock, which moves between runs). Judge it by eye or save both to files and diff them."*

**Observed:** Running the sections in the order the checklist presents them (HV.1 -> HV.2 -> HV.3 -> HV.4 -> HV.5), `Market.json` is left in the "Dieterle Beacon" state by HV.3 and never reset before HV.5, while the journal's `Docked` event still names "Ryman Enterprise" (also never reset). HV.5's own prerequisite reference is "(prerequisite 2)" only, i.e. it resets `ED_CONFIG_DIR` but not `ED_JOURNAL`/`Market.json`. The result: **both** HV.5 `market` calls returned `"ok": false, "reason": "stale_market", "market": null` — there is no `market.age_seconds` field present in either output to compare, so the specific invariant the checklist describes ("identical apart from age_seconds") cannot actually be observed by following the written steps in order.

A supplementary check (fresh config dir + `Market.json` restored to the live Ryman fixture, otherwise identical to HV.5's steps) confirmed the invariant the checklist describes does hold in the tool: the two JSON bodies were byte-identical except for `age_seconds`, once the expected first-run "Wrote a starting configuration" line is excluded. So this is a **checklist sequencing/documentation gap**, not a functional defect — a human following the checklist step-by-step from a clean start will see two `null`-market JSON blobs that are trivially identical, not the described `age_seconds`-only difference, unless they think to re-copy the fixture before HV.5.

**Suggested checklist fix:** HV.5's steps should say "(prerequisites 2 and 3)" — i.e., re-copy `tests\fixtures\market_ryman_journal.json` to `Market.json` as well as resetting `ED_CONFIG_DIR` — so the market is live going into HV.5 and the described `age_seconds`-only diff is actually observable.

### Mismatch #2 — 2.2's advice text says "not found" for a file that is present but corrupt

**Checklist text (2.2):** *"`market` reports no market data (as 0.7.8 did for an unreadable file)."*

**Observed:** The actual advice string returned is `"No Market.json found. Dock and open the station's Commodity Market screen once so the game writes it."` The file was not missing — it was truncated to half its original byte length and still present on disk. The checklist's own claim ("reports no market data") is satisfied, and it explicitly attributes this to pre-existing 0.7.8 behavior rather than something 0.7.9 introduces, so this is **not** flagged as a regression — but the literal wording "No Market.json found" is inaccurate for the truncated-file case (it conflates "absent" with "present but unreadable"). Worth a UX cleanup in the tool's own advice string at some point (distinguishing "no file" from "unreadable file"), independent of this checklist.

### Prerequisite quoting note (not a tool defect)

The `q.py`-creation one-liner in Prerequisite 4 (a `python -c` command with a further-escaped embedded string) throws `SyntaxError: unterminated string literal` when run verbatim in PowerShell — it was evidently authored/tested against cmd.exe or bash quoting only. Worked around locally by writing the identical file content directly. A PowerShell-specific variant (e.g., a here-string) would spare future testers this trip-up.
