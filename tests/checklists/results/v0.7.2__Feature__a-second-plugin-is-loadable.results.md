## Extension findings (not checklist steps — probing beyond it, per dispatch instructions)

### Finding A — a plugin whose `layout()` raises crashes *every* command, including `--version`

**Reproduction:**

```python
# targets = {"r": {"kind": "gsheet", "plugin": "raises_layout"}}
# raises_layout/__init__.py:
KIND = "gsheet"
def layout(**overrides):
    raise RuntimeError("layout blew up")
def writes():
    return {}
```

```
edapitool --version
```

Result: an uncaught `RuntimeError: layout blew up`, full Python traceback to
stderr, no `Error: ...` message, process exits via an unhandled exception
rather than a clean nonzero return code.

**Cause:** `cli.py`'s `_destination_defaults()` (line ~1121) wraps only the
`discover()` call in `try/except Exception`; the following line,
`destination.module.layout()`, runs *unguarded*:

```python
def _destination_defaults():
    try:
        from .loader import discover
        destination = discover().first()
    except Exception:
        return _Defaults()
    if destination is None:
        return _Defaults()
    return _Defaults(destination.module.layout())   # <-- not covered
```

Because `main()` calls `_destination_defaults()` unconditionally before
parsing `argv` (needed to seed argparse's `--totals-tab`/`--need-header`
defaults), a broken `layout()` takes down every command, including
`--version` and `--help` — exactly the failure mode HV.4/HV.4b's
"a broken plugin is listed, not fatal" property is designed to prevent for
*import* failures, but not for a *load-time* exception raised from inside a
successfully-imported module's `layout()`. A `load()`-time `writes()` call
(`loader.py` line 372-373) is already guarded the same way `layout()` should
be — `declares()` is called inside the same `try/except Exception` that
isolates import failures — so `writes()` raising is caught and the plugin is
reported `BROKEN`, but `layout()` raising is not caught anywhere on this
path. Two functions with the same "the plugin declares itself" contract are
isolated inconsistently.

Not filed as a FAIL against a checklist step (no HV/1.x/2.x step exercises
this), reported as a finding per the dispatch instructions. Candidate fix:
wrap the `destination.module.layout()` call in `_destination_defaults()` in
the same `except Exception: return _Defaults()` the surrounding function
already has (or catch narrower and log). Diagnose-and-report only — no
source edit was made.

### Finding B — `ED_PLUGIN_DIR` pointing at a file (not a directory) is handled gracefully

**Reproduction:** `ED_PLUGIN_DIR` set to a plain file path; config has no
`targets`.

```
edapitool --version
edapitool market --help
```

Result: both run cleanly, exit 0, no crash, no error message. `loader._candidates()`
guards with `directory.is_dir()` before calling `.iterdir()`, so a file path
simply yields zero candidates — behaviorally identical to an empty or
nonexistent user plugin directory. This is *not* a defect; recorded as a
finding because the checklist doesn't cover it and the behavior is correct
by omission rather than by an explicit test. No action needed.
