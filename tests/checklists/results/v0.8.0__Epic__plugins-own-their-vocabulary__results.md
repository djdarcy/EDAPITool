## What mocks don't cover — findings from this run

1. **`--no-markers` refusal is generic, not a rename hint.** `edapitool market --no-markers` fails with argparse's stock `unrecognized arguments: --no-markers` rather than any tool-authored message pointing at the new `--no-glyph-markers` spelling. The checklist's own rationale is "an old spelling that silently did nothing would be worse than one that fails" — that bar is met (it fails loudly, exit 2) — but a person who typed the old flag from muscle memory gets no hint toward the correct new name, unlike every other refusal this run observed (`plugins enable`, `plugins hello count`, `plugins nosuch` all name what to do instead). This is the one refusal in the whole run that reads as a generic argparse error rather than a tool-authored one. Not a FAIL against the checklist's literal expectation, but worth a REVIEW: is this rename supposed to eventually get its own `--no-markers is now --no-glyph-markers` message, or is silence-to-argparse the intended design given `--no-markers` was never a public/stable name?
2. **Capitalization/prefix drift between dry-run and real-write output for the same line.** 1.1's dry-run prints `marked rows: [17]` under a `DRY RUN - would write:` header; 1.4's real write prints `Marked rows: [17]` with no such header, directly under `Wrote 0 ranges to 'Totals Tab'.`. A tester (or a user) diffing the two outputs to confirm "only what was planned changed" (which is literally what 1.4's own checklist step asks) has to mentally normalize a casing/prefix change that carries no semantic difference. Minor, cosmetic, but it is exactly the kind of thing a byte-diff-based golden test would not catch and a human reading side-by-side output would notice.
3. **"Wrote 0 ranges" alongside "Marked rows: [17]" reads as contradictory on first glance.** In the 1.4 real-write output, "0 ranges" written and "[17]" marked appear back-to-back with no connecting sentence explaining that row 17's marker cell was one of the 20 cells already left alone (that connection is only inferable by cross-referencing the very next line, `left alone (20 already held something): Totals Tab!L5:L24`, and doing the arithmetic that row 17 falls in `L5:L24`). A first-time reader could reasonably ask "then what got marked?" Suggest making the relationship between "marked" and "left alone" explicit in the message itself (e.g., "marked rows: [17] (all already held something, so 0 ranges written)").

None of the three are functional defects — every checklist-specified expectation was met byte-for-byte or better. All three are candidates for #28/#33 follow-up polish, per the checklist's own "Reporting issues found" instructions.
