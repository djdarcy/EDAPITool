# Human Test Checklist: a cell that already holds something is left alone

**Target version:** v0.7.6
**Ships with commit:** `v0.7.6 fix(sheets)!: a cell that already holds something is left alone (#25, #18)` — TBD until committed
**Companion automated tests:** 836 passing (from 777). New: `tests/test_marker_skip_occupied.py` (23), `tests/test_help_output.py` (24), `tests/test_generated_tabs.py` (9). Modified: `tests/test_sheets.py` (the write-allowlist rows, and one selector), `tests/test_supplier_registry.py` (worksheet reads are now counted by range, not by call).

## What this is

`market --update-sheet` used to rewrite the whole marker column every run. That was right while the tool *painted* glyphs there, and it became destructive the moment workbooks started computing that column themselves — twenty `LET` formulas in `Totals Tab!L5:L24` were destroyed by a single run on 2026-09-16, and the command reported success, because it had done exactly what it intended.

This release makes the tool leave alone any marker cell that already holds something. The automated tests prove the logic against fake worksheets; **no mock in this project has ever contained a formula, and no mock can tell you whether Google actually hands back formula text when asked.** That is what this document is for. It also covers the two smaller changes that ride with it: the wholesale-rewrite allow list is now derived from the tabs the tool generates, and the settlement plugin declares a narrower slice of the marker column.

Who runs it: anyone with a Google Sheet the tool can reach. **Section 4 is the one that matters, and it is the one that can destroy work if run carelessly — read its warning before starting.**

## Prerequisites

1. **Windows, macOS or Linux.** The commands below are given for `cmd.exe`, PowerShell and POSIX shells.
2. **This version installed from the working tree**, not from PyPI:

   ```
   python -m pip install -e .
   edapitool --version
   ```

   Expect a string starting with `0.7.6` (see HV.2 for the full format).

3. **A Google Sheet you can write to**, and credentials already working — if `edapitool market --update-sheet --dry-run` worked before this release, you are set.

   Sections 1-3 and 5 need no sheet, but they are not all identical in what they need:

   | Step | Needs |
   |---|---|
   | Most of sections 1, 2, 3 and 5 | nothing configured at all |
   | **5.3** (`--show-formula`) | **some destination plugin configured** — any plugin, and a placeholder sheet id is fine. It returns before any network call, but it refuses outright with no destination. Run `edapitool plugins describe settlement` for a starter block |
   | **5.4** | **no destination configured**, which is the point of the step — so run it before 5.3, or clear the config again after |
   | HV.4, 3.3, 5.2, all of section 4 | a real sheet, reachable |

   A clean-room runner (a fresh VM, a CI box, an agent) hits the 5.3 case; a maintainer on their own machine never does, because their settlement plugin is already configured.

4. **Console encoding.** The marker glyphs (`●` `◕` `◑` `◔` `○`) are not in Windows codepage 1252 or 437, and printing them on a raw console raises `UnicodeEncodeError`. Set this once per shell before any command that may print a glyph:

   **cmd.exe**
   ```cmd
   set PYTHONIOENCODING=utf-8
   ```

   **PowerShell**
   ```powershell
   $env:PYTHONIOENCODING = "utf-8"
   ```

   **POSIX**
   ```bash
   export PYTHONIOENCODING=utf-8
   ```

5. **A scratch directory for captures.**

   **cmd.exe**
   ```cmd
   set WORK=%TEMP%\edapitool-v076
   mkdir "%WORK%"
   ```

   **PowerShell**
   ```powershell
   $env:WORK = "$env:TEMP\edapitool-v076"
   New-Item -ItemType Directory -Force $env:WORK | Out-Null
   ```

   **POSIX**
   ```bash
   export WORK=/tmp/edapitool-v076
   mkdir -p "$WORK"
   ```

**Resetting between sections:** sections 1, 2, 3 and 5 write nothing anywhere and need no reset. Section 4 writes to a real spreadsheet; its own steps say how to restore.

## High-Value Verification (~5 minutes)

If you only have five minutes, run these six. They need no spreadsheet except HV.4.

### HV.1 — The flag exists and says what it does

Validates: `--force` is discoverable, and its help text warns rather than just naming itself.

- [ ] **Steps:**
  1. `edapitool market --help`
- [ ] **Expected:** a `--force` entry whose text says it overwrites marker cells that already hold something, why the default is not to, and that there is no undo.
- [ ] **Why this matters:** `--force` is the one flag here that can destroy work. If someone can find it without finding the warning, the warning does not exist.

### HV.2 — The version is what you think you are testing

- [ ] **Steps:**
  1. `edapitool --version`
- [ ] **Expected:** a string **starting with** `0.7.6`. The full output carries branch, build and commit too, e.g. `ED API Tool 0.7.6_main_42-20260921-9980cd3d` — that is this project's standard version format, not a fault. The trailing hash names the commit this build sits on, so before v0.7.6 is itself committed it still reads as the previous one.
- [ ] **Why this matters:** every result below is meaningless against the wrong build, and this has caught a stale editable install before.

### HV.3 — The derived allow list still names exactly three tabs

Validates: unit 2 changed how the list is produced, not what is in it.

- [ ] **Steps** (same in all shells):

  ```
  python -c "from APITool.google.exporter import GoogleSheetsExporter as E; print(sorted(E.WRITABLE_TABS))"
  ```

- [ ] **Expected:** `['FreighterData', 'MarketData', 'ShipCargo']`
- [ ] **Why this matters:** this list is what stands between `worksheet.clear()` and a tab holding someone's hand-entered work. If it grew, something is now clearable that was not. If it shrank, a legitimate export is about to be refused.

### HV.4 — A dry run says what it would leave alone

Validates: the whole feature, in read-only form, against a real sheet.

- [ ] **Steps:**
  1. `edapitool market --update-sheet --dry-run`
- [ ] **Expected:** the usual `DRY RUN - would write:` block, **and** — if your marker column holds anything — a line reading

   ```
     left alone (20 already held something): Totals Tab!L5:L24
     pass --force to overwrite them (there is no undo)
   ```

   with your own count and ranges. If your marker column is genuinely empty, no such line appears and the plan looks as it did in v0.7.5.
- [ ] **Why this matters:** this is the entire fix, visible before anything is written. A dry run that does not mention the skip is the same silent behaviour that made the original defect invisible.

### HV.5 — The TOTAL row is refused

Validates: unit 3, the narrowed declaration.

- [ ] **Steps** (same in all shells):

  ```
  python -c "from APITool.sheets import WriteGuard; from APITool.plugins.settlement.layout import SheetLayout; g=WriteGuard.build(SheetLayout().writes()); print({a: g.allows('Totals Tab', a) for a in ('C2','G2','L3','L4','L5','L5:L24','L3:L24')})"
  ```

- [ ] **Expected:** `True` for `C2`, `G2`, `L3`, `L5`, `L5:L24`; **`False` for `L4` and for `L3:L24`** (a block spanning the TOTAL row).
- [ ] **Why this matters:** every other cell in row 4 of that tab is a `=SUM(...)`. The old declaration would have waved a write there straight through.

### HV.6 — The suite is green at the stated count

- [ ] **Steps:**
  1. `python -m pytest -q`
- [ ] **Expected:** `836 passed`
- [ ] **Why this matters:** if the count differs from this document, this document is describing a different build.

## Section 1: The `--force` flag and the help output (~3 min, no sheet needed)

### 1.1 `--force` appears under `market` and nowhere else

- [ ] **Steps:**
  1. `edapitool market --help`
  2. `edapitool serve --help`
  3. `edapitool ship --help`
- [ ] **Expected:** `--force` present on `market`; absent from `serve` and `ship`.
- [ ] **Check:** it does not collide with, shadow, or get confused with `--dry-run` or `--no-markers`, which sit nearby.

### 1.2 The help text warns, not just names

- [ ] **Steps:**
  1. `edapitool market --help`
- [ ] **Expected:** the `--force` text mentions all three of: that marker cells already holding something are skipped **by default**; that many sheets hold formulas there; that there is **no undo**.
- [ ] **Judgement call for the runner:** would somebody skimming this list understand the risk before typing the flag? If not, say so — this is exactly the kind of thing only a person notices.

### 1.3 The help output is still readable at all

- [ ] **Steps:**
  1. `edapitool market --help` in a window about 80 columns wide.
- [ ] **Expected:** no truncation, no ragged wrapping mid-word.
- [ ] **Changed in this release:** `market`'s flags are now printed under five headings -- `finding the market`, `the spreadsheet`, `writing to it`, `the marker column`, `exporting data` -- each with a one-line description. `serve` gains three. No flag was renamed; the `marker` -> `glyph-marker` rename is still **#28**. Check the headings read sensibly and that nothing landed under the wrong one.

## Section 2: The derived allow list (~5 min, no sheet needed)

### 2.1 Every writable tab traces back to a function

- [ ] **Steps** (same in all shells):

  ```
  python -c "from APITool.generated import builders; [print(f'{t:<14} <- {b}') for b, t in sorted(builders().items())]"
  ```

- [ ] **Expected:** exactly three lines —

  ```
  FreighterData  <- APITool.google.exporter.carrier_grid
  MarketData     <- APITool.market.sheet_grid
  ShipCargo      <- APITool.ship.sheet_grid
  ```

- [ ] **Check:** a name in the allow list with no function behind it would mean the list is still an enumeration wearing a derivation's clothes.

### 2.2 The answer does not depend on what happened to be imported

This is the property that cannot be checked from inside the test suite, because by then everything has been imported.

- [ ] **Steps** (same in all shells — each is a fresh interpreter):

  ```
  python -c "from APITool.generated import generated_tabs; print(sorted(generated_tabs()))"
  python -c "from APITool.google.exporter import GoogleSheetsExporter as E; print(sorted(E.WRITABLE_TABS))"
  python -c "import APITool.market; from APITool.google.exporter import GoogleSheetsExporter as E; print(sorted(E.WRITABLE_TABS))"
  ```

- [ ] **Expected:** all three print `['FreighterData', 'MarketData', 'ShipCargo']`.
- [ ] **Why:** a caller who imports only the exporter must still get the full list. If the second line is short by `MarketData` or `ShipCargo`, a legitimate export is about to be refused with a confusing message.

### 2.3 "Permit nothing" means nothing

- [ ] **Steps** (same in all shells):

  ```
  python -c "from APITool.google.exporter import GoogleSheetsExporter as E; print(sorted(E(writable_tabs=[]).writable_tabs))"
  ```

- [ ] **Expected:** `[]`
- [ ] **Why this matters:** this is the strictest thing a caller can say. Before this release it was read as "not specified" and fell back to permitting every generated tab — a safety override that failed open on its safest setting.

### 2.4 A tab nobody generates is still refused

- [ ] **Steps** (same in all shells):

  ```
  python -c "from APITool.google.exporter import GoogleSheetsExporter as E; t=E.WRITABLE_TABS; print([x for x in ('Totals Tab','Settlements','Notes','Sheet1') if x in t])"
  ```

- [ ] **Expected:** `[]`
- [ ] **Check:** these are the tabs that hold people's own work.

## Section 4: The live run — READ THIS BOX FIRST (~15 min, needs your sheet)

> ### Warning
>
> This section writes to a real spreadsheet.
>
> **The defect this release fixes destroyed twenty formulas in one run**, on the maintainer's own workbook, in `Totals Tab!L5:L24`. The command reported success while doing it.
>
> - **Do not run step 4.4 (the real write) until step 4.2 has shown you a dry run you understand.**
> - **Do not use `--force` on a workbook whose marker column holds formulas** unless you have completed step 4.1 and can paste the formulas back. `--force` has no undo; remembering what a cell held is **#29**, and it is not built.
> - If in any doubt, stop after step 4.3. Steps 4.1 to 4.3 write nothing.

### 4.1 Snapshot the marker column BEFORE anything else

This is the step that makes the rest safe. Do not skip it.

- [ ] **Steps** (same in all shells — writes only to your scratch directory):

  **cmd.exe**
  ```cmd
  python -c "import sys,json;from APITool.google.exporter import GoogleSheetsExporter as E;w=E().worksheet(sys.argv[1],'Totals Tab');print(json.dumps(w.get_values('L1:L60',value_render_option='FORMULA'),indent=1))" YOUR_SHEET_ID > "%WORK%\L-before.json"
  type "%WORK%\L-before.json"
  ```

  **PowerShell**
  ```powershell
  python -c "import sys,json;from APITool.google.exporter import GoogleSheetsExporter as E;w=E().worksheet(sys.argv[1],'Totals Tab');print(json.dumps(w.get_values('L1:L60',value_render_option='FORMULA'),indent=1))" YOUR_SHEET_ID > "$env:WORK\L-before.json"
  Get-Content "$env:WORK\L-before.json"
  ```

  **POSIX**
  ```bash
  python -c "import sys,json;from APITool.google.exporter import GoogleSheetsExporter as E;w=E().worksheet(sys.argv[1],'Totals Tab');print(json.dumps(w.get_values('L1:L60',value_render_option='FORMULA'),indent=1))" YOUR_SHEET_ID > "$WORK/L-before.json"
  cat "$WORK/L-before.json"
  ```

- [ ] **Expected:** a JSON array of rows. If your column holds formulas, you will see `=IF(...)` text — **not** blank strings, and not glyphs. That is `value_render_option="FORMULA"` doing its job, and it is the same call the fix makes.
- [ ] **Check:** count the non-empty rows and write the number down. You will compare against it in 4.5.
- [ ] **If this step fails**, stop. Everything below assumes you can restore.

### 4.2 Dry run, and read the skip line

- [ ] **Steps:**
  1. `edapitool market --update-sheet --dry-run`
- [ ] **Expected:**
  - the `DRY RUN - would write:` block naming `Totals Tab!C2`, `Totals Tab!G2`, and marker ranges;
  - a `left alone (N already held something)` line whose **N matches the count you wrote down in 4.1**;
  - the follow-up line offering `--force`.
- [ ] **Check:** if every cell in `L5:L<last>` was occupied, the plan should contain **no** `L...` write at all — only `C2` and `G2`. That is correct: there is nothing free to fill.
- [ ] **Judgement call:** is the line readable? Does `L5:L24` read better than twenty separate cells would have? Say so either way.

### 4.3 Dry run with `--force`, still writing nothing

- [ ] **Steps:**
  1. `edapitool market --update-sheet --dry-run --force`
- [ ] **Expected:** the full `L5:L<last>` block back in the plan, and **no** `left alone` line — `--force` does not consult the column at all.
- [ ] **Check:** nothing has been written. Re-run 4.1's capture if you want to prove it; the file should be identical.

### 4.4 The real write — ONCE

- [ ] **Steps:**
  1. `edapitool market --update-sheet`
- [ ] **Expected:**
  - `Wrote N ranges to 'Totals Tab'.`
  - `Marked rows: ...`
  - **and the same `left alone` line the dry run showed.** The real path is the one that most needs to say what it did not touch; "Wrote 3 ranges" is precisely what the tool printed while destroying twenty formulas.
- [ ] **Do not run this twice** before completing 4.5.

### 4.5 Re-read the column and diff

- [ ] **Steps:** repeat 4.1's command, writing to `L-after.json`, then compare.

  **cmd.exe**
  ```cmd
  fc "%WORK%\L-before.json" "%WORK%\L-after.json"
  ```

  **PowerShell**
  ```powershell
  Compare-Object (Get-Content "$env:WORK\L-before.json") (Get-Content "$env:WORK\L-after.json")
  ```

  **POSIX**
  ```bash
  diff "$WORK/L-before.json" "$WORK/L-after.json"
  ```

- [ ] **Expected:** **no differences in any row that was non-empty before.** Rows that were empty may now hold a glyph or an empty string; that is the tool filling what it owns.
- [ ] **This is the acceptance criterion of #25.** If any formula changed, stop, restore from `L-before.json`, and report it with both files attached.

### 4.6 Open the sheet and look at it

- [ ] **Steps:** open `Totals Tab` in a browser. Click a cell in `L5:L24`.
- [ ] **Expected:** the formula bar shows your formula, unchanged. Background colours on those cells are unchanged too — a skipped cell is not painted either.
- [ ] **Why a human has to do this:** no assertion in this project can tell you whether the sheet still *looks* right.

### 4.7 A cell that the tool does own

- [ ] **Steps:**
  1. In the sheet, clear one marker cell by hand — pick a row for a commodity the current station sells.
  2. `edapitool market --update-sheet --dry-run`
- [ ] **Expected:** that one cell now appears in the would-write plan (as a single-cell range such as `Totals Tab!L17`, or inside a small block), and it is absent from the `left alone` list.
- [ ] **Check:** the plan did not degrade into one range per row for the whole column — contiguous free cells should still travel as one range.
- [ ] **Reset:** paste the formula back from `L-before.json`.

### 4.8 The known trade, seen once

Only meaningful on a workbook where the tool **paints** the column rather than computing it. Skip if yours holds formulas.

- [ ] **Steps:**
  1. Run `--update-sheet` while docked somewhere that sells a commodity you need; confirm a glyph appears in that row.
  2. Move to a station that does **not** sell it. Run `--update-sheet` again.
- [ ] **Expected:** the previous station's glyph **is still there**. This is the accepted trade, stated in `CHANGELOG.md` and in `docs/writing-your-own-formulas.md` rule 5: the tool cannot tell its own leftover from something you typed, so it leaves both. `--force` clears it; remembering what it wrote is **#29**.
- [ ] **This is a behaviour change to report on, not a bug to file.** Say whether it is tolerable in practice.

## Section 5: Failure and edge behaviour (~5 min, no sheet needed)

### 5.1 An unreadable column fails closed

- [ ] **Steps** (same in all shells):

  ```
  python -c "from APITool.sheets import WriteGuard; from APITool.sheets.writer import MarkerWriter; import types; L=types.SimpleNamespace(totals_tab='Totals Tab',marker_column='L',marker_header='H',header_row=3,first_data_row=5,system_cell='C2',station_cell='G2',marker_range=lambda n:f'L5:L{n}',marker_header_cell=lambda:'L3',writes=lambda:{'Totals Tab':['C2','G2','L3','L5:L']}); W=type('W',(),{'get_values':lambda s,*a,**k:(_ for _ in ()).throw(RuntimeError('API said no')),'batch_update':lambda s,*a,**k:None,'batch_format':lambda s,*a,**k:None})(); R=type('R',(),{'cell':lambda s,m,**k:'X','cell_note':lambda s,m,c:'','cell_format':lambda s,m,v:None})(); M=type('M',(),{'row':0}); ms=[type('m',(),{'row':r,'is_covered':False})() for r in (5,6,7)]; sn=types.SimpleNamespace(last_data_row=7); p=MarkerWriter(W,R,L,guard=WriteGuard.build(L.writes())).build_plan(ms,sn,'Sys','Stn'); print('writes:',[u['range'] for u in p.updates]); print('skipped:',p.skipped)"
  ```

- [ ] **Expected:** `writes: ['C2', 'G2']` and `skipped: ['L5', 'L6', 'L7']`.
- [ ] **Why:** not being able to find out what is in a column is not a reason to write over it. Note that the location cells still travel — those are not marker cells.

### 5.2 `--no-markers` still does what it always did

- [ ] **Steps:**
  1. `edapitool market --update-sheet --dry-run --no-markers`
- [ ] **Expected:** `C2` and `G2` only; no marker range, and **no** `left alone` line (nothing was considered, so nothing was skipped).
- [ ] **Check:** it does not report a dry run when you did not ask for one — that was a real defect once.

### 5.3 The glyph formula is unchanged

- [ ] **Steps:**
  1. `edapitool market --show-formula`
- [ ] **Expected:** the formula prints, with glyphs, without a `UnicodeEncodeError`. If it raises one, your shell is missing step 4 of the prerequisites — that is a console setting, not a defect in this release.
- [ ] **Check:** the formula text itself is byte-identical to v0.7.5's. Capture it and diff if you have the earlier output.

### 5.4 Nothing needs a spreadsheet that did not before

- [ ] **Steps:**
  1. `edapitool market --no-sheet`
  2. `edapitool market --export csv --output "%WORK%"` (cmd.exe) / `--output "$env:WORK"` (PowerShell) / `--output "$WORK"` (POSIX)
- [ ] **Expected:** both work with no destination configured at all, exactly as in v0.7.5.

## What the automated tests DON'T cover

- **Whether Google actually returns formula text** for `value_render_option="FORMULA"`. Every fake in this suite returns whatever the test planted. Section 4.1 is the only place this is ever really checked.
- **Whether a formula survived.** A mock cannot hold a formula, so it cannot lose one. Section 4.5 is the acceptance criterion of #25 and it cannot be automated here.
- **Cell background colour on a live sheet.** The plan is asserted; the rendered sheet is not.
- **How the skip line reads** at a real terminal width, with a real number of skipped cells, next to the rest of the output.
- **Google's own error shapes.** Section 5.1 raises a synthetic exception; a real quota error, a revoked token or a renamed tab may arrive differently.
- **Console encoding.** The glyphs are outside cp1252 and cp437; only a real Windows console shows you that.
- **Whether the accepted trade in 4.8 is actually tolerable.** That is a judgement, not an assertion.

## Reporting issues found

1. Note the section and step number (for example, "4.5").
2. Capture the exact command and its full output.
3. For anything in section 4, attach **both** `L-before.json` and `L-after.json`.
4. File an issue referencing this checklist by filename and naming the version (`v0.7.6`).
5. If a formula was lost, say so in the title — that is a regression of #25 and outranks everything else here.
