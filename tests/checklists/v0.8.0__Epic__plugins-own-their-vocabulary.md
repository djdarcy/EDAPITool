# Human Test Checklist: plugins own their vocabulary

**Target version:** 0.8.0 (a command-line break)
**Ships with commit:** TBD (pre-commit)
**Companion automated tests:** new in this release: `tests/test_plugin_flags.py` (22: flags registered only for enabled plugins, collisions and reserved names refused, the options envelope, two sheet plugins on one workbook), `tests/test_plugin_commands.py` (25: `plugins <name> <command>`, consent by import tripwire, reserved words), `tests/test_changelog_break.py` (9: the CHANGELOG names every word, rename and migration), `tests/test_goldens.py` (2: the fixture plan, pinned tab and new default); rewritten or extended: `tests/test_help_output.py` (30), `tests/test_plugin_docs.py` (8), `tests/test_stock_config.py` (13), `tests/test_config_regions.py` (22), `tests/test_plugins_verb.py` (10). Full suite: 998.

## What this is

0.8.0 moves every flag that means something to only one workbook out of the tool's core and into the plugin that owns it. The old `settlement` plugin becomes two, `totals` (the roll-up tab and its glyph markers) and `construction` (the construction blocks). Four glyph-marker flags are renamed (#28). `edapitool plugins <name> <command>` gives a plugin commands of its own (#33). This checklist verifies all of that by hand, and it starts with the one step an existing install cannot skip: moving a `settlement` target forward. About 25 minutes. Sections 0, 1 and 4 use your real configuration and real spreadsheet; every other section runs in scratch directories.

## Prerequisites

1. 0.8.0 installed editable (`pip install -e .` from the repo root). **An editable install runs whatever is in the working tree**, so if you are the maintainer, your `edapitool` is already on 0.8.0 the moment the tree is, whether or not you have migrated.
2. A copy of the spreadsheet exists (File > Make a copy, or version history). Section 1 writes nothing until its last, optional step; that step writes.
3. A long-running `serve` started before the upgrade keeps its old code in memory. Leave it running until Section 0 is done, then restart it in Section 4.
4. Sections 2, 3, 5 and 6 set `ED_CONFIG_DIR` (and Section 6 `ED_PLUGIN_DIR`) to scratch directories. With those set, nothing under `~/edapitool/` is read or written.

## High-Value Verification (~5 minutes)

### HV.1 — your own configuration still publishes

- [ ] **Steps:** do Section 0, then `edapitool plugins`.
- [ ] **Expected:** `Loaded 2:`, with `totals` serving your roll-up target and `construction` serving your construction target; no `NOT loaded` section.
- [ ] **Why this matters:** until this passes, every command you run publishes nothing to your workbook, silently apart from the `plugins` listing.

### HV.2 — the live plan has the same shape as before

- [ ] **Steps:** `edapitool market --update-sheet --dry-run --write-location`
- [ ] **Expected:** `DRY RUN - would write:`, then `Totals Tab!C2`, `Totals Tab!G2`, the glyph-marker rows, and (on a sheet whose L column holds formulas) `left alone (20 already held something): Totals Tab!L5:L24` and `pass --force to overwrite them`. Station and system names are wherever you are docked.
- [ ] **Why this matters:** it is the whole break seen from the sheet: same tab, same cells, same refusal to overwrite formulas.

### HV.3 — the renamed flags, and only those

- [ ] **Steps:** `edapitool market --no-glyph-markers --dry-run --update-sheet`, then `edapitool market --no-markers`
- [ ] **Expected:** the first plans no glyph-marker column; the second is refused, `unrecognized arguments: --no-markers`, exit 2.
- [ ] **Why this matters:** an old spelling that silently did nothing would be worse than one that fails.

### HV.4 — `plugins <name>`

- [ ] **Steps:** `edapitool plugins totals`, `edapitool plugins enable`
- [ ] **Expected:** `totals declares no commands.` (exit 0); `` `plugins enable` is reserved for a later version and does nothing yet.`` (exit 2).

### HV.5 — `serve` keeps both halves current

- [ ] **Steps:** Section 4.
- [ ] **Expected:** startup lists both targets; docking refreshes `MarketData` and your construction block.

## Section 0: move your own `settlement` target forward

Skip if your config never named `settlement`.

### 0.1 Back up the file

- [ ] **Steps** (pick your shell):

  **cmd.exe**
  ```cmd
  copy "%USERPROFILE%\edapitool\config.json" "%USERPROFILE%\edapitool\config.json.pre-0.8.0"
  ```
  **PowerShell**
  ```powershell
  Copy-Item "$HOME\edapitool\config.json" "$HOME\edapitool\config.json.pre-0.8.0"
  ```
  **POSIX**
  ```bash
  cp ~/edapitool/config.json ~/edapitool/config.json.pre-0.8.0
  ```
- [ ] **Expected:** the copy exists and is the same size.

### 0.2 Before the edit: what 0.8.0 makes of the old target

- [ ] **Steps:** `edapitool plugins`
- [ ] **Expected:** `NOT loaded 1:` / `settlement  not found by the scan` / `the tool is unaffected; other plugins loaded normally`, and `totals`, `construction`, `jsonl` under `Available but not loaded`.
- [ ] **Check:** the message is honest but does not name `totals`. Note whether you would have known what to do without the CHANGELOG. (A design question, not a defect: with one known install, no hint was added.)

### 0.3 The edit

Open `config.json` in an editor. In your existing target:

- [ ] change `"plugin": "settlement"` to `"plugin": "totals"`
- [ ] replace its `"config"` block with `"config": {"totals_tab": "Totals Tab"}` (use your tab's real name)
- [ ] add a second target beside it, keeping the same `"id"`:

  ```json
  "construction-workbook": {
    "kind": "gsheet",
    "plugin": "construction",
    "id": "THE SAME SHEET ID",
    "config": {"construction_regions": [ ...your existing list, unchanged... ]}
  }
  ```
- [ ] Any `#` comment lines above the first `{` stay where they are.

### 0.4 After the edit

- [ ] **Steps:** `edapitool plugins`
- [ ] **Expected:** `Loaded 2:`, each with `serves '<your target name>'`; no `CONFIG` complaint lines.
- [ ] **Steps:** `edapitool plugins describe construction`
- [ ] **Expected:** `writes     nothing as shipped` (regions are bound per config) and the starter block.

**Rollback:** copy `config.json.pre-0.8.0` back over `config.json` (the reverse of 0.1).

## Section 1: the live plan (dry run first)

### 1.1 Without the location cells

- [ ] **Steps:** `edapitool market --update-sheet --dry-run`
- [ ] **Expected:** no `C2`/`G2` lines (they have been opt-in since 0.7.7); glyph-marker rows as for your current station; formulas in the glyph-marker column reported as left alone.

### 1.2 With them

- [ ] **Steps:** `edapitool market --update-sheet --dry-run --write-location`
- [ ] **Expected:** compare with `tests/goldens/v0.7.6__market--update-sheet--dry-run.txt`. Same tab name, same two location cells, the same `left alone ... L5:L24` line if your column still holds formulas. Different station names are expected.

### 1.3 The tab name comes from your config, not the default

- [ ] **Steps:** temporarily delete `"totals_tab"` from your totals target's config, run 1.1 again, then put it back.
- [ ] **Expected:** without it the plan names `Totals!...`, the plugin's new default, and probably fails to find the tab; with it, `Totals Tab!...` again.

### 1.4 (optional) the real write

- [ ] **Steps:** `edapitool market --update-sheet`
- [ ] **Expected:** the cells 1.1 planned, and nothing else, change. Check version history.

## Section 2: the help pages

Set a scratch config directory first, so the plugins are enabled by the stock file:

  **cmd.exe**
  ```cmd
  set ED_CONFIG_DIR=%TEMP%\edapitool-080
  if exist "%ED_CONFIG_DIR%" rmdir /s /q "%ED_CONFIG_DIR%"
  edapitool plugins
  ```
  **PowerShell**
  ```powershell
  $env:ED_CONFIG_DIR = "$env:TEMP\edapitool-080"
  if (Test-Path $env:ED_CONFIG_DIR) { Remove-Item -Recurse -Force $env:ED_CONFIG_DIR }
  edapitool plugins
  ```
  **POSIX**
  ```bash
  export ED_CONFIG_DIR=/tmp/edapitool-080
  rm -rf "$ED_CONFIG_DIR"
  edapitool plugins
  ```

### 2.1 `market --help`

- [ ] **Expected:** `options:` holds only `-h`; then `signing in to Frontier:`, `finding the market:`, `the spreadsheet:`, `writing to it:`, `exporting data:`, and last `the totals plugin:`.
- [ ] **Check:** the totals group holds `--glyph-marker-column`, `--empty-glyph-marker`, `--write-glyph-marker-header`, `--no-glyph-markers`, `--force`, `--write-location` (its help ends `DEPRECATED: may be removed in a release after 2027-01-01`), and the rest. `writing to it:` holds only `--update-sheet` and `--dry-run`.
- [ ] **Check:** the page reads well at your normal terminal width; the long `--force` and `--write-location` paragraphs wrap cleanly.

### 2.2 `serve --help`

- [ ] **Expected:** `the totals plugin:` (`--totals-tab`, `--write-location`) and `the construction plugin:` (`--construction-region TAB!RANGE[=SITE]`), each under its own name.

### 2.3 Without the plugins

- [ ] **Steps:** point `ED_CONFIG_DIR` at a second empty scratch directory and set `ED_NO_STOCK_CONFIG=1` (cmd `set ED_NO_STOCK_CONFIG=1`, PowerShell `$env:ED_NO_STOCK_CONFIG = "1"`, POSIX `export ED_NO_STOCK_CONFIG=1`), then `edapitool market --help`.
- [ ] **Expected:** no `the totals plugin:` group; `--force` does not appear anywhere on the page. Unset `ED_NO_STOCK_CONFIG` afterwards.

## Section 3: the `plugins` verb

With the Section 2 scratch directory:

- [ ] `edapitool plugins`, `edapitool plugins list`, `edapitool plugins LIST`: the same listing, three times.
- [ ] `edapitool plugins describe totals`: kind, `supplies requirements`, `subscribes markers`, the starter block `{"totals_tab": "Totals Tab"}`.
- [ ] `edapitool plugins describe`: `needs a plugin name`, the found plugins, exit 2.
- [ ] `edapitool plugins help`: the verb's own help, mentioning `plugins <name> <command>`.
- [ ] `edapitool plugins totals` and `edapitool plugins totals --help`: `totals declares no commands.`
- [ ] `edapitool plugins enable`, `plugins Install`: reserved for a later version, exit 2.
- [ ] `edapitool plugins nosuch`: `no plugin named 'nosuch'` and the list of what is found, exit 1.
- [ ] **Check:** exit codes (cmd `echo %ERRORLEVEL%`, PowerShell `$LASTEXITCODE`, POSIX `echo $?`).

## Section 4: `serve` on the migrated configuration

Unset `ED_CONFIG_DIR` first (cmd `set ED_CONFIG_DIR=`, PowerShell `Remove-Item Env:\ED_CONFIG_DIR`, POSIX `unset ED_CONFIG_DIR`).

- [ ] Stop the old `serve` (Ctrl+C in its window) and start `edapitool serve`.
- [ ] **Expected at startup:** every target listed by name, including the construction region(s) from your `construction` target.
- [ ] Dock somewhere, or deliver to a site: `MarketData` refreshes, and the construction block for that site refreshes.
- [ ] `edapitool serve --construction-region "Tab!R1:AC60"` still works as an override (the flag wins outright over the file).

## Section 5: a fresh install writes two targets

- [ ] **Steps:** a new empty scratch `ED_CONFIG_DIR` (as in Section 2), then `edapitool plugins`.
- [ ] **Expected:** first line `Wrote a starting configuration to ...`, then `Loaded 2:` (`totals` serves `totals-workbook`, `construction` serves `construction-workbook`).
- [ ] **Check:** view `config.json` in that directory (cmd `type`, PowerShell `Get-Content`, POSIX `cat`). Two targets on the template id; the totals block names the template's tab; the header comment describes both targets and does not itself spell out a tab name.

## Section 6: a plugin with a command of its own

- [ ] **Steps:** make a scratch plugin directory and point `ED_PLUGIN_DIR` at it (cmd `set ED_PLUGIN_DIR=%TEMP%\edapitool-plugins`, PowerShell `$env:ED_PLUGIN_DIR = "$env:TEMP\edapitool-plugins"`, POSIX `export ED_PLUGIN_DIR=/tmp/edapitool-plugins`). Inside it create `hello/__init__.py`:

  ```python
  from APITool.registry import Command

  KIND = "jsonl"

  def _greet(tail, target):
      print("hello", tail, "target:", None if target is None else target.name)
      return 0

  def _count(tail, target):
      print("counting for", target.name)
      return 0

  def commands():
      return {"greet": Command("greet", _greet, "say hello", safe_unconfigured=True),
              "count": Command("count", _count, "needs a target")}
  ```
- [ ] `edapitool plugins hello`: both commands listed; `greet` marked `(runs without a target)`; the header says it is not enabled by any target.
- [ ] `edapitool plugins hello greet --loud x`: `hello ['--loud', 'x'] target: None`, exit 0.
- [ ] `edapitool plugins hello count`: refused, naming `hello` and the `"plugin": "hello"` line to add, exit 1; `counting for` never printed.
- [ ] Rename the directory to `List` and run `edapitool plugins`: `List` reported as a RESERVED name (on Windows the directory name is case-insensitive, and the rule is too).

## What the automated tests DON'T cover

- **Your live sheet.** The fixture golden proves the plan is byte-identical on a planted grid; only Section 1 proves it against real formulas, where a cell that *displays* nothing is often a live formula.
- **The editable-install surprise.** No test can see that your installed tool changed under you the moment the tree did, or that your config stopped selecting a destination. Section 0 exists for this.
- **A long-running daemon across an upgrade.** It keeps its old code until restarted; whether a restart on the migrated config picks up both targets is Section 4.
- **Windows' case-insensitive directories.** The tests plant `List` and `INSTALL` on whatever filesystem runs them; Section 6's last step checks the real one.
- **Whether the refusal messages help.** Tests check the words are present, not that a person reading them knows what to do next (0.2's check, and every refusal in Sections 3 and 6).

## Reporting issues found

1. Note the section and step.
2. Capture the exact command and output, and the exit code.
3. For Section 1, note the station and whether the sheet was changed (version history).
4. File against #28 or #33 as fits, naming 0.8.0 and this checklist.
