# Human Test Checklist: the store beside the pipelines

**Target version:** 0.10.5
**Ships with commit:** the v0.10.5 docs commit, over the five store units (v0.10.3) and `construction --delta` (v0.10.4)
**Companion automated tests:** `tests/test_store_history.py` (9), `tests/test_store_ingest.py` (16), `tests/test_store_projections.py` (17), `tests/test_store_rebuild.py` (3), `tests/test_store_liveness.py` (10), `tests/test_store_export.py` (7), `tests/test_store_schema.py` (4), `tests/test_construction_delta.py` (9), with the sheet writer faked throughout. Suite: 1,241.

## What this is

The store now keeps the journal as well as the side files, indexes what the colonisation, BGS and trade questions need, answers a step through one supplier, and travels as JSON. The automated tests prove every criterion on fixture journals. This checklist covers what they cannot: the real journal's size and shape, the timings a person waits through, the verbs' output read by a person, a real sheet receiving the block's two new columns, and the migration of a store made by an earlier version. About 25 minutes. **Every step runs against a scratch store first; your own store is touched only in section 5, after a backup.**

## Prerequisites

1. EDAPITool installed from this tree; `edapitool --version` begins `0.10.5`.
2. The game need not be running; the journal directory must exist (`%USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous`, or `ED_JOURNAL_DIR`).
3. A scratch config directory, so your own store is untouched until section 5:

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\edstore
   set ED_CONFIG_DIR=%TEMP%\edstore
   ```

   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\edstore" | Out-Null
   $env:ED_CONFIG_DIR = "$env:TEMP\edstore"
   ```

4. For section 4 only: a copy of your workbook (Drive, **Make a copy**), its id, and the two Google credential files copied into the scratch directory (copy only; never open or print them).

## 1. The ingest (~5 minutes)

### 1.1 -- The first pass reads everything

- [ ] `edapitool store ingest`
- [ ] **Expected:** three lines: `Ingested <journal dir> into <scratch>\store.db`, then `N file(s) read, 0 unchanged, P not yet readable`, then `K event(s) kept, K' new, B bytes advanced`. N is your journal file count (`JournalAlpha` and `JournalBeta` files are not counted; the tool has never read them); P is 0 or 1 (a file the game created and has not written yet). Record N, K and the wall time. **Measured 2026-10-09 on a 636-file, 287 MB journal: 7.0 s with every derived table filled, 31,251 events kept.**

### 1.2 -- The second pass reads nothing

- [ ] `edapitool store ingest` again.
- [ ] **Expected:** `N file(s) read, N unchanged`, `0 event(s) kept, 0 new, 0 bytes advanced`, well under a second.

### 1.3 -- The sources are listed, present

- [ ] `edapitool store sources`
- [ ] **Expected:** `N source(s)`, one line per journal file: id, `journal`, `present`, your machine's name, how many events it gave, the path. A file with 0 events is listed too.

### 1.4 -- Verify re-checks them against the world

- [ ] `edapitool store verify`
- [ ] **Expected:** `Store OK: <path>` then `sources: N present, 0 absent, 0 retired, 0 on other machines`. Under two seconds.

## 2. The questions (~5 minutes)

### 2.1 -- A site's delta, from the command the criterion names

- [ ] `edapitool construction --list --all --scan-files` and pick a completed or well-advanced site's market id.
- [ ] `edapitool construction --delta --site <MARKETID> --scan-files`
- [ ] **Expected:** `Delivered at <name> (<id>) since the store's first reading of it:`, the two readings' stamps, a table of commodities with `delivered`, `yours`, `by others`, and a total line. A site you never contributed to shows `0 t yours`. **Measured 2026-10-09: site 3957057282, 269,924 t delivered, 0 t yours, 269,924 t by others -- #22 criterion 19's number.**
- [ ] `edapitool construction --delta --json --site <MARKETID> --scan-files | more`
- [ ] **Expected:** the site's JSON with a `"delta"` object carrying `since`, `until`, `resources`, `delivered`, `own`, `by_others`, `why`.

### 2.2 -- A moment you name

- [ ] `edapitool construction --delta <a stamp between the two readings, e.g. 2026-01-01T00:00:00Z> --site <MARKETID> --scan-files`
- [ ] **Expected:** `since 2026-01-01T00:00:00Z:` and `from the reading of <the latest reading at or before it>`; the numbers smaller than 2.1's or equal when no reading precedes the stamp.

### 2.3 -- Without a store, the command says what to run

- [ ] In a second shell with `ED_CONFIG_DIR` pointed at an empty directory: `edapitool construction --delta --site <MARKETID> --scan-files`
- [ ] **Expected:** `Error: no store yet: run `edapitool store ingest` first, then ask again`, exit 1, and no `store.db` created there (a first run in a new directory writes the stock `config.json`, as every command does; that is not the store).

## 3. Rebuild, export, import (~5 minutes)

### 3.1 -- Rebuild reproduces the derived tables

- [ ] `edapitool store rebuild`
- [ ] **Expected:** `Rebuilt market_snapshot, market_item, system, station, faction_presence, conflict, construction_reading, construction_contribution, construction_delta, trade from the primary tables.` A few seconds. Then 2.1 again gives the same numbers.

### 3.2 -- Export, import into an empty store, export again

- [ ] `edapitool store export %TEMP%\edstore\a.json`
- [ ] **Expected:** `Exported N source(s), K' observation(s), 0 write(s) to ...a.json`. The file is readable JSON; open it and find a `"payload"` that is a journal line.
- [ ] `set ED_CONFIG_DIR=%TEMP%\edstore2` (make the directory first), then `edapitool store import %TEMP%\edstore\a.json`
- [ ] **Expected:** `Imported ... into an empty store, ids kept`, `N new source(s), 0 already known; K' new observation(s), 0 already kept`. A few seconds (the derived tables are rebuilt).
- [ ] `edapitool store export %TEMP%\edstore\b.json`, then `fc /b %TEMP%\edstore\a.json %TEMP%\edstore\b.json`
- [ ] **Expected:** `FC: no differences encountered`. **Measured 2026-10-09: 46 MB document, export 0.7 s, import 2.5 s, byte-identical.**
- [ ] `edapitool store import %TEMP%\edstore\a.json` again, in `edstore2`.
- [ ] **Expected:** `merged by source and content`, `0 new source(s), N already known; 0 new observation(s), K' already kept`.
- [ ] `set ED_CONFIG_DIR=%TEMP%\edstore` to return to the first scratch store.

### 3.3 -- Retire, and the backup set

- [ ] `edapitool store retire 1`
- [ ] **Expected:** `Retired source 1 (journal on <machine>, was present): <path>` and the line about its observations staying.
- [ ] `edapitool store backup`
- [ ] **Expected:** `Backed up to ...store.db.bak-<stamp>` and `backup set: E observation(s) whose source is absent or retired`, where E is source 1's event count from 1.3.
- [ ] `edapitool store verify`
- [ ] **Expected:** `N-1 present, 0 absent, 1 retired`.

## 4. The block's two columns on a real sheet (~5 minutes; needs the workbook copy)

- [ ] Choose a tab of the copy with free columns and reserve nine of them for sixty rows, e.g. `R61:Z120`. Dry run first:
  `edapitool construction --publish-to "<TAB>" --region R61:Z120 --sheet-id <COPY_ID> --site <MARKETID> --scan-files --dry-run`
- [ ] **Expected:** `Would publish ... (dry run; nothing written)`.
- [ ] The same without `--dry-run`.
- [ ] **Expected:** `Published N commodities to <TAB>!R61:Z120`. On the sheet: row 61 the metadata header, row 62 its values, row 64 the headers ending `Payment`, `Delivered since last publish`, `By others`, and from row 65 one row per commodity with the last two columns filled (since this is the first publish, they count from the store's first reading of the site).
- [ ] Run the same publish again.
- [ ] **Expected:** `Published` again, and the last two columns now read `0` for every commodity: nothing was delivered between the two publishes.
- [ ] Try a region narrower than nine columns: `--region R61:X120`.
- [ ] **Expected:** `Error: Refusing to write <TAB>!R61:X120: the grid is N rows x 9 columns but the reserve is 60 x 7. Widen the declared region rather than spilling out of it.`, exit 1, nothing written.

## 5. Your own store (~3 minutes)

- [ ] `set ED_CONFIG_DIR=` (unset it), then `edapitool store backup`.
- [ ] **Expected:** a copy beside your real `store.db`, and a backup set of 0 if nothing was ever retired. If your store was made before 0.10.3 the open migrated it first; `edapitool store verify` says `Store OK`.
- [ ] `edapitool store ingest`
- [ ] **Expected:** as 1.1, into your own store. From here `serve` primes from the store's position and keeps it current as you play, and your construction regions carry the two columns.

## What mocks don't cover

- The real journal's size: 1.1's timing and count, and whether any file is `not yet readable`.
- The verbs' lines read by a person: whether `sources` is scannable at six hundred rows.
- A real sheet receiving a nine-wide block where a seven-wide one used to be published (the market grid is narrower).
- A store made by 0.7.9 through 0.10.2 migrating on open (5).
- Old journal shapes: a `SystemFaction` written as a bare string, pre-2019 files, were met in the maintainer's journal; another journal may hold a shape the projector has not seen, which is reported once and leaves the raw row kept -- note any such line in the results.

## Cleanup

- `rmdir /s /q %TEMP%\edstore %TEMP%\edstore2` -- the scratch stores, the exports, and (section 4) the credential copies. Nothing else was written outside the workbook copy.
