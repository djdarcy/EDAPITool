# Human Test Checklist: sequencing from the command line

**Target version:** 0.11.0
**Ships with commit:** the v0.11.0 docs commit, over `c0d98de` (the regions plugin retired) and `a4f6833` (cargo and carrier pipelines)
**Companion automated tests:** `tests/test_steps.py` (20), `tests/test_stages.py` (6), `tests/test_pipeline_verb.py` (11), `tests/test_pipeline_kinds.py` (3), `tests/test_publish_region.py` (11), `tests/test_regions.py` (5), with the sheet writer and the daemon builder faked throughout. Suite: 1,164.

## What this is

`edapitool pipeline` runs the stages `serve` keeps current, plugin steps and plugin commands once, in the order you type. The automated tests prove the grammar, the order, the refusals and the stop-at-first-failure against fakes. This checklist covers what they cannot: the printed plan read by a person, a real Google Sheet receiving the runs, the retired plugin's refusal read from a real file, and the one-edit migration of a configuration that still names it. About 20 minutes. **Every live write runs on a copy of your workbook, never the original.**

## Prerequisites

1. EDAPITool installed from this tree; `edapitool --version` begins `0.11.0`.
2. **A copy of your workbook.** In Google Drive, right-click the workbook, **Make a copy**, and note the copy's id from its URL. Every live step below names that copy.
3. A scratch config directory, so your real configuration is untouched. `ED_CONFIG_DIR` moves the config and the credential lookup together, so copy the two Google credential files in; copy them only, never open or print them.

   **cmd.exe**:
   ```cmd
   mkdir %TEMP%\edseq
   copy "%USERPROFILE%\edapitool\gsheet_credentials.json" %TEMP%\edseq\
   copy "%USERPROFILE%\edapitool\gsheet_token.json" %TEMP%\edseq\
   set ED_CONFIG_DIR=%TEMP%\edseq
   ```

   **PowerShell**:
   ```powershell
   New-Item -ItemType Directory -Force "$env:TEMP\edseq" | Out-Null
   Copy-Item "$env:USERPROFILE\edapitool\gsheet_credentials.json", "$env:USERPROFILE\edapitool\gsheet_token.json" "$env:TEMP\edseq\"
   $env:ED_CONFIG_DIR = "$env:TEMP\edseq"
   ```

4. Write `%TEMP%\edseq\config.json` (or `$env:TEMP\edseq\config.json`) with the copy's id in both targets, a tab name of yours in the region, and a file target:

   ```json
   {
     "targets": {
       "totals-workbook": {"kind": "gsheet", "plugin": "totals", "id": "COPY_ID",
                           "config": {"totals_tab": "Totals Tab"}},
       "regions-workbook": {"kind": "gsheet", "id": "COPY_ID",
                            "regions": [{"region": "Hauling!H1:N200", "data": "market"}]},
       "market-log": {"kind": "jsonl", "plugin": "jsonl", "path": "market.jsonl", "config": {}}
     }
   }
   ```

   The game need not be running for anything below; with no current market the market pipeline publishes its "no current market" grid, which is the right answer.

## High-Value Verification (~5 minutes)

### HV.1 -- The verb explains itself

- [ ] `edapitool pipeline --help` exits 0.
- [ ] **Expected:** the description names all three forms -- a BUILT-IN pipeline (`market`, `cargo`, `carrier`, `regions`), a TARGET's name, and a plugin COMMAND `<plugin>:<command>[=params]` -- and says the sequence is printed before anything runs and the configuration is re-read between runs.

### HV.2 -- The maintainer's example, typed, and nothing done

- [ ] `edapitool pipeline regions totals-workbook --dry-run`
- [ ] **Expected:** `Sequence (2 runs):` then `1. regions -- every region bound ...` then `2. totals-workbook -- the market pipeline with that step only, then MarketData`, then `(dry run; nothing read or written)`. Exit 0. Nothing in the copy changed.

### HV.3 -- A bad token runs nothing

- [ ] `edapitool pipeline regions nothere totals-workbook`
- [ ] **Expected:** exit 1; `Error: the sequence cannot run:`; a line naming `'nothere'` as not a configured target, and naming the built-in stages and the plugin-command form; no `Run 1` line. Nothing in the copy changed.

### HV.4 -- A configuration still naming the retired plugin is refused with the move

- [ ] Edit the scratch config: change the `regions-workbook` target to the old shape -- add `"plugin": "regions"` and move the list to `"config": {"bindings": [...]}`.
- [ ] `edapitool plugins`
- [ ] **Expected:** exit 1; `Error: targets['regions-workbook'] names the plugin "regions", which retired in 0.11.0 ...` with the sentence to move the entries to a `"regions"` list on the target and drop `"plugin"`; a second line `(from <the scratch config's path>)`.
- [ ] Make the one edit the message describes (the before/after is in `docs/configuration.md`, "A target that names the `regions` plugin"). `edapitool plugins` now exits 0 and lists `totals` and `jsonl` as loaded, with no `regions` plugin anywhere in the listing.

### HV.5 -- A real sequence on the copy

- [ ] `edapitool pipeline market regions --sheet-id COPY_ID`
- [ ] **Expected:** the two-run plan, then `Run 1: market` with `MarketData <- N rows` (or `unchanged`), then `Run 2: regions` with `Hauling!H1:N200 <- N rows (MarketData)` (or `waiting for the first market read` if the region ran before the tab in a previous session -- it will not here, because run 1 just built the grid). Exit 0. Open the copy: `MarketData` and `Hauling!H1:N200` hold the same grid.

## Section 1: the plan, read by a person

### 1.1 Every built-in's line says what it reads and writes

- [ ] `edapitool pipeline market cargo carrier regions --dry-run`
- [ ] **Expected:** four lines, in that order; `market` names its steps (`totals-workbook -> market-log (derived from the enabled targets)`) and `MarketData`; `cargo` says `no plugin steps, then ShipCargo`; `carrier` says it needs a Frontier login; `regions` names the configuration or the flag.

### 1.2 Consecutive targets share one reading

- [ ] `edapitool pipeline totals-workbook market-log --dry-run`
- [ ] **Expected:** ONE run: `1. totals-workbook -> market-log -- the market pipeline with those steps only, then MarketData`.

### 1.3 A command's parameters are shown as the plugin will receive them

- [ ] Add a settlement target: `"settlements": {"kind": "gsheet", "plugin": "settlement", "id": "COPY_ID", "config": {}}`.
- [ ] `edapitool pipeline "settlement:new=--type \"industrial large\" --name \"Ind. Lrg. 2\" --dry-run" --dry-run`
- [ ] **Expected:** `1. settlement:new=... -- the settlement plugin's `new` command with: --type industrial large --name Ind. Lrg. 2 --dry-run; a non-zero exit stops the sequence` and nothing run. (The quoted value with a space is one word in the shown parameters: the POSIX split.)

## Section 2: refusals and the stop

### 2.1 A command the plugin does not offer

- [ ] `edapitool pipeline settlement:old --dry-run`
- [ ] **Expected:** exit 1; `plugin 'settlement' offers no command 'old' (it offers: new)`.

### 2.2 A failing command stops the sequence

- [ ] `edapitool pipeline "settlement:new=--type nope --name X" regions --sheet-id COPY_ID`
- [ ] **Expected:** `Run 1: settlement:new=...`, the plugin's own error naming the 18 known types, then `Stopped at run 1 of 2 (exit 1); nothing after it ran.` Exit 1. No `Run 2` line; nothing in the copy changed.

### 2.3 A built-in listed inside a recipe is refused by name

- [ ] Add to the config: `"pipelines": {"market": {"reads": "market", "steps": ["totals-workbook", "cargo"]}}`.
- [ ] `edapitool plugins`
- [ ] **Expected:** a `REFUSED` line: `pipeline 'market' lists the built-in stage 'cargo', which cannot run inside a refresh in this build; only targets' plugin steps can`. Remove the `pipelines` key afterwards.

## Section 3: regions, live, on the copy

### 3.1 A one-off region write from a data command

- [ ] `edapitool ship --publish-to Hauling --region P1:U40 --sheet-id COPY_ID --dry-run`
- [ ] **Expected:** `Would publish N rows (ShipCargo) to Hauling!P1:U40 (dry run; nothing written)`; the copy unchanged.
- [ ] Without `--dry-run`: `region: Published N rows (ShipCargo) to Hauling!P1:U40`; the copy's `Hauling!P1:U40` holds the ShipCargo grid and nothing outside it moved.

### 3.2 A region laid over a declared range is refused at load

- [ ] Add a region over the roll-up tab: `{"region": "Totals Tab!L3:L10", "data": "market"}` in `regions-workbook`'s list.
- [ ] `edapitool plugins`
- [ ] **Expected:** a conflict line naming `totals` and `regions-workbook` over `Totals Tab`. Remove the entry afterwards.

### 3.3 `serve --once` on the copy

- [ ] `edapitool serve --once --sheet-id COPY_ID`
- [ ] **Expected:** `Pipeline market: totals-workbook -> market-log (derived from the enabled targets)`, then one line per target: `MarketData`, `ShipCargo`, `Hauling!H1:N200`, and the carrier line or its "not published" note. The region's grid equals `MarketData`'s.

## What the mocks do not cover

- The plan as a person reads it: whether the line per run says enough to trust before running (HV.2, 1.1).
- The Sheets API's own behaviour for a region write after a tab write in the same process (HV.5, 3.3).
- The retirement sentence read from a real file, and the one-edit move actually being one edit (HV.4). The maintainer's own configuration is the one known user.
- Quoting on cmd.exe versus PowerShell for a command token with spaces (1.3): the POSIX split is the tool's; the shell's quoting is the shell's.

## Cleanup

- Delete the workbook copy in Google Drive, or keep it as a test bed.
- `set ED_CONFIG_DIR=` (cmd.exe) / `Remove-Item Env:ED_CONFIG_DIR` (PowerShell); remove `%TEMP%\edseq` when done. The two credential files in it are copies.
- Your real `~/edapitool/config.json` was never read. If it still names the `regions` plugin, make the one edit of HV.4 there too, after copying the file to `config.json.<date>` first.
