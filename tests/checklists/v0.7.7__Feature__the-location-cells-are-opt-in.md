# Human Test Checklist: the location cells are opt-in

**Target version:** 0.7.7
**Ships with commit:** TBD (pre-commit)
**Companion automated tests:** 7 new or rewritten tests: `tests/test_location_opt_in.py` (6, one of them parametrized for `serve`) and `tests/test_service.py::test_a_refresh_that_does_not_ask_for_location_writes_none` (1, pinned from a mutation survivor), plus the rewritten `tests/test_marker_formula.py::test_the_help_text_no_longer_promises_that_no_markers_writes_nothing`. Eleven existing tests now pass `write_location=True` because the location cells are their subject. Full suite: 843.

## What this is

From 0.7.7, `market --update-sheet` writes the system and station cells (`Totals Tab!C2` and `G2` on the settlement workbook) only when `--write-location` is given, which is how `serve` already behaved. This checklist is for whoever maintains a settlement workbook, to confirm against the real Google API that a normal run leaves those two cells alone, and that the flag still writes them when asked. About 10 minutes; section 3 needs your sheet.

## Prerequisites

1. 0.7.7 installed editable (`pip install -e .` from the repo root); `edapitool --version` prints `0.7.7`.
2. A settlement target configured in `~/edapitool/config.json` (`edapitool plugins` lists `settlement` as loaded).
3. A recent `Market.json`: dock somewhere with a commodity market and open its Commodity Market screen once. After that the game can be closed.
4. For section 3: `Totals Tab!C2` holds `=MarketData!$E$1` and `G2` holds `=MarketData!$C$1`. **Write down what they hold now** so the Cleanup section can restore them.

Every command below is a plain `edapitool` call and runs the same in cmd.exe, PowerShell and bash, except the output filters in section 1, which are given for each shell.

## High-Value Verification (~5 minutes)

### HV.1: a normal dry run names no location cells

- [ ] **Steps:** `edapitool market --update-sheet --dry-run`
- [ ] **Expected:** the `DRY RUN - would write:` block names marker ranges (or reports cells left alone) and **does not name `C2` or `G2`**.
- [ ] **Why this matters:** until 0.7.7 every `--update-sheet` put fixed values over the location formulas. This is the whole fix.

### HV.2: the flag still asks for them

- [ ] **Steps:** `edapitool market --update-sheet --dry-run --write-location`
- [ ] **Expected:** the same block, now also naming `Totals Tab!C2` and `Totals Tab!G2` with your current system and station.
- [ ] **Why this matters:** a sheet that still wants the tool to fill these cells must have a way to ask.

### HV.3: the real write leaves the formulas in place

- [ ] **Steps:** `edapitool market --update-sheet` (no `--write-location`), then click `C2` and `G2` in the sheet and read the formula bar.
- [ ] **Expected:** still `=MarketData!$E$1` and `=MarketData!$C$1`. Column L shows markers or blanks, and no `?`.
- [ ] **Why this matters:** a dry run is the tool's account of what it will do. This checks what the Google API actually received.

## Section 1: help text (~2 min, no sheet needed)

### 1.1 `--write-location` is listed and explains itself

- [ ] **Steps** (pick your shell):

  **cmd.exe**:
  ```cmd
  edapitool market --help | findstr /C:"write-location" /C:"update-sheet" /C:"writing to it"
  ```
  **PowerShell**:
  ```powershell
  edapitool market --help | Select-String "write-location","update-sheet","writing to it"
  ```
  **POSIX**:
  ```bash
  edapitool market --help | grep -E "write-location|update-sheet|writing to it"
  ```
- [ ] **Expected:** `--write-location` appears under **writing to it**. Its help (run `edapitool market --help` in full to read it) says the option is off by default because those cells are better as formulas reading MarketData. `--update-sheet`'s help reads "Write column markers to the spreadsheet" and no longer mentions location cells.

### 1.2 the formula instructions no longer promise a refresh

- [ ] **Steps:** `edapitool market --show-formula`
- [ ] **Expected:** step 3 says `--no-markers` leaves the marker column alone, and that the location cells are written only with `--write-location`, naming `MarketData!$E$1` and `MarketData!$C$1`. It must **not** say "`--no-markers` still refreshes the location cells".

## Section 2: dry runs against your sheet (~3 min, read-only)

### 2.1 with `--no-markers`, nothing at all is planned for the roll-up tab

- [ ] **Steps:** `edapitool market --update-sheet --dry-run --no-markers`
- [ ] **Expected:** `DRY RUN - would write:` followed only by `marked rows: (none)`, with no `Totals Tab` range. Before 0.7.7 this printed `C2` and `G2`. Judge whether an empty plan reads clearly enough as "nothing to write", and report it if not.

### 2.2 with `--no-markers --write-location`, exactly the two cells

- [ ] **Steps:** `edapitool market --update-sheet --dry-run --no-markers --write-location`
- [ ] **Expected:** exactly `Totals Tab!C2` and `Totals Tab!G2`, and no marker range.

---

## Section 3: the real write (~3 min, needs your sheet)

> The hazard noted on the project board and in the 0.7.6 checklist, not to run `market --update-sheet` against a sheet with location formulas, **is lifted from 0.7.7**, provided `--write-location` is left off.

### 3.1 a real write, formulas kept

This is HV.3. Also confirm:
- [ ] the command's report says `Wrote N ranges`, where N counts only marker ranges;
- [ ] after the next time `MarketData` changes (dock elsewhere, or run `serve`), `C2` and `G2` show the new system and station. That is the formulas following the data, which is the point.

### 3.2 (optional) `--write-location` for real

Only if you're willing to restore the formulas afterwards (see Cleanup).
- [ ] **Steps:** `edapitool market --update-sheet --write-location`
- [ ] **Expected:** `C2` and `G2` now hold **literal** text (the formula bar shows text, not `=`). Restore them straight away.

---

## Section 4: `serve` is unchanged (~3 min, optional)

### 4.1 plain `serve` leaves the cells alone

- [ ] **Steps:** `edapitool serve --once`
- [ ] **Expected:** `MarketData` is published, and `C2`/`G2` are still formulas. The market line does **not** end in `+ location cells`.

### 4.2 `serve --write-location` still writes them

Only on a sheet that wants literals, or be ready to restore them.
- [ ] **Steps:** `edapitool serve --once --write-location`
- [ ] **Expected:** the market line ends in `+ location cells`, and `C2`/`G2` hold literals.

## What the automated tests DON'T cover

- **The real Google API receiving a batch without C2/G2.** Every test uses a fake worksheet. HV.3 is the only check against the real call.
- **A workbook whose location formulas live in other cells.** The settlement plugin names `C2`/`G2`; a different layout is its own plugin's business.
- **How an empty plan reads** (2.1). It prints correctly, but whether the wording is clear is a judgement for whoever reads it.
- **The formulas following `MarketData` over time** (3.1's second check). It depends on the sheet recalculating, which no test runs.

## Reporting issues found

1. Note the section and step
2. Copy the exact command and its full output
3. Note what C2 and G2 held before and after
4. File an issue referencing this checklist and #25

## Cleanup

If 3.2 or 4.2 was run, restore the formulas by typing them back into the sheet:
- `Totals Tab!C2`: `=MarketData!$E$1`
- `Totals Tab!G2`: `=MarketData!$C$1`

Nothing else in this checklist changes state.
