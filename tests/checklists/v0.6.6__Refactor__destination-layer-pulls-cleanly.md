# Human Test Checklist: the destination layer pulls cleanly

**Target version:** v0.6.6 (the bump had not happened when this was written — if the shipped version differs, this file's name is the only thing that is wrong)
**Ships with commit:** "Let the tool survive losing the spreadsheet it was built for" (Refs #18)
**Companion automated tests:** 590 total, up from 563 — 24 in `tests/test_destination_seam.py`, 3 in `tests/test_market_data.py`

## What this is

A refactor with **no user-visible change at all**: no new flag, no changed output, no changed behaviour. Everything below exists to check that claim rather than to trust it.

Internally, `APITool/service.py` stopped importing one particular spreadsheet's code (`APITool/workbook/`) when the module loads, and now resolves it at the moment it is used. The point is that removing that package no longer takes `serve`, the daemon and the market comparison down with it.

**This runs entirely without Elite Dangerous.** The game does not need to be open for any step here. `market` reads `Market.json` from wherever you were last docked, and that file stays on disk — so the comparison works from a cold start with the game closed. That is worth saying because the opposite is the natural assumption.

**~10 minutes, and step 4 is the only one that matters.** Steps 1–3 are cheap confirmations; step 4 is the one thing the 590 automated tests genuinely cannot reach.

**Note on releases:** v0.6.4 and v0.6.5 are both committed and deliberately unreleased — no tag, no GitHub release, and users remain on 0.6.3 pending a separate play session. This checklist does not unblock that; it covers only the refactor.

## Prerequisites

1. A working `edapitool` install with the `gsheets` extra, and Google credentials already set up (the same ones the daemon uses).
2. `Market.json` present from a previous session. No game needed — just a prior docking at a station with a commodity market.
3. **Know which spreadsheet you are pointing at.** Step 4 writes to it for real.

**Every command below is the same in cmd.exe, PowerShell and bash** — they are all `edapitool` or `python` invocations with no shell-specific syntax, no environment variables and no redirection. No per-shell variants are needed.

**If `serve` is already running, leave it alone.** Nothing here requires stopping it, and step 4 is a single manual write that a running daemon will simply see as an unchanged sheet.

## High-Value Verification

### HV.1 — The goal check

Validates: the property this whole commit exists to create.

- [ ] **Steps:**
  ```
  python tests/one-offs/thinking/plugin-isolation/poc_pull_the_plug.py
  ```
- [ ] **Expected:** the final line reads `RESULT: the plug pulls cleanly. Requirement 3 of #18 is MET.`
  Every row in the table says `as designed`. No row says `*** COLLATERAL ***`.
- [ ] **Why this matters:** before this commit it printed `UNMET`, with `refresh service` and `daemon` listed as collateral. If it says `UNMET`, the fix did not land.

### HV.2 — The market path still works with no spreadsheet at all

Validates: the service layer, which is the module that was changed.

- [ ] **Steps:**
  ```
  edapitool market --no-sheet
  ```
- [ ] **Expected:** your last station and system, and the market contents. No traceback. No mention of a spreadsheet.
- [ ] **Why this matters:** this is the path that had a hard dependency on one workbook's code. It should now run without that code ever being imported.

### HV.3 — The comparison reads requirements, without writing anything

Validates: `TotalsTabReader`, whose construction moved.

- [ ] **Steps:**
  ```
  edapitool market --update-sheet --dry-run
  ```
- [ ] **Expected:** the comparison table, and a description of exactly what *would* be written. **Nothing is written.**
- [ ] **Check:** the outstanding quantities shown match what the Totals Tab's "Left to buy" column actually says right now. Open the sheet and spot-check two or three rows.
- [ ] **Why this matters:** every automated test of this path uses a mock worksheet. This is the first time the reader is built the new way against a real one.

### HV.4 — The real write ← **the step that matters**

Validates: `TotalsTabWriter`, the other class whose construction moved. **This writes to your spreadsheet.**

- [ ] **Steps:**
  ```
  edapitool market --update-sheet
  ```
- [ ] **Expected:** the same comparison as HV.3, and a confirmation that the sheet was updated.
- [ ] **Check, in the spreadsheet itself:**
  - `C2` and `G2` show the right system and station
  - the marker column renders its usual glyphs — `●  ◕  ◑  ◔  ○` — and is not blank, not all one symbol, and not shifted by a row or a column
  - nothing you typed by hand has been overwritten
- [ ] **Why this matters:** this is the only live consumer of both classes, and mocks cannot tell you the sheet *looks* right. If the markers land one row off, every automated test still passes.

### HV.5 — The formula generator survived

Validates: that the refactor did not damage a supported feature that lives inside the isolated package.

- [ ] **Steps:**
  ```
  edapitool market --show-formula
  ```
- [ ] **Expected:** the full marker formula, with thresholds `0.375` and `0.625` and the glyphs `◔ ◑ ◕`.
- [ ] **Why this matters:** it would have been easy to treat everything in that package as legacy. This feature is the opposite — it is how the sheet stopped needing the tool to paint cells at all.

## What the automated tests DO cover

| Area | Test file | Count |
|---|---|---|
| Removing the destination layer breaks only destination features | `tests/test_destination_seam.py` | 24 |
| Composition modules reach the destination only at function scope | `tests/test_market_data.py` | 3 |
| Everything else, unchanged by this work | the rest of `tests/` | 563 |

The seam tests run the check in a **child interpreter** with an import blocker installed, so the test process itself never loads or unloads anything. An earlier in-process version passed on its own and broke eleven unrelated tests in the full suite; the child process is why that cannot happen again.

## What the automated tests DON'T cover

- **Whether the spreadsheet looks right.** Column alignment, row offsets, glyph rendering — a marker written one row off passes every assertion.
- **A real Google Sheets worksheet.** Every automated test of the reader and writer uses a mock. Quota behaviour, API errors and partial writes are all invisible to them.
- **Console rendering of the marker glyphs** on a Windows codepage. The glyphs are non-ASCII and the terminal may substitute or mangle them.
- **Whether the comparison is *correct*** — only that it runs. Checking the numbers against the sheet is HV.3's job and needs a person.

## If something fails

1. Note the step number and capture the exact command and full output.
2. For HV.1, paste the whole table — which rows say `COLLATERAL` is the diagnosis.
3. For HV.4, screenshot the affected range of the sheet before changing anything.
4. File against [#18](https://github.com/djdarcy/EDAPITool/issues/18), referencing this checklist by filename.

## Cleanup

Nothing to clean up. No temporary files, no config changes, no backups taken. HV.4 writes to the spreadsheet, and that write is the tool's ordinary behaviour — the same thing `serve` does on its own schedule.
