# Human Test Checklist: Current-Station Market Comparison

**Target version:** v0.3.0
**Ships with commit:** "Add current-station market comparison with guarded spreadsheet writes"
**Companion automated tests:** 278 tests — `tests/test_sheets.py` (103), `tests/test_journal.py` (46), `tests/test_matcher.py` (46), `tests/test_catalog.py` (45), `tests/test_service.py` (24), `tests/test_gsheet_guard.py` (14). All 35 injected mutants killed (`python tests/one-offs/mutate.py`).

## What this is

`edapitool market` reads your current station's commodity market from the Elite Dangerous journal, reads the outstanding quantities from your tracking spreadsheet, and marks which commodities are worth buying right here.

Every automated test runs offline against saved fixtures. That is deliberate — but it means **nothing in the suite proves the tool behaves correctly against a live game or a real Google Sheet**. This checklist covers that gap. It also covers the things a person has to look at and judge: whether the marker column is actually readable, whether the colours mean what they should, and whether error messages tell you what to do next.

**Steps marked `MANUAL` require a running copy of Elite Dangerous and/or a real Google Sheet, and cannot be automated.** Steps marked `SAFE` are read-only or write only to scratch locations.

## Prerequisites

1. **Python 3.10+** with the package installed: `pip install -e .[gsheets]`
2. **Elite Dangerous** installed, with a journal directory at
   `%USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous`
   (override with `ED_JOURNAL_DIR` — see isolation below)
3. **A Google Sheet** built from the tracker template, with credentials at
   `~/.ed_gsheet_credentials.json`
4. **Frontier authentication** for the `--use-capi` and `carrier` steps:
   `edapitool auth --client-id YOUR_CLIENT_ID`

### State isolation

Most of this checklist can run against a **copied journal directory** instead of your live one, which removes any dependence on where your commander happens to be:

**cmd.exe**
```cmd
mkdir %TEMP%\edtest-journal
copy "%USERPROFILE%\Saved Games\Frontier Developments\Elite Dangerous\Market.json" %TEMP%\edtest-journal\
set ED_JOURNAL_DIR=%TEMP%\edtest-journal
```

**PowerShell**
```powershell
New-Item -ItemType Directory -Force "$env:TEMP\edtest-journal"
Copy-Item "$env:USERPROFILE\Saved Games\Frontier Developments\Elite Dangerous\Market.json" "$env:TEMP\edtest-journal\"
$env:ED_JOURNAL_DIR = "$env:TEMP\edtest-journal"
```

**POSIX**
```bash
mkdir -p /tmp/edtest-journal
cp ~/"Saved Games/Frontier Developments/Elite Dangerous/Market.json" /tmp/edtest-journal/
export ED_JOURNAL_DIR=/tmp/edtest-journal
```

**For sheet-writing steps there is no isolation** — the tool writes to the spreadsheet id you give it. Before the first `--update-sheet` run:

- [ ] **Make a copy of your spreadsheet** (File → Make a copy) and use the copy's id for this checklist. Recover its id from the URL: `docs.google.com/spreadsheets/d/<THIS_PART>/edit`.
- [ ] Note what is currently in the marker column (default `L`) so you can tell what the tool changed.

### Reset between sections

**cmd.exe**: `set ED_JOURNAL_DIR=` &nbsp;&nbsp; **PowerShell**: `Remove-Item Env:\ED_JOURNAL_DIR` &nbsp;&nbsp; **POSIX**: `unset ED_JOURNAL_DIR`

## High-Value Verification (~5 minutes)

If you only have five minutes, run these six.

### HV.1 — The suite is green `SAFE`

Validates: nothing is broken before you start looking at behaviour.

- [ ] **Steps:**
  ```
  python -m pytest tests/ -q
  ```
- [ ] **Expected:** `278 passed`. No failures, no errors.
- [ ] **Why this matters:** Every later step assumes this baseline. A red suite here means stop.

### HV.2 — It reports where you are `MANUAL`

Validates: journal parsing, the two filename formats, and location state.

- [ ] **Steps:** With Elite Dangerous running and your commander docked somewhere:
  ```
  edapitool market --no-sheet
  ```
- [ ] **Expected:** Your actual commander name, current star system, and docked station. Not a system you visited years ago.
- [ ] **Why this matters:** Journal files use two different filename formats and comparing them as text picks the wrong one. If this shows a stale system, the ordering fix has regressed and every marker downstream will describe the wrong place.

### HV.3 — Stale market data is refused, not guessed `MANUAL`

Validates: the freshness gate — the single most dangerous failure mode in the tool.

- [ ] **Steps:**
  1. Dock at a station and open its **Commodity Market** screen (this makes the game write `Market.json`).
  2. Undock, fly to a **different** station, and dock — but do **not** open its commodity market.
  3. `edapitool market --no-sheet`
- [ ] **Expected:** The station name updates to the new station, and **no comparison is produced**. The message reads: *"Market.json still describes a different station. Open the Commodity Market screen here so the game refreshes it."*
- [ ] **Why this matters:** Without this, the tool would compare your shopping list against the *previous* station's prices and produce markers that look completely plausible and are entirely wrong.

### HV.4 — Dry run shows exactly what would change `MANUAL`

Validates: the write plan, and that nothing happens without being asked.

- [ ] **Steps:**
  ```
  edapitool market --sheet-id YOUR_COPY_ID --update-sheet --dry-run
  ```
- [ ] **Expected:** A list of exactly the ranges that would be written — `C2`, `G2`, and one marker range like `L5:L32`. Open the sheet: **nothing has changed.**
- [ ] **Why this matters:** `--dry-run` is the safety net people will reach for before trusting the tool with their sheet. If it writes anything, that trust is misplaced.

### HV.5 — A real write leaves everything else alone `MANUAL`

Validates: the write allowlist, against a real spreadsheet.

- [ ] **Steps:**
  1. Note the exact contents of a formula cell (e.g. `G5`) and a hand-entered cell (e.g. `M5`).
  2. `edapitool market --sheet-id YOUR_COPY_ID --update-sheet`
  3. Re-check `G5` and `M5`, and click into `B5`.
- [ ] **Expected:** `C2` shows your system, `G2` your station, the marker column is populated. **`B5` is still a formula** (the formula bar shows `=IF($AA5=...`), `G5` is still a formula, `M5` is unchanged.
- [ ] **Why this matters:** Overwriting `B5` would destroy the commodity list and detach the sheet from its settlement tabs. This is the irreversible failure.

### HV.6 — Markers are readable and mean what they say `MANUAL`

Validates: the thing automated tests structurally cannot check.

- [ ] **Steps:** Look at the marker column after HV.5. Cross-reference two or three rows against the station's Commodity Market screen in-game.
- [ ] **Expected:**
  - A **dark green ●** appears only where you can genuinely buy the full outstanding quantity.
  - A **near-white ○** means the station trades it but has none in stock — verify against the in-game supply figure.
  - A **grey ●/○** means it is available here but `Left to buy` is 0 — verify that column reads 0.
  - A **blank** cell means the station does not trade it at all.
- [ ] **Why this matters:** A blank cell used to mean two different things, and that ambiguity sent a user hunting for a bug that did not exist. The greyed markers are what removed it.

## Section 1: Location and market reading (~10 min)

### 1.1 Not docked `MANUAL`

- [ ] **Steps:** Undock and fly around in normal space, then `edapitool market --no-sheet`
- [ ] **Expected:** Station reads `Not docked`. Message: *"Dock at a station to compare its market."* System still updates.
- [ ] **Check:** With `--update-sheet`, the station cell reads `Not docked` **and every marker is cleared**. Old markers must not survive undocking.

### 1.2 Station with no commodity market `MANUAL`

- [ ] **Steps:** Dock at an outpost or settlement with no commodities service. `edapitool market --no-sheet`
- [ ] **Expected:** *"This station has no commodity market."* No comparison, no crash.

### 1.3 Game not running `SAFE`

- [ ] **Steps:** With Elite Dangerous closed, `edapitool market --no-sheet`
- [ ] **Expected:** Reports the last known location from the journal. Market data is described with its age. No crash, no hang.

### 1.4 Journal directory missing `SAFE`

- [ ] **Steps** (pick your shell):

  **cmd.exe**: `set ED_JOURNAL_DIR=%TEMP%\does-not-exist` then `edapitool market --no-sheet`

  **PowerShell**: `$env:ED_JOURNAL_DIR = "$env:TEMP\does-not-exist"` then `edapitool market --no-sheet`

  **POSIX**: `ED_JOURNAL_DIR=/tmp/does-not-exist edapitool market --no-sheet`

- [ ] **Expected:** *"No Elite Dangerous journal directory found. Set ED_JOURNAL_DIR if your Saved Games folder is in a non-standard location."*
- [ ] **Check:** The message names the env var. A user who has moved their Saved Games folder should be able to fix this without reading source.

### 1.5 Market data age is reported `MANUAL`

- [ ] **Steps:** Dock, open the commodity market, run `edapitool market --no-sheet`. Wait 10 minutes and run it again.
- [ ] **Expected:** The `Market:` line shows the age in minutes and it increases. Data source is named (`journal`, `capi`, or `merged`).

### 1.6 Frontier API supplement `MANUAL`

- [ ] **Steps:** `edapitool market --no-sheet --use-capi`
- [ ] **Expected:** Source reads `merged` and the commodity count is higher than the journal alone. Notably, `Limpet` should appear (the journal's `Market.json` omits it entirely).
- [ ] **Check:** With no network, the command still succeeds using journal data alone — CAPI failure must never block an answer.

## Section 2: The marker column (~10 min)

### 2.1 Only outstanding commodities are marked `MANUAL`

- [ ] **Steps:** Find a row where `Left to buy` is 0 but the station clearly stocks the commodity.
- [ ] **Expected:** Greyed glyph, no coloured background. Confirms "available, not needed" rather than a missing mark.

### 2.2 The fill scale tracks coverage `MANUAL`

- [ ] **Steps:** Find a row where the station's supply is *less* than `Left to buy` (a partial). Compare the glyph to the ratio.
- [ ] **Expected:** `◔` under ~37%, `◑` around half, `◕` above ~62%, `●` at 100% or more. Darker green as the circle fills.
- [ ] **Note:** Partials are uncommon at large stations — supply is usually either enormous or zero. If you cannot find one naturally, this path is covered by automated tests.

### 2.3 Markers are fully rewritten, not patched `MANUAL`

- [ ] **Steps:**
  1. Run with `--update-sheet` at a station stocking something you need.
  2. Move to a station that does **not** stock it. Open its commodity market. Run again.
- [ ] **Expected:** The old marker is **gone**, not left behind.
- [ ] **Why this matters:** The commodity list is generated by an array formula, so rows shift when a settlement tab changes. A marker left in place would eventually label the wrong commodity.

### 2.4 Your header cell is left alone `MANUAL`

- [ ] **Steps:** Type your own text into the cell above the markers (e.g. `L3`). Run with `--update-sheet`.
- [ ] **Expected:** Your text survives. Then run with `--write-marker-header` and confirm it is replaced with `At Current Station`.

### 2.5 Glyph and colour variants `MANUAL`

- [ ] **Steps:** Try `--empty-marker small`, `--empty-marker dotted`, `--no-colour`, and `--no-show-covered`.
- [ ] **Expected:** Each changes only what it claims to. `--no-colour` leaves glyphs with no background fill. `--no-show-covered` blanks the greyed rows.

### 2.6 Cell notes `MANUAL`

- [ ] **Steps:** Hover a marker in the browser.
- [ ] **Expected:** Commodity name, need, stock, quantity to buy, unit price, estimated cost, and when the market was read.

## Section 3: Write safety (~5 min)

### 3.1 A misconfigured marker column is refused `SAFE`

- [ ] **Steps:** `edapitool market --sheet-id YOUR_COPY_ID --marker-column B --update-sheet --dry-run`
- [ ] **Expected:** Refused with a message naming the permitted ranges. **Nothing is written**, even in a non-dry run.
- [ ] **Why this matters:** Column B holds the commodity formulas. This is the guard's whole purpose.

### 3.2 The cargo export refuses the wrong tab `SAFE`

- [ ] **Steps:** `edapitool carrier --export google --sheet-id YOUR_COPY_ID` — then in a Python shell:
  ```python
  from APITool.gsheet import GoogleSheetsExporter
  from APITool.models import FleetCarrier
  GoogleSheetsExporter().export_cargo(
      FleetCarrier.from_capi({"name": {"callsign": "TEST"}}),
      sheet_id="anything", tab_name="Totals Tab")
  ```
- [ ] **Expected:** `ValueError: Refusing to rewrite tab 'Totals Tab'...` naming `CargoData` as the only permitted target. This raises **before any network call**, so it works without credentials.

### 3.3 A missing tab gives a useful error `MANUAL`

- [ ] **Steps:** `edapitool market --sheet-id YOUR_COPY_ID --totals-tab "No Such Tab"`
- [ ] **Expected:** The error lists the tabs that **do** exist.

### 3.4 A missing or duplicated header fails loudly `MANUAL`

- [ ] **Steps:** Rename your `Left to buy` header in the sheet copy, then run. Restore it, then add a *second* cell with the same header text and run again.
- [ ] **Expected:** First case names the header and lists the headers present. Second case reports the ambiguity and names the columns. Neither guesses.
- [ ] **Reset:** Restore the original header text and delete the duplicate.

### 3.5 Moving a column requires no code change `MANUAL`

- [ ] **Steps:** Insert a column before `Left to buy` so it shifts right. Run `edapitool market --no-sheet` — no wait, use `--dry-run` against the copy.
- [ ] **Expected:** Still found, still correct. The written marker range shifts accordingly.
- [ ] **Reset:** Undo the column insert (Ctrl+Z in the browser).

## Section 4: Authentication (~5 min, mostly waiting)

These verify the three token fixes in this release. They are slow because they depend on real expiry.

### 4.1 Google token refresh `MANUAL`

- [ ] **Steps:** Use the tool, then wait **over an hour**, then use it again.
- [ ] **Expected:** No browser prompt on the second run. Before this release, an expired Google token forced a full sign-in every hour.

### 4.2 Frontier token refresh `MANUAL`

- [ ] **Steps:** Authenticate, wait **over four hours**, then run `edapitool market --use-capi` or `edapitool carrier`.
- [ ] **Expected:** No browser prompt. Before this release, expiry was treated as "not authenticated at all".

### 4.3 Revoked credentials fail clearly `MANUAL`

- [ ] **Steps:** Revoke the app at <https://user.frontierstore.net/> then run `edapitool carrier`.
- [ ] **Expected:** A clear prompt to re-authorize, not a silent no-op or an unhandled traceback.

## Section 5: Commodity naming (~5 min)

### 5.1 The bundled catalog is current `SAFE`

- [ ] **Steps:** `python scripts/update-commodity-catalog.py --check`
- [ ] **Expected:** *"Bundled catalog is up to date."* If it reports STALE, upstream EDCD has changed — regenerate without `--check` and re-run the suite.

### 5.2 It works with no network `SAFE`

- [ ] **Steps:** Disconnect from the network. `edapitool market --no-sheet`
- [ ] **Expected:** Still resolves commodity names. The catalog must never fetch at runtime.

### 5.3 An unrecognized name is reported, not hidden `MANUAL`

- [ ] **Steps:** In a settlement tab, add a commodity with a deliberately misspelled name so it flows into the roll-up. Run `edapitool market --sheet-id YOUR_COPY_ID`.
- [ ] **Expected:** A warning listing the unrecognized name and pointing at `name_aliases.json`. It must **not** be silently marked unavailable.
- [ ] **Then:** Add the name to `APITool/data/name_aliases.json` mapping to the right commodity, re-run, and confirm it now resolves.
- [ ] **Reset:** Remove the test commodity from the settlement tab.

## Section 6: The signed requirement column (~5 min)

Only relevant if you merge `Left to buy` and `Extra next rnd` into one signed column.

### 6.1 Negative means "still to buy" `MANUAL`

- [ ] **Steps:** In your sheet copy, replace the `Left to buy` formula with a signed one (`=$D5+$M5-$F5`) and rename the header to `What's left`. Then:
  ```
  edapitool market --sheet-id YOUR_COPY_ID --need-header "What's left" --need-sign negative --update-sheet --dry-run
  ```
- [ ] **Expected:** Rows with a **negative** value are treated as outstanding; positive values are surplus and never marked.
- [ ] **Check:** A row showing `-229` should produce the same marker as `229` did under the positive convention.

## What the automated tests DON'T cover

Everything in the suite runs offline against saved fixtures. That leaves:

- **A live Google Sheet.** Every write test uses a test double. Real API behaviour — quota, latency, formatting persistence, how a batch interacts with existing conditional formatting — is only verified by running it.
- **A running game.** Journal tests use synthetic files. Real event ordering, partial writes while the game appends, and journal rollover mid-session are untested by machine.
- **Whether the colours are legible.** No assertion can tell you the greens are distinguishable on your monitor, or that grey reads as "not actionable".
- **Whether the markers mean the right thing to a person.** The distinction between "not sold here" and "here but not needed" was found by a human looking at a sheet, not by a test.
- **Token expiry.** Refresh paths are exercised only by waiting for real tokens to expire.
- **Terminal rendering.** The marker glyphs are non-ASCII; Windows consoles default to cp1252 and mangle them. (The tool writes them to Sheets correctly regardless — this affects only console output.)
- **Cross-platform paths.** The journal directory default is Windows-shaped; macOS/Linux users need `ED_JOURNAL_DIR`.
- **Performance feel.** Whether a refresh is fast enough to run on every docking.

## Reporting issues found

1. Note the section and step number (e.g. HV.5, or 3.4).
2. Capture the exact command and its full output.
3. For sheet problems, capture the cell address, its displayed value, and its formula.
4. For location problems, include `edapitool market --no-sheet --json` output.
5. File an issue referencing this checklist and the version.
