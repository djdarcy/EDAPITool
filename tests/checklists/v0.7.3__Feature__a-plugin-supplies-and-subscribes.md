# Human Test Checklist: a plugin supplies and subscribes

**Target version:** v0.7.3
**Ships with commit:** `v0.7.3 feat(plugins): a plugin supplies and subscribes (#26, #18, #17)`
**Companion automated tests:** 691 passing — `tests/test_supplier_registry.py` (18, new), `tests/test_plugin_loader.py` (63), `tests/test_sheets.py` (123, the reader and writer now exercised through the plugin's thin subclasses), `tests/test_service.py` (33, every one now flowing through the registry), `tests/test_destination_seam.py` (28), the rest of the suite (426). Every new test was red-green audited; each unit was mutation-swept (`tests/mutation/v0.7.3__sweep__slice-b-*.md`).

## What this is

This version changes how the tool and a plugin talk to each other, without changing what either does. A plugin now *declares* two things: what it **supplies** (data the tool pulls once per refresh and hands to every consumer) and what it **subscribes** to (a publish the tool pushes once its needs are met). The requirements reader and marker writer moved from the settlement plugin into the shared toolkit, because a second plugin would have rewritten them. The tool's command layer no longer imports anything from the plugin — not its glyphs, not its help text — it asks the loaded plugin for them.

**Every command must behave exactly as in v0.7.2.** The one addition a person can see: `market --json` rows carry an `origin` (where the requirement was read from) beside the `row` they always had. This checklist is mostly a "nothing changed" checklist run against a rewired interior, which is exactly when a checklist earns its keep.

**~10 minutes. The game does not need to be running.** HV.2, 1.2 and Section 2 need the spreadsheet and the `gsheets` extra; the rest run with neither.

**Release state:** 0.6.4 through 0.7.3 are all committed and deliberately unreleased.

## ⚠ Read before running anything

**Do not run `edapitool market --update-sheet` against a workbook whose marker column holds formulas.** It clears that column unconditionally (#25, pre-existing). HV.2 uses `--dry-run`, which writes nothing.

**Steps that plant a plugin edit your configuration file** — there is still no environment override for its location. Back it up first exactly as `tests/checklists/v0.7.2__Feature__a-second-plugin-is-loadable.md` Prerequisites step 3 shows, and restore it in Cleanup. This checklist reuses that file's temp-plugin recipe by reference rather than repeating it.

## High-Value Verification (~5 minutes)

### HV.1 — `--show-formula` is byte-identical ← the courier removed

Validates: the help text now comes from the loaded plugin rather than a hardcoded import, and says exactly what it said before.

- [ ] **Steps** (pick your shell):

  **cmd.exe**
  ```cmd
  set PYTHONIOENCODING=utf-8
  edapitool market --show-formula > %TEMP%\formula_now.txt
  fc %TEMP%\formula_now.txt %TEMP%\formula_before.txt
  ```
  **PowerShell**
  ```powershell
  $env:PYTHONIOENCODING = "utf-8"
  edapitool market --show-formula > "$env:TEMP\formula_now.txt"
  Compare-Object (Get-Content "$env:TEMP\formula_now.txt") (Get-Content "$env:TEMP\formula_before.txt")
  ```
  **POSIX**
  ```bash
  PYTHONIOENCODING=utf-8 edapitool market --show-formula > /tmp/formula_now.txt
  diff /tmp/formula_now.txt /tmp/formula_before.txt
  ```
  If you have no `formula_before.txt`: check out `0a745ea` in a scratch worktree (`git worktree add <scratch> 0a745ea`), run the same command from there into `formula_before.txt`, then `git worktree remove <scratch>`.
- [ ] **Expected:** no differences. The text begins `Reproducing the marker column from a MarketData tab`.
- [ ] **Why this matters:** the plugin's formula help used to be imported by name; now the CLI asks whichever plugin loaded. A single changed character would mean the wrong plugin, or the wrong function, answered.

### HV.2 — The live plan is unchanged (needs the spreadsheet)

Validates: the refresh now runs through the supplier registry — requirements read once, the plan built by the plugin's subscriber — and produces the same plan.

- [ ] **Steps:**
  ```
  edapitool market --update-sheet --dry-run
  ```
- [ ] **Expected:** the same `DRY RUN - would write:` block as v0.7.2 — **three** ranges on the roll-up tab, the two location cells and the marker range — and the same marked rows. **Nothing is written.**
- [ ] **Why this matters:** `refresh()` was rewritten onto the registry. Every automated test of it uses a fake sheet; this is the one real read through the new path.

### HV.3 — `market --json` carries `origin`, and still `row`

Validates: R5 — a requirement can say where it came from.

- [ ] **Steps** (needs a journal from a session that was docked at a station with a market; skip if none):
  ```
  edapitool market --no-sheet --json
  ```
  Then look at the first entry under `"matches"`.
- [ ] **Expected:** each match has both `"row": <n>` and `"origin": "<tab>!<column><n>"` — for the shipped plugin, `"Totals Tab!B<n>"`. No other field is missing compared with v0.7.2.
- [ ] **Why this matters:** `origin` is the field that lets a requirement come from somewhere other than a sheet; `row` stays because the JSON is a published schema and the writer places markers by it.

### HV.4 — `--empty-marker` still selects the glyph family

Validates: the choice now travels to the plugin as a word, and the plugin builds the map the CLI used to.

- [ ] **Steps** (needs the spreadsheet; `PYTHONIOENCODING=utf-8` set as in HV.1):
  ```
  edapitool market --update-sheet --dry-run --empty-marker small
  edapitool market --update-sheet --dry-run --empty-marker dotted
  edapitool market --update-sheet --dry-run
  ```
- [ ] **Expected:** the plan's marker values use `◦` (small) and `◌` (dotted) for the empty state, and the default run uses the graded `○ ◔ ◑ ◕ ●` family. Nothing is written.
- [ ] **Why this matters:** four glyph constants used to be imported into the CLI only to build this map; if the word does not reach the plugin, every choice renders as the default.

### HV.5 — A plugin without formula help is told so

Validates: the CLI asks the plugin rather than assuming.

- [ ] **Steps:** plant the `mytab` plugin from the v0.7.2 checklist's HV.3 recipe (it has no `formula_help`), enable it as the only target (**edits the config file** — back it up first), then:
  ```

  ```
- [ ] **Expected:** `The 'mytab' plugin has no formula help.` and exit code 1. No traceback.
- [ ] **Why this matters:** a plugin for a sheet with no marker column has no formula to show; the old import would have shown the settlement plugin's regardless.

## Section 3: known rough edges

### 3.1 Still no environment override for the config file

Unchanged from v0.7.2; HV.5 edits the real file. Worth adding before slice C adds more configuration.

### 3.2 `origin` is tab-qualified, not target-qualified

`"Totals Tab!B5"`, not `"settlement-workbook!Totals Tab!B5"`. The target-name prefix arrives when configuration carries target names into the refresh (slice C). Recorded so nobody reads the shorter form as final.

### 3.3 `--show-formula` on a stock Windows console

Unchanged: needs `PYTHONIOENCODING=utf-8`. Pre-existing.

### 3.4 A bad `subscribes()` is inert under `--no-sheet`

A subscription naming a supplier nobody offers is refused by name — `no supplier named 'x'; known suppliers: ...` — but only when a refresh reaches its subscribers, which needs a worksheet. Under `--no-sheet` the refresh returns before that point, so the misdeclaration is never reported and never runs. Exercising it needs a real sheet (HV.2) or a direct `Refresh.run()`; the automated test `test_a_subscription_needing_an_unknown_supplier_fails_before_publishing` covers the registry side. Found by the first run of this checklist.

### 3.5 `serve` reports a colliding supplier under the wrong heading

A plugin whose `supplies()` offers a name core already supplies (`location`, `market`) is refused when the service is built. `market` now says so in one `Error:` line (found by the first run of this checklist; pinned by `test_a_plugin_supplying_what_core_supplies_is_refused_in_one_line`). `serve` builds the service inside the same guard that catches a bad spreadsheet, so the same refusal arrives prefixed `Error opening spreadsheet:` — the sentence after the prefix is right; the prefix is not.
