# Human Test Checklist: the first run writes your config

**Target version:** 0.7.8
**Ships with commit:** TBD (pre-commit)
**Companion automated tests:** 21 new: `tests/test_stock_config.py` (13) and 8 added to `tests/test_settings.py` (the comment header, the backup on every save, recovery from a corrupt file with and without a backup, one report per lookup, a non-object body, a comment inside the body, saving over a corrupt file). Full suite: 864.

## What this is

From 0.7.8, the first time any `edapitool` command runs with no `config.json`, the tool writes a commented starting file and says so; and a `config.json` that fails to parse is reported on stderr and recovered from `config.json.bak` instead of being read as empty. This checklist walks both in a **scratch configuration directory**, so your real `~/edapitool/` is never touched. About 10 minutes; nothing needs the game, a spreadsheet or the network except the optional last section.

## Prerequisites

1. 0.7.8 installed editable (`pip install -e .` from the repo root); `edapitool --version` prints `0.7.8`.
2. **Every step below sets `ED_CONFIG_DIR` to a scratch directory first.** That variable is the whole answer for where the tool's files are; with it set, nothing under `~/edapitool/` is read or written. Start each section from a fresh scratch directory:

   **cmd.exe**
   ```cmd
   set ED_CONFIG_DIR=%TEMP%\edapitool-scratch
   if exist "%ED_CONFIG_DIR%" rmdir /s /q "%ED_CONFIG_DIR%"
   ```
   **PowerShell**
   ```powershell
   $env:ED_CONFIG_DIR = "$env:TEMP\edapitool-scratch"
   if (Test-Path $env:ED_CONFIG_DIR) { Remove-Item -Recurse -Force $env:ED_CONFIG_DIR }
   ```
   **POSIX**
   ```bash
   export ED_CONFIG_DIR=/tmp/edapitool-scratch
   rm -rf "$ED_CONFIG_DIR"
   ```
3. Make sure `ED_NO_STOCK_CONFIG` is **not** set in your shell (it turns the first-run write off): `set ED_NO_STOCK_CONFIG=` / `Remove-Item Env:\ED_NO_STOCK_CONFIG` / `unset ED_NO_STOCK_CONFIG`.

## High-Value Verification (~5 minutes)

### HV.1: the first command writes the file and says so

- [ ] **Steps:** with a fresh scratch directory, `edapitool plugins`
- [ ] **Expected:** the first line is `Wrote a starting configuration to <scratch>\config.json -- edit it, or keep the defaults.`, followed by the usual listing: `Loaded 1:` with `settlement ... serves 'settlement-workbook'`, and `jsonl` under "Available but not loaded".
- [ ] **Why this matters:** a new install has had no starting point since 0.7.5; this is it.

### HV.2: the file explains itself, and the JSON under the header is valid

- [ ] **Steps:** open `config.json` in your editor (`type` / `Get-Content` / `cat` work too).
- [ ] **Expected:** it starts with `# edapitool settings -- written by the tool on its first run.` and a `#` header that explains `client_id`, `sheet_id`, `targets`, `kind`, `plugin`, `config`; names the public template workbook and says writing to it is **EXPECTED TO FAIL**; shows a commented-out `nightly-dump` jsonl target as an example. Below the header: JSON with one target, `settlement-workbook`, whose `config` block is the settlement plugin's own default. Judge the header as a reader: is it clear what you would change first?
- [ ] **Check** the JSON parses once the header is skipped (cross-shell, needs Python):
  ```
  python -c "from APITool import settings; print(settings.load()['targets']['settlement-workbook']['plugin'])"
  ```
  prints `settlement`.
- [ ] **Why this matters:** the file is the documentation a newcomer reads first.

### HV.3: a second run leaves it alone

- [ ] **Steps:** `edapitool plugins` again.
- [ ] **Expected:** no `Wrote a starting configuration` line; the same listing.

### HV.4: `--version` writes nothing

- [ ] **Steps:** delete the scratch directory (prerequisite 2), then `edapitool --version`.
- [ ] **Expected:** the version prints; the scratch directory **does not exist** afterwards (`dir %ED_CONFIG_DIR%` / `Test-Path $env:ED_CONFIG_DIR` / `ls "$ED_CONFIG_DIR"` reports it missing).

### HV.5: the header survives the tool's own write, and a backup appears

- [ ] **Steps:** `edapitool plugins` (a fresh first run), then
  ```
  python -c "from APITool import settings; print(settings.save('client_id', 'x'))"
  ```
- [ ] **Expected:** `True`; `config.json` still starts with the `#` header and now holds `"client_id": "x"` in its JSON; `config.json.bak` exists beside it and holds the file as it was before the save (no `client_id`).
- [ ] **Why this matters:** `edapitool auth` writes this way; without this the first `auth` would erase the commentary.

## Section 1: a broken file is reported and recovered (~3 min)

### 1.1 with a backup

- [ ] **Steps:** after HV.5, append a stray comma to `config.json`:
  **cmd.exe** `echo ,>> "%ED_CONFIG_DIR%\config.json"` · **PowerShell** `Add-Content "$env:ED_CONFIG_DIR\config.json" ","` · **POSIX** `printf ',' >> "$ED_CONFIG_DIR/config.json"`
  Then `edapitool plugins`.
- [ ] **Expected:** on stderr, one line: `Warning: <scratch>\config.json is not valid JSON (Extra data: ...); using config.json.bak instead`. The listing still shows `Loaded 1: settlement`, because the backup holds the target. The warning appears **once**, not once per setting the tool looked up.

### 1.2 without a backup

- [ ] **Steps:** delete `config.json.bak` (`del` / `Remove-Item` / `rm`), then `edapitool plugins`.
- [ ] **Expected:** `Warning: ... is not valid JSON (...); no usable config.json.bak, running with no settings`, and the listing shows both plugins as "Available but not loaded". The broken file is **not** overwritten; it is yours to fix.

### 1.3 a comment inside the JSON is an error

- [ ] **Steps:** restore a good file (delete the scratch directory and run `edapitool plugins`), then add a line `# note` *inside* the braces with your editor; run `edapitool plugins`.
- [ ] **Expected:** the same `not valid JSON` warning. Comments belong above the first `{` only, as `docs/configuration.md` says.

## Section 2: the off switch (~1 min)

- [ ] **Steps:** delete the scratch directory; set `ED_NO_STOCK_CONFIG=1` (`set ED_NO_STOCK_CONFIG=1` / `$env:ED_NO_STOCK_CONFIG = "1"` / `export ED_NO_STOCK_CONFIG=1`); `edapitool plugins`.
- [ ] **Expected:** no write line; both plugins "Available but not loaded"; the scratch directory does not exist afterwards. Unset the variable before continuing.

## Section 3 (optional): the template really is read-only (~3 min, needs Google credentials in the scratch directory)

Copy your `gsheet_credentials.json` and `gsheet_token.json` into the scratch directory first; nothing else.

- [ ] **Steps:** `edapitool market --no-sheet` (works with no sheet at all), then `edapitool market --update-sheet --dry-run` against the stock target.
- [ ] **Expected:** the dry run reads the template's `Totals Tab` and prints a plan; nothing is written.
- [ ] **Steps:** `edapitool market --update-sheet` (the real write, against the **template**, which is not yours).
- [ ] **Expected:** a permission error from Google, reported by the tool. That is the failure the header promises. Do **not** put your own sheet id into the scratch config for this step.

## What the automated tests DON'T cover

- **How the header reads in a real editor**: wrapping, `#` highlighting (most editors will not colour it in a `.json` file), whether the guidance is clear to someone new. HV.2 is a judgement.
- **The real permission error from Google** against the template (section 3). Every test uses a fake worksheet.
- **Outside JSON tools**: `python -m json.tool config.json` rejects the file because of the header. Expected, and stated in `docs/configuration.md`; check that the wording there is enough.
- **The stderr warning on a Windows console**: it is ASCII only and should render everywhere; confirm on cmd.exe.

## Reporting issues found

1. Note the section and step
2. Copy the exact command and its full output, stdout and stderr
3. Keep the scratch `config.json` and `config.json.bak`
4. File an issue referencing this checklist and #30 or #22

## Cleanup

Delete the scratch directory and unset the variables:
**cmd.exe** `rmdir /s /q "%ED_CONFIG_DIR%" & set ED_CONFIG_DIR= & set ED_NO_STOCK_CONFIG=`
**PowerShell** `Remove-Item -Recurse -Force $env:ED_CONFIG_DIR; Remove-Item Env:\ED_CONFIG_DIR; Remove-Item Env:\ED_NO_STOCK_CONFIG -ErrorAction SilentlyContinue`
**POSIX** `rm -rf "$ED_CONFIG_DIR"; unset ED_CONFIG_DIR ED_NO_STOCK_CONFIG`

Your real `~/edapitool/` was never touched.
