# Human Test Checklist: a second plugin is loadable

**Target version:** v0.7.2
**Ships with commit:** `v0.7.2 feat(plugins): a second plugin is loadable (#18, #26, #27)`
**Companion automated tests:** 663 passing — `tests/test_plugin_loader.py` (54), the overlap cases in `tests/test_sheets.py` (15), `tests/test_destination_seam.py` (28, now including the loader as a surface), the rest of the suite (566). Every new test was red-green audited and the three units were mutation-swept (`tests/mutation/v0.7.2__sweep__slice-a-*.md`).

## What this is

Until this version a plugin was chosen by a hardcoded import in `cli.py`. That line *was* the selection mechanism: adding `APITool/plugins/mysheet/` produced a directory nothing read. This version adds a loader that finds plugins without importing them, imports only what configuration enables, lists a broken one with its reason instead of dying with it, builds every write guard in core from the plugin's own declaration, and refuses to start when two plugins declare the same cells.

**Nothing changes for an existing install.** With no `targets` map in the config file, the shipped `settlement` plugin is the implicit default and every command behaves exactly as in v0.7.1. This checklist first proves that, then walks the new surface with plugins planted in a temporary directory.

**~15 minutes. The game does not need to be running.** Steps HV.2 and 2.1 need a spreadsheet and the `gsheets` extra; everything else runs with neither.

**Release state:** 0.6.4 through 0.7.2 are all committed and deliberately unreleased. Tags accompany releases; version numbers are build identifiers.

---

## ⚠ Read before running anything

**Do not run `edapitool market --update-sheet` against a workbook whose marker column holds formulas.** It clears that column unconditionally (#25, pre-existing, not a regression from this version). HV.2 uses `--dry-run`, which writes nothing.

**This checklist edits your configuration file.** There is no environment variable that redirects `~/.ed_capi_config.json`, so the steps that add a `targets` map edit the real file. Back it up first (Prerequisites, step 3) and restore it in Cleanup. Every step below says what it writes; apart from the config edits and a temporary plugin directory, nothing does.

## Prerequisites

1. `edapitool` installed from this working tree. The `gsheets` extra and Google credentials are needed only for HV.2 and 2.1.
2. A scratch directory for planted plugins. The steps use `%TEMP%\edplug` / `$env:TEMP\edplug` / `/tmp/edplug`.
3. **Back up your config file** — every `targets` step edits it:

   **cmd.exe**
   ```cmd
   copy "%USERPROFILE%\.ed_capi_config.json" "%USERPROFILE%\.ed_capi_config.json.bak"
   ```
   **PowerShell**
   ```powershell
   Copy-Item "$HOME\.ed_capi_config.json" "$HOME\.ed_capi_config.json.bak"
   ```
   **POSIX**
   ```bash
   cp ~/.ed_capi_config.json ~/.ed_capi_config.json.bak
   ```
4. Confirm the file has **no** `targets` key yet (it will not, unless you added one):

   ```
   python -c "import json,os;print(sorted(json.load(open(os.path.expanduser('~/.ed_capi_config.json'))).keys()))"
   ```
   Expected: `['client_id', 'construction_regions', 'sheet_id']` or a subset — no `targets`.

**Reset between sections:** restore the backup (Cleanup, step 1) and unset `ED_PLUGIN_DIR`. Each section states its own starting state.

## High-Value Verification (~6 minutes)

**If you only have 6 minutes**, run these six. They cover the one thing that must not have changed and the five things that are new.

### HV.1 — Nothing changed for an existing install ← the safety property

Validates: with no `targets` map, the shipped plugin is the implicit default and the CLI is identical to v0.7.1.

- [ ] **Steps** (cross-shell safe):
  ```
  edapitool --version
  edapitool market --help
  ```
- [ ] **Expected:** the version prints; the help text shows `--totals-tab TOTALS_TAB` with `(default: 'Totals Tab')` and `--need-header` with `(default: 'Left to buy')` — the same defaults as before.
- [ ] **Why this matters:** the loader replaced the hardcoded import that every command used to select the plugin. If defaults are missing or `--version` fails, the fallback for installs without `targets` is broken and every existing user is affected.

### HV.2 — The live plan is unchanged (needs the spreadsheet)

Validates: selection through the loader, and the guard now built by core, produce the same plan as before.

- [ ] **Steps:**
  ```
  edapitool market --update-sheet --dry-run
  ```
- [ ] **Expected:** your last station and system, the comparison, and a `DRY RUN - would write:` block naming **three** ranges on the roll-up tab — the two location cells and the marker range. **Nothing is written.**
- [ ] **Why this matters:** the guard used to be built by the plugin's own layout; core builds it now from `layout.writes()`. Identical output proves the declaration and the old guard's allowlist agree. Skip if no credentials; HV.6 covers the same seam without a sheet.

### HV.3 — A planted plugin is found, loaded, and supplies the defaults

Validates: two-phase discovery of a user plugin; `--help` reads the *configured* plugin.

- [ ] **Steps:** create the plugin directory and file. The file is the same in every shell — save it as `edplug/mytab/__init__.py`:

  ```python
  KIND = "gsheet"

  class _Layout:
      totals_tab = "My Tab"

      def writes(self):
          return {"My Tab": ["A1:B2"]}

  def layout(**overrides):
      return _Layout()

  def writes():
      return _Layout().writes()
  ```

  Then point the tool at it and enable it (**this edits the config file**):

  **cmd.exe**
  ```cmd
  mkdir "%TEMP%\edplug\mytab"
  set ED_PLUGIN_DIR=%TEMP%\edplug
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'mine':{'kind':'gsheet','plugin':'mytab'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --help
  ```
  **PowerShell**
  ```powershell
  New-Item -ItemType Directory -Force "$env:TEMP\edplug\mytab" | Out-Null
  $env:ED_PLUGIN_DIR = "$env:TEMP\edplug"
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'mine':{'kind':'gsheet','plugin':'mytab'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --help
  ```
  **POSIX**
  ```bash
  mkdir -p /tmp/edplug/mytab
  export ED_PLUGIN_DIR=/tmp/edplug
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'mine':{'kind':'gsheet','plugin':'mytab'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --help
  ```
  (Write the `__init__.py` with any editor before running the block.)
- [ ] **Expected:** `--totals-tab` now shows `(default: 'My Tab')`. `--need-header` shows `(default: None)` — the planted plugin has no such field, and a flag the plugin cannot default is simply undefaulted.
- [ ] **Why this matters:** this is the property the version exists to create. The second half — `None` for a field the plugin lacks — is a defect the second-plugin probe found: the parser used to read those fields as bare attributes and crashed `--version` on any plugin of a different shape.

### HV.4 — A broken plugin is listed, not fatal

Validates: per-plugin failure isolation; the tool keeps running.

- [ ] **Steps:** with HV.3's state in place, plant a plugin that fails to import — `edplug/broken/__init__.py` containing exactly:
  ```python
  raise RuntimeError("planted: this plugin does not import")
  ```
  Enable it as the **first** target (**edits the config file**):
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'bad':{'kind':'gsheet','plugin':'broken'},'mine':{'kind':'gsheet','plugin':'mytab'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool --version
  edapitool market --help
  ```
- [ ] **Expected:** `--version` prints. `market --help` still shows `(default: 'My Tab')` — the broken plugin was listed and skipped, and the next enabled one supplies the defaults. No traceback anywhere.
- [ ] **Then** disable the good one so nothing loads, and run a command that needs a destination:
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'bad':{'kind':'gsheet','plugin':'broken'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --no-sheet
  ```
- [ ] **Expected:** exit code 1 and this listing, not a traceback:
  ```
  Error: no destination plugin is loaded.
    BROKEN    broken: RuntimeError: planted: this plugin does not import
    available settlement (shipped) -- not enabled
    available mytab (user) -- not enabled
  ```
- [ ] **Why this matters:** a scanned user directory is only safe if a plugin that fails cannot take the tool down with it. The listing is what tells the person *which* plugin, and *why*.

### HV.5 — Two plugins declaring the same cells are refused, by name

Validates: load-time overlap detection, severity `error` by default.

- [ ] **Steps:** plant two more plugins. `edplug/alpha/__init__.py`:
  ```python
  KIND = "gsheet"
  def layout(**overrides):
      return None
  def writes():
      return {"Data": ["L5:L24"]}
  ```
  and `edplug/beta/__init__.py`, identical except `"L20:L30"`. Enable both (**edits the config file**):
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'a':{'kind':'gsheet','plugin':'alpha'},'b':{'kind':'gsheet','plugin':'beta'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool --version
  edapitool market --no-sheet
  ```
- [ ] **Expected:** `--version` still prints (a conflict means "no defaults", never a crash). `market` exits 1 with:
  ```
  Error: refusing to load plugins whose declared writes overlap; resolve the overlap, or set severity to 'warn' with a precedence:
    alpha / beta: Data!L5:L24 overlaps L20:L30 (alpha takes precedence)
  ```
- [ ] **Why this matters:** `L5:L24` and `L20:L30` overlap while neither contains the other — the case the older `contains()` check cannot see. Two plugins silently writing the same cells is the failure this exists to catch before either writes.

### HV.6 — The probes agree

Validates: the four measurements the migration is judged on, none needing a sheet.

- [ ] **Steps:** restore the config backup first (Cleanup step 1) and unset `ED_PLUGIN_DIR`, then:
  ```
  python tests/one-offs/thinking/plugin-isolation/probe_second_plugin_loads.py
  python tests/one-offs/thinking/plugin-isolation/probe_no_sheet_knowledge.py
  python tests/one-offs/thinking/plugin-isolation/poc_pull_the_plug.py
  python tests/one-offs/thinking/plugin-isolation/poc_region_overlap.py
  ```
- [ ] **Expected**, one line from each: `7/7 checks held. LOADED / BROKEN: listed. Check C5 is met.` · `0 leaks   (0 literal, 0 layout default)` · `RESULT: the plug pulls cleanly. Requirement 3 of #18 is MET.` · `13/13 cases correct`.
- [ ] **Why this matters:** these are the checks the migration's stop condition is measured against, and each one's exit code is its failure count.

## Section 1: configuration shapes (~4 min, all edit the config file)

### 1.1 Naming the shipped plugin explicitly changes nothing

- [ ] **Steps:**
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'settlement-workbook':{'kind':'gsheet','plugin':'settlement'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --help
  ```
- [ ] **Expected:** `(default: 'Totals Tab')` — identical to HV.1.

### 1.2 A malformed target names itself

- [ ] **Steps:**
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'oops':{'kind':'gsheet'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool --version
  edapitool market --no-sheet
  ```
- [ ] **Expected:** `--version` prints. `market` prints `Error: targets['oops'] has no "plugin"` and exits 1. No traceback.
- [ ] **Check:** a `targets` value that is a list rather than an object gives `Error: "targets" must be an object, got list`.

### 1.3 The plugin directory from the config file, and `~` expansion

- [ ] **Steps** (unset the env var first — `set ED_PLUGIN_DIR=` / `Remove-Item Env:\ED_PLUGIN_DIR` / `unset ED_PLUGIN_DIR`), then:
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['plugin_dir']='~/edplug-from-config';d['targets']={'mine':{'kind':'gsheet','plugin':'mytab'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --no-sheet
  ```
- [ ] **Expected:** the listing reports `BROKEN    mytab: not found by the scan` — the directory under your home does not exist, and the tool looked there rather than in `%TEMP%`.
- [ ] **Check:** setting `plugin_dir` to `42` gives `Error: "plugin_dir" must be a non-empty string, got 42` — refused, not coerced.

### 1.5 A plugin that imports but cannot build its layout

Found by the tester sweep of this checklist's first draft and fixed before the version shipped; kept as a step because it is the case the first draft missed.

- [ ] **Steps:** plant `edplug/blowup/__init__.py`:
  ```python
  KIND = "gsheet"
  def layout(**overrides):
      raise RuntimeError("layout blew up")
  ```
  Enable it alone (**edits the config file**):
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d['targets']={'x':{'kind':'gsheet','plugin':'blowup'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool --version
  edapitool market --help
  edapitool market --no-sheet
  ```
- [ ] **Expected:** `--version` prints; `market --help` shows `(default: None)` for the tab flags; `market` prints `Error: plugin 'blowup' could not build its layout: RuntimeError: layout blew up` and exits 1. No traceback anywhere.
- [ ] **Why this matters:** importing cleanly and then failing is a different failure from failing to import, and the first draft of the loader guarded only the second.

### 1.4 A user plugin shadows a shipped one, and says so

- [ ] **Steps:** with `ED_PLUGIN_DIR` pointing at the scratch directory again, copy `edplug/mytab` to `edplug/settlement` (same file, new directory name), then:
  ```
  python -c "import json,os;p=os.path.expanduser('~/.ed_capi_config.json');d=json.load(open(p));d.pop('plugin_dir',None);d['targets']={'s':{'kind':'gsheet','plugin':'settlement'}};json.dump(d,open(p,'w'),indent=2)"
  edapitool market --help
  ```
- [ ] **Expected:** `(default: 'My Tab')` — the user's `settlement` won. Run `edapitool market --no-sheet` (it will fail later for other reasons; look at the first lines): nothing says "no destination", because one loaded.
- [ ] **Why this matters:** the shadowing is deliberate and must never be silent. The automated test asserts the listing carries `shadows the shipped plugin at <path>`; the CLI surfaces that line only in the failure listing today, which is the rough edge in 3.2.

### 2.1 `serve` starts with the guard built by core

- [ ] **First: check whether a daemon is already running.** If one is, leave it alone and skip this section — do not start a second against the same spreadsheet.
- [ ] **Steps:** restore the config backup (Cleanup step 1), unset `ED_PLUGIN_DIR`, then:
  ```
  edapitool serve
  ```
  Let it reach its first poll, then stop it with Ctrl-C.
- [ ] **Expected:** it starts, prints which targets it keeps current, and polls. No traceback, and specifically no `ValueError` about a missing layout or a missing guard.
- [ ] **Why this matters:** `serve` now receives its write guard from the composition root instead of the plugin building one; this is the only surface where that path runs for real.

## Section 3: known rough edges

### 3.1 No environment override for the config file

There is no `ED_CONFIG_FILE`. Every step above that adds a `targets` map edits the real file, which is why this checklist starts with a backup. Worth adding before the next slice adds more configuration; not a regression.

### 3.2 The loader's listing is shown only on failure

`edapitool market` prints the full loaded / broken / available / conflict listing only when nothing loaded. When something did load, shadowing and `warn`-severity conflicts are recorded but not printed. The `edapitool plugins` verb that shows the listing on demand is the next slice's work (V3), gated on a second real plugin existing.

### 3.3 `--show-formula` on a stock Windows console

Unchanged from v0.7.0: fails with `UnicodeEncodeError` under codepage 1252 unless `PYTHONIOENCODING=utf-8` is set. Pre-existing.

- **A real Google worksheet.** Every reader and writer test uses a fake; quota behaviour, API errors and partial writes are invisible to them. HV.2 is the only real read.
- **`serve` starting for real** — Section 2 is the only coverage.
- **The real config file's shape** — tests redirect `CONFIG_FILE`; only Section 1 edits the file a person maintains.
- **Console rendering** of the listing and the conflict message on a stock Windows console.
- **Whether the error messages are helpful**, as opposed to correct.

   ```cmd
   del "%USERPROFILE%\.ed_capi_config.json.bak"
   ```

   ```powershell
   Copy-Item -Force "$HOME\.ed_capi_config.json.bak" "$HOME\.ed_capi_config.json"
   ```

   ```bash
   cp ~/.ed_capi_config.json.bak ~/.ed_capi_config.json
   rm ~/.ed_capi_config.json.bak
   ```
2. **Unset the plugin directory:** `set ED_PLUGIN_DIR=` · `Remove-Item Env:\ED_PLUGIN_DIR` · `unset ED_PLUGIN_DIR`
