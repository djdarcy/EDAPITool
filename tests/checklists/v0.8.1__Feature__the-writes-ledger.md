**Ships with commit:** TBD (pre-commit)

Full suite: 1,052.

## What this is

From 0.8.1 the tool remembers what it last wrote to each glyph-marker cell (and, with `--write-location`, the location cells), so its own glyphs refresh at the next station and anything a person put there is left alone. This checklist verifies that against a real spreadsheet, which the automated tests cannot: they use fake worksheets. About 15 minutes. It needs a Google Sheet **you own** — a copy of the template, never someone else's workbook — and a Frontier-free journal is enough.

## Prerequisites

1. 0.8.1 installed editable (`pip install -e .`); `edapitool --version` prints `0.8.1`.
2. A copy of the template workbook that you own (File > Make a copy), with its glyph-marker column (`L5:L…`) **empty** — delete any formulas there in your copy. Note its sheet id.
3. A scratch configuration directory, so your real `~/edapitool/` and its `store.db` are never touched. Every section below assumes it is set:

   **cmd.exe**
   ```cmd
   set ED_CONFIG_DIR=%TEMP%\edapitool-081
   if exist "%ED_CONFIG_DIR%" rmdir /s /q "%ED_CONFIG_DIR%"
   edapitool plugins
   ```
   **PowerShell**
   ```powershell
   $env:ED_CONFIG_DIR = "$env:TEMP\edapitool-081"
   if (Test-Path $env:ED_CONFIG_DIR) { Remove-Item -Recurse -Force $env:ED_CONFIG_DIR }
   edapitool plugins
   ```
   **POSIX**
   ```bash
   export ED_CONFIG_DIR=/tmp/edapitool-081
   rm -rf "$ED_CONFIG_DIR"
   edapitool plugins
   ```
   The first command writes a stock `config.json` in that directory. Edit it: put **your copy's** sheet id in `"id"` of `totals-workbook`, and copy your Google credentials (`gsheet_credentials.json`, `gsheet_token.json`) into the scratch directory so the tool can reach your copy.
4. To look inside the ledger without the `sqlite3` shell (all shells):
   ```
   python -c "import sqlite3,os; c=sqlite3.connect(os.path.join(os.environ['ED_CONFIG_DIR'],'store.db')); print(c.execute('SELECT target, tab, a1, value FROM writes ORDER BY a1').fetchall())"
   ```

## High-Value Verification (~5 minutes)

### HV.1 — a painted column refreshes the tool's own glyphs and keeps your edit

- [ ] **Steps:**
  1. Dock at a station with a market (or use a journal where you are docked). `edapitool market --update-sheet`
  2. Note the glyphs painted in `L5:L…`. Run the ledger query (prerequisite 4): one row per painted cell, target `totals-workbook`.
  3. In the spreadsheet, type `mine` into one of the painted glyph cells.
  4. Dock at a **different** station. `edapitool market --update-sheet`
- [ ] **Expected:** the second run's report lists your edited cell under `held and left alone`, and the others under `ours and refreshed`. In the sheet, your `mine` is still there, and the other glyphs show the new station's answers.
- [ ] **Why this matters:** before 0.8.1 the second run left *every* painted glyph in place, stale, until `--force` — which would also have destroyed your `mine`.

### HV.2 — a sheet whose column holds formulas is never written

Measured on the maintainer's own workbook at v0.8.1, whose glyph column and location cells all hold formulas:

```
DRY RUN - would write:
  marked rows: [17] -- 1 held, not written: [17]
  held and left alone (22): Totals Tab!C2, G2, L5:L24
  pass --force to overwrite the held cells (there is no undo)

Wrote 0 ranges to 'Totals Tab'.
  marked rows: [17] -- 1 held, not written: [17]
  held and left alone (20): Totals Tab!L5:L24
```

- [ ] **Steps:** on your copy, put a formula (e.g. `=A1`) back into two glyph cells, then `edapitool market --update-sheet --dry-run --write-location` and `edapitool market --update-sheet`.
- [ ] **Expected:** the formula cells are listed under `held and left alone` on both runs, and they are unchanged in the sheet afterwards. Row numbers and counts depend on your sheet.
- [ ] **Why this matters:** this is #25's original incident. Formulas must survive whatever the ledger says.

### HV.3 — the first run after upgrading holds old paint; one `--force` adopts it

- [ ] **Steps:**
  1. Start from a column the tool painted before the ledger existed: set `ED_NO_STORE=1` (cmd `set ED_NO_STORE=1`, PowerShell `$env:ED_NO_STORE = "1"`, POSIX `export ED_NO_STORE=1`), run `edapitool market --update-sheet` once, then unset it (cmd `set ED_NO_STORE=`, PowerShell `Remove-Item Env:\ED_NO_STORE`, POSIX `unset ED_NO_STORE`).
  2. `edapitool market --update-sheet` — the painted cells are held.
  3. `edapitool market --update-sheet --force` — the ledger query now shows rows.
  4. `edapitool market --update-sheet` — the same cells are now `ours and refreshed`.
- [ ] **Why this matters:** every existing user meets step 2 on their first run after upgrading, and the CHANGELOG tells them step 3 is the fix.

### HV.4 — the store switched off behaves as 0.7.6 did

- [ ] **Steps:** with `ED_NO_STORE=1` set, run `edapitool market --update-sheet` twice.
- [ ] **Expected:** the second run holds every painted cell, and the ledger query shows no new rows.

### HV.5 — the report reads the same on both paths

- [ ] **Steps:** compare the report lines of HV.2's dry run and real write.
- [ ] **Expected:** both say `  marked rows:` in lower case, and when a marked row was held, both say `-- N held, not written: [...]`. `Wrote 0 ranges` never appears beside a marked row without that explanation.

## Section 1: the store

- [ ] **1.1** `edapitool store verify` passes with ledger rows present.
- [ ] **1.2** Count the rows with the ledger query, run `edapitool store rebuild`, then count again. The count is unchanged: the ledger is primary data and a rebuild never touches it.
- [ ] **1.3** `edapitool store backup` writes `store.db.bak-<stamp>` into the scratch directory, not into `~/edapitool/`.

## Section 2: the location cells

- [ ] **2.1** With `C2`/`G2` empty on your copy, `edapitool market --update-sheet --write-location` fills them, and the ledger records them.
- [ ] **2.2** Put `=MarketData!$E$1` in `C2`, then run the same command. `C2` is held and reported; `G2` (the tool's own) is refreshed.
- [ ] **2.3** Add `--force` to the same command: `C2` is overwritten. Undo it with the sheet's version history afterwards.

## What the automated tests DON'T cover

- **What Google stores versus what was sent.** `USER_ENTERED` reinterprets text; the ledger records what *reads back*, and only a real sheet shows what that is. Look at the ledger query after HV.1: the values should be the glyphs exactly as the cells show them in the formula bar.
- **A person editing a cell in the real UI between two runs** (HV.1, step 3).
- **Quota under `serve`.** Each real write now makes one more read. Watch a long `serve --write-location` session for quota errors.
- **Whether the report's words make sense to someone meeting them for the first time.**
