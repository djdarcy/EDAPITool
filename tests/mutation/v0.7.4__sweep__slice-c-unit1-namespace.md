## What the sweep found that the audit could not

S3 is the one worth naming. The red-green driver's Q1 reverted `default_target` to return `None` unconditionally and three tests went red, which proved the alias is tested — but every one of those tests used a config carrying *both* a sheet id and a plugin key. The `and`→`or` mutant slips between them: the alias still fires for the fixtures, and stops firing for the plainest real file in existence. A revert of the whole behaviour cannot see a boundary inside the behaviour.

S2 is the second: pinning it surfaced a pre-existing asymmetry the verbatim move carried over — the flag spelling strips a whitespace-only site before testing it and the config block's does not, so `"site": "   "` survives where `"site": ""` becomes `None`. Pinned as it is rather than changed inside a move; recorded as a rough edge in the v0.7.4 checklist.

## Caveats

A kill proves the suite noticed *this* change, not that it tests the right thing — and **a clean sweep is evidence about the mutations tried, not proof of suite completeness.**

The eleven red-green reverts (`redgreen_slicec_unit1_namespace.py`, Q1–Q11) were excluded from generation by name, so this population deliberately does not overlap them; the two together are the unit's evidence, not either alone.
