## Triage — all four survivors killable, all four killed

**M3, M5, M6 are one finding.** `generated.py`'s docstring claims the set is evaluated per call so it cannot depend on import order — and nothing tested that claim, because **in-process it can never fail**. By the time pytest reaches any test, some other test module has imported the whole package, so the registry is always fully populated no matter how it got that way. That is precisely the condition under which an import-order bug hides.

The killing tests run a **fresh interpreter** per question, importing only what the hypothetical caller would:

| Test | What it asks |
|---|---|
| `test_the_set_is_complete_in_an_interpreter_that_imported_nothing_else` | `from APITool.generated import generated_tabs` alone |
| `test_the_allow_list_is_complete_for_a_caller_that_imported_only_the_exporter` | `from APITool.google.exporter import GoogleSheetsExporter` alone |
| `test_the_builder_map_is_complete_in_a_fresh_interpreter_too` | `builders()` alone |

**M8 is a safety override that failed open on its safest setting.** `GoogleSheetsExporter(writable_tabs=[])` means *permit nothing* — the strictest thing a caller can say. Under truthiness it is read as *not specified* and silently falls back to the full derived set, re-opening every generated tab. Killed by `test_permitting_nothing_is_honoured_rather_than_falling_back`.

Nothing was triaged equivalent or don't-care; `equivalents.md` is unchanged by this sweep.
